# Schema

`schema/` is the product source of truth. Protocol framing and catalogs are
validated and generated by `tools/generate.mjs`; runtime C++ and TypeScript read
only the committed generated views, never these JSON/YAML inputs.

| Path | Purpose |
| --- | --- |
| `protocol.yaml` | sparse fields, dense groups, component projection, input/output framing |
| `transport.json` | packet XOR algorithm, encoding, byte count and the 256-byte key |
| `catalogs/*.json` | petals, combat, entities, spawns, strings, drop rules and display overrides |
| `generated/protocol-contracts.json` | machine-readable compiled protocol contracts (output) |
| `generated-outputs.json` | output manifest: path, byte count and SHA-256 for every generated file |

Generated outputs:

| Output | Contents |
| --- | --- |
| `engine/include/engine/net/generated_protocol.hpp` | C++ protocol constants, dense tables and field metadata |
| `client/src/schema/protocol.ts` | TypeScript protocol constants and dense specs |
| `engine/include/engine/net/packet_key.hpp` | 256-byte packet XOR key |
| `client/src/schema/packet-key.ts` | 256-byte packet XOR key |
| `engine/include/engine/catalog/*.hpp` | catalog types, petal/entity/spawn data, combat, spawn defaults, drops |
| `client/src/schema/petals.ts` | petal HUD/gallery view |
| `client/src/schema/mob-gallery.ts` | mob gallery view |
| `client/src/schema/menu-content.ts` | changelog menu content |
| `schema/catalogs/drop-chances.json` | derived product drop table |
| `docs/catalogs.md` | generated catalog reference |

## Commands

```sh
npm run schema:generate   # validate every input, compute every output, then write
npm run schema:check      # read-only: missing/stale/orphan output is a failure
```

`schema:check` never repairs a file. It verifies output contents, the manifest,
the exact output inventory, and that no unregistered file carries the generator
header. `schema:generate` computes all contents before its first write, then
removes only outputs recorded in the previous manifest.

Every generated output has one owner: protocol fields and transport come from
`protocol.yaml`/`transport.json`; catalog attributes have exactly one JSON
owner (for example, rarity/recharge/instances live only in `petals.json`);
`drop-chances.json` is derived, never hand-edited; `CHANGELOG.md` is the only
menu content source.

Historical layouts, probes and old generators are under
[`../archive/`](../archive/README.md); nothing in the active build reads them.
