# W2 · 原版客户端 Garden 联机闭环

**目标**　两份原版客户端通过真实 WebSocket 连接独立服务端，原版菜单和 HUD 完成访客、入局、移动、清波、阵亡、观战和重生。用协议夹具验证字节，再接权威服务端。取证可以从 W0 后开始，实服闭环依赖 W1。

## 02.1 先打通原版启动和入局

按 [源码复用清单](reuse-audit.md) 抽取现有 Asio/Beast 通用连接层和每房单次更新模式。历史字节、握手和可见状态通过 [协议专项](protocol-20221030.md) 独立恢复。

1. 按 [W0 的启动需求](00-baseline-and-evidence.md#002-确认可启动的页面和资源) 补齐必要 DOM、资源和本地发现接口。确认原版加载结束，菜单可操作。记录阻塞启动的资源或初始化错误。
2. 按 [协议顺序](protocol-20221030.md#p1--按最短路径恢复格式) 恢复最小握手、小队、首张对局状态和输入。先用原版回放 fixture 抵达 Garden。每一步保留可消费的服务端字节、原版实际发送的消息、客户端状态和字段定位。
3. 实现服务端可接入的本地发现、访客状态和两人私有房。给原版客户端的字段采用已确认的旧格式和可见值。内部仍用类型化身份、命令、实体、波次和生命状态。首版人数上限仅是项目闭环负载，历史容量在 W4 验证。
4. 在 `wave/server/wire/` 接已证实的实体、波次、观战和本地控制字段。在宿主中把真实输入传给 W1 模拟。对局更新后按每连接的可见状态发布。切换波次、死亡、复活和重新连接时，以原客户端能够恢复的全量或等价序列重建控制对象。

## 02.2 真实浏览器验证

注册 CTest 标签 `w2` 及独立 Node 包的 `dev` 和 `test:wire`。`dev` 从快照路径装配原件，启动本地静态页和 native 服务，输出实际 URL。自动化用同一正式页面与 socket 路径，固定种子和短波参数由测试宿主提供。

| 用例       | 操作                                       | 预期                                                 |
| ---------- | ------------------------------------------ | ---------------------------------------------------- |
| W2-01 启动 | 新浏览器上下文打开页面并进入访客           | 原版文件哈希符合 W0，客户端完成加载并建立访客会话    |
| W2-02 双人 | A 建私有房，B 按原版方式加入，两人准备开局 | 同一房间和波次，身份分离，原版输入被服务端处理       |
| W2-03 进度 | 触发分批生成与清波，查看两端状态           | 两个客户端接收正确波次和实体更新，服务端只推进一次   |
| W2-04 阵亡 | A 阵亡，B 清波，A 等待重生                 | A 进入等待或观战状态，下一波恢复控制，旧生命输入失效 |
| W2-05 重连 | B 断线时 A 进入下一波，随后 B 恢复         | B 恢复正确身份、当前波次、控制对象和可见实体         |
| W2-06 异常 | 重放截断、错误时序和非法长度，恢复正常连接 | 服务端有界处理并选择已验证的错误行为，合法会话恢复   |

实现相应入口后执行。

```sh
set -eu
cmake --build build/wave/native --parallel
ctest --test-dir build/wave/native --output-on-failure --no-tests=error -L '^w2$'
npm --prefix wave run test:wire -- --snapshot "$WAVE_SNAPSHOT" --stage W2
```

人工复查执行 `npm --prefix wave run dev -- --snapshot "$WAVE_SNAPSHOT" --port 8478`，在两个隔离上下文打开打印的 URL，按 W2-01 至 W2-05 操作。报告保存握手、首张对局状态、波次、死亡、重生及重连结果。若原客户端卡在握手或首帧，保留可重现的最短字节和第一处失败。W2 以双原版客户端完成实际对局和重连用例为关闭条件。 [协议专项](protocol-20221030.md) · [执行记录](README.md#执行记录)

## W2 执行结果

W2-01 至 W2-06 已全部通过。两份哈希校验后的原版 JS/Wasm 在隔离 Chromium 上下文中，通过正式页面和真实同源 WebSocket 完成建房、邀请加入、准备、移动、分批出怪、清波、阵亡、跨波重生和断线恢复。

独立 native 服务使用锁定的 Boost 1.86.0 Asio/Beast，只监听 IPv4 回环。`dev` 在装配前验证两个原件的长度和 SHA-256；启动壳只将发现请求和归档 socket 地址转到本地同源路径。每房在宿主时钟上推进一次，随后按连接投影；每连接独立维护变换状态、可靠序号、实体句柄和已确认生命。

| 用例  | 状态 | 实测                                                                                                                                              |
| ----- | ---- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| W2-01 | 通过 | 两个独立访客加载未修改的原 JS/Wasm，完成握手、身份写入和原版菜单显示                                                                              |
| W2-02 | 通过 | A 创建私有房，B 用原版 `#wavelocal-<房间码>` 邀请加入；昵称双向可见，两人 Ready 后同局，原版鼠标命令驱动 W1 移动                                  |
| W2-03 | 通过 | 首批 2 只、第二批 4 只；B 用原版移动靠近怪物，由 Basic 碰撞清波，两端显示 Wave 2；房间 tick 与宿主步数一致                                        |
| W2-04 | 通过 | A 经 W1 接触伤害阵亡，控制对象归零并显示原版死亡界面；下一波生命代次递增、旧实体删除并恢复控制                                                    |
| W2-05 | 通过 | 关闭 B 上下文，A 留在对局跨到 Wave 3；保存的访客状态在新上下文恢复同一玩家、当前 HUD、正确控制对象和怪物集合                                      |
| W2-06 | 通过 | 截断首包、首包前 ACK、重复首包和截断 ACK 返回 1002，4096 字节边界仍按协议拒绝，4097/65536 字节各重复 20 次均返回 1009；随后新合法原版会话成功启动 |

`W2-WIRE-BOOTSTRAP` 验证原版捕获字节、启动序列和解析边界；`W2-GARDEN` 验证双人准入、满房拒绝、每房单次推进、实体删除和重连归属。后者还通过加密 ACK/输入夹具验证旧生命输入拒绝、可靠请求去重、旧 ACK 不回退生命，以及旧 socket 无法撤销新连接。浏览器测试只观测原版绘制和收发字节，不注入 Wasm 状态或代发游戏命令。

[协议字段及证据](../wave/data/wire/20221030/w2-bootstrap.md) · [阶段报告](../reports/wave/W2/wire.json) · [双客户端字节与权威状态](../reports/wave/W2/online.json)

测试宿主单独编译为 `wave_host_fixture`，固定种子为 `20221030`，规则版本为 `w2-wire-fixture.1`。沿用 W1 的短批次，模拟步长 25 ms，测试通过专用端点手动推进时钟。A 为 5 Common Rose，B 为 5 Common Basic；接触伤害、速度、轨道和 20000 tick 波次上限均为验收夹具设置，不代表历史数值。W2-03/04 由真实碰撞清波；W2-05 由 W1 的波次上限跨波，未注入实体、血量或生命周期状态。测试端点只存在于夹具可执行文件，正式 `wave_host` 不编入。

本轮使用 Node 24.13.0、Chromium 156.0.8078.47 和 Playwright Core 1.49.1。源码清单与摘要、原件摘要、正式及夹具 native 可执行文件摘要随报告保存。报告和截图为本地生成物，不入库。
