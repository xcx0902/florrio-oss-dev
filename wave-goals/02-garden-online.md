# W2 · 原版客户端 Garden 联机闭环

**目标**　两份原版客户端通过真实 WebSocket 连接独立服务端，原版菜单和 HUD 完成访客、入局、移动、清波、阵亡、观战和重生。用协议夹具验证字节，再接权威服务端。取证可以从 W0 后开始，实服闭环依赖 W1。

## 02.1 先打通原版启动和入局

按 [源码复用清单](reuse-audit.md) 抽取现有 Asio/Beast 通用连接层和每房单次更新模式。历史字节、握手和可见状态通过 [协议专项](protocol-20221030.md) 独立恢复。

1. 按 [W0 的启动需求](00-baseline-and-evidence.md#002-确认可启动的页面和资源) 补齐必要 DOM、资源和本地发现接口。确认原版加载结束，菜单可操作。记录阻塞启动的资源或初始化错误。
2. 按 [协议顺序](protocol-20221030.md#p1--按最短路径恢复格式) 恢复最小握手、小队、首张对局状态和输入。先用原版回放 fixture 抵达 Garden。每一步保留可消费的服务端字节、原版实际发送的消息、客户端状态和字段定位。
3. 实现服务端可接入的本地发现、访客状态和两人私有房。给原版客户端的字段采用已确认的旧格式和可见值。内部仍用类型化身份、命令、实体、波次和生命状态。首版人数上限仅是项目闭环负载，历史容量在 W4 验证。
4. 在 `wave/server/wire/` 接已证实的实体、波次、观战和本地控制字段。在宿主中把真实输入传给 W1 模拟。对局更新后按每连接的可见状态发布。切换波次、死亡、复活和重新连接时，以原客户端能够恢复的全量或等价序列重建控制对象。

## W2 执行结果

旧 W2-01 至 W2-06 通过时仍遗漏了基本可玩性：错误组件映射造成黄色/红色背景、近零血量、错误场地约束、实体过小，合法退出请求还会触发重载。此前“全部通过”只代表当时的部分联机验收，不能证明可玩。

2026-11-07 修订补齐 W2-07 至 W2-10，以真实原版客户端检查正式时钟、绘制/控制字段、常见操作、死亡继续、场景恢复及小队退出。根因、Wasm 消费点、组件与生命周期详见 [客户端模块记录](../wave/docs/client-20221030.md)。双人建房、清波、阵亡重生和断线恢复仍保留 W2-01 至 W2-06 回归。

2026-11-08 继续纠正镜头 X/Y 顺序、本体半径、攻防轨道、Wave 目录/进度、受击命令段和回充字段。旧“花瓣绕转”只观察了 wire 坐标，不能证明原版最终绘制正确；W2-11 增加最终 transform、真实鼠标中心交点和逐帧动画观察。先恢复原版消费者，再接服务端权威状态，具体协议与本地数值选择分开记录。

独立 native 服务使用锁定的 Boost 1.86.0 Asio/Beast，只监听 IPv4 回环。`dev` 在装配前验证两个原件的长度和 SHA-256；启动壳只将发现请求和归档 socket 地址转到本地同源路径。每房在宿主时钟上推进一次，随后按连接投影；每连接独立维护变换状态、可靠序号、实体句柄和已确认生命。

### 2026-11-07 可玩性修订

- `0x2000` 恢复为单一全局圆形场地半径 + RGB，移除旧的每实体 health/color；Garden 使用本地绿色，死亡不再把怪物颜色当底色。
- `0x200000` 第三 byte 映射真实 0..255 血量。W1 位置、实体半径、镜头与场地统一 × 5，正式花朵半径 8 对应客户端 40；花朵 heading 固定 0，花瓣继续由 W1 轨道驱动。这些显示尺度/颜色是显式本地复刻设置。
- 恢复记录头 XOR `ac` 后的扩展标志和 `0x20` 装备布局，默认 level 1，前五 active 槽正确显示 Basic/Rose；不把保留槽与 active 交错。
- 补齐原版无参数请求：退出 11、死亡第一段 Continue 21、小队关闭 38、可选广告完成 34。死亡第二段 GAME OVER Continue 关闭结算后返回菜单，再次 Ready 创建新局。
- 装配归档 Ubuntu 700 的六个 WOFF2、同源 CSS 与许可证，逐个核验字体长度/SHA-256。原 `client.js`/`client.wasm` 不变。
- 原版切换 Desert 的发现请求在本地壳暂停，显示明确的不可用提示；用户主动 Return to Garden 只导航一次并保留访客身份。

新增验收保存正式原版收发帧 `playability.json`、`wire.json` 中 W2-07..10 结果，以及正式游戏、死亡、两段 Continue 后菜单、重新入局、圆形边界、场景恢复与退队截图。原生测试包含 11/21/34/38 的合成加密边界用例；浏览器断言必须使用原版实际发出的命令。

### 2026-11-08 绘制与战斗协议修订

- 空 profile 的 wire 283 是 Y、327 是 X；修正顺序后，用非原点花朵的真实鼠标方位验证屏幕居中。正式本体权威半径改为 5（wire 25），夹具保持 2（wire 10）。
- 原版按钮 bit 0/1 对应 attack/defend，轨道与碰撞一起切换本地倍率 1.8/0.6，同时按下时 defend 优先；断线和重生清除按键模式。
- `0x800` 恢复 biome 和 36×6 存活目录；按用户确认的蓝色生成条→红色清场计时条顺序投影，pending 清零时才启动红条。批次比例和现有 deadline 的映射仍为明确的本地设置。只绘制的死亡记录不进入存活目录。
- 恢复实体终止后的额外分隔 byte、命令 envelope 与 opcode 32。每房最多 4096 条伤害事件、每 socket 独立游标，覆盖普通广播间的事件并避免重放；饱和时会淘汰最旧事件。
- generic bit 0 调用原版 `$597` 的 150 ms 膨胀淡出；投影保留已见记录 400 ms 后真正删除，期间不复用句柄。装备八个回充 vu 映射到归一化 u16，原版自行插值扇形。
- 新花瓣句柄首张广播收花朵中心、下一张收轨道终点，触发原版位置插值；后续广播不重复初始化，权威碰撞半径不变。旧验收仅覆盖回充 widget，未覆盖实体出现，此处补齐。
- W2-11 逐帧观测原版最终绘制、受击向量、死亡时钟、回充 widget 及花瓣重现的中间最终绘制位置；真实碰撞与真实输入产生状态，测试不写 Wasm、不代发游戏命令。截图包括生成阶段、attack/defend、Wave 目录、镜头、淡出、recharge 和出现中间帧。
