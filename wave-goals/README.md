## 2. 独立项目边界

实施代码拟放在 `wave/`，包含独立的 `CMakeLists.txt`、`package.json` 和锁文件。`wave/web/` 管启动壳、资源清单和同源兼容入口。`wave/server/` 按历史线协议、应用会话、模拟和持久化分层。`wave/data/` 管日期固定的规则和目录。`wave/tests/` 管参考回放、线格式夹具和规则测试。`wave/tools/` 管证据提取、浏览器验收及打包。

建议参考当前 World PvP 实现。纯数值、空间索引、定宽字节和哈希工具优先复用。房间、网络宿主及测试结构按需抽取。10 月原协议、波次和历史数值重新建立，界面由原客户端运行。移植代码随 `wave/` 独立保存。具体文件、可用范围、重写项和验收条件见 [源码复用清单](reuse-audit.md)。

`wave-reference/20221030/` 是只读输入。交付时从指定快照验证并装配原件，构建和打包时校验原件哈希。独立构建须能在只含 `wave/` 的临时目录运行，快照及已登记的同版外部资源以固定输入传入。原版 UI 通过历史字节收发，线协议适配器将字节转换为内部的类型化命令与状态，模拟和存档只处理内部类型。客户端和服务端分别持有各自的渲染与游戏状态。

除特别说明，命令从仓库根目录运行。开始一组操作前设置快照路径，构建产物放到 `build/wave/`，报告放到 `reports/wave/`。

```sh
export WAVE_SNAPSHOT="$(pwd)/wave-reference/20221030"
```

W0 已提供 `npm --prefix wave run verify:reference` 和归档资源装配入口。其余阶段的 npm、CTest 和 `wave/tools/` 入口随对应实现新增。
