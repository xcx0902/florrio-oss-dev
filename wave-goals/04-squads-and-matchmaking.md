# W4 · 原版小队、公开匹配与中途加入

**前置**　[W2 的原版小队入口](02-garden-online.md) 与 [W3 持久进度](03-catalog-economy-and-save.md)。本阶段使原客户端能用现有大厅操作完成小队和公开匹配，下发字段通过旧协议验证。

## 04.1 小队生命周期

1. 从原版大厅逐项观察创建、邀请、加入、准备、取消、离开、主持者离线、开局及失败反馈。为每条路径绑定原客户端操作和出站字节。用本地原客户端回放可接受的成员、队长、房间码和结果字段。
2. 在 `wave/server/app/` 建内部小队身份、成员席位、准备和房间版本。开始前对成员、场景、规则版本和存档进度做原子快照。重复开始或准备只产生一次有效结果。房满、错码、旧小队和主持者变化通过原版能读的结果路径呈现。
3. 按已观察的原版行为实现访客、队伍和对局之间的状态转换。小队 ID 与对局 ID 独立。房间返回时优先恢复原有队伍或菜单，具体路径以原客户端接受的消息时序为准。用原版消息时序覆盖成功、失败和取消。

## 04.2 公开匹配与 AFK

1. 用持久化最高波和当前可见场景从公开局筛选，优先选可进入的最高波。同波并发采用稳定排序和原子席位预留。公开资格、起始波公式、最大队伍、区域轮换和迟入时窗分别登记历史来源。缺口填项目设置，避免从现代小队规则直接套用。 [公开匹配和特殊波更新](https://github.com/AstRatJP/florr.io-files/blob/main/i18n/en_US/changelog.txt#L1487-L1506)
2. 中途加入时按原版消息顺序同步队伍、波次、实体和控制身份。新玩家什么时候可控以同期证据为准，早期可用波次边界作为标注过的复刻设定。为候选过期、席位满、撤销及重复连接提供原客户端接受的反馈。
3. 断线保留席位、重连、主动退出与 AFK 分开计时。用服务端采纳的有效行为驱动活动时钟。通过原版反馈验证断线、超时、准备失效和回到大厅。完成波奖励在相应存档提交后才对外确认。 [8 月 AFK 和蚁穴计时记录](https://github.com/AstRatJP/florr.io-files/blob/main/i18n/en_US/changelog.txt#L1527-L1545)

## 04.3 验收

注册 CTest 标签 `w4`。自动化采用可控时钟推进 AFK 和恢复边界，浏览器通过原版菜单和真实 socket 运行。

| 用例             | 操作和通过条件                                                            |
| ---------------- | ------------------------------------------------------------------------- |
| W4-01 私有房     | 原客户端能加入有效房间并收到正确的错误或成员状态，每次操作只转移一次      |
| W4-02 公开选择   | 夹具含合格第 4、8 波和超资格第 11 波，选第 8 波，客户端收到正确房间及波次 |
| W4-03 并发席位   | 两个请求争用最后一席，取消和重试有唯一结果，私房不出现在公开候选          |
| W4-04 迟入和恢复 | 加入后先见当前状态，按已登记时机获得控制。重连恢复旧席位与可见集          |
| W4-05 AFK 边界   | 到期前后分别操作，按规则保留或移除席位，原客户端收到相应状态并可返回大厅  |
| W4-06 结算返回   | 清波、全灭、退队与重复结果消息均只结算一次，原版界面可再次开始            |

```sh
set -eu
cmake --build build/wave/native --parallel
ctest --test-dir build/wave/native --output-on-failure --no-tests=error -L '^w4$'
npm --prefix wave run test:wire -- --snapshot "$WAVE_SNAPSHOT" --stage W4
```

将每个大厅状态的旧协议字节、规则 ID 和联机结果关联到 [执行记录](README.md#执行记录)。状态或字节来源不足时保留缺口和明确范围。
