# W4 · 原版小队、公开匹配与中途加入

**前置**　[W2 的原版小队入口](02-garden-online.md) 与 [W3 持久进度](03-catalog-economy-and-save.md)。本阶段使原客户端能用现有大厅操作完成小队和公开匹配，下发字段通过旧协议验证。

## 04.1 小队生命周期

1. 从原版大厅逐项观察创建、邀请、加入、准备、取消、离开、主持者离线、开局及失败反馈。为每条路径绑定原客户端操作和出站字节。用本地原客户端回放可接受的成员、队长、房间码和结果字段。
2. 在 `wave/server/app/` 建内部小队身份、成员席位、准备和房间版本。开始前对成员、场景、规则版本和存档进度做原子快照。重复开始或准备只产生一次有效结果。房满、错码、旧小队和主持者变化通过原版能读的结果路径呈现。
3. 按已观察的原版行为实现访客、队伍和对局之间的状态转换。小队 ID 与对局 ID 独立。房间返回时优先恢复原有队伍或菜单，具体路径以原客户端接受的消息时序为准。用原版消息时序覆盖成功、失败和取消。

## 04.2 公开匹配、迟入与重连

1. 未入队时点 Ready，按持久化最高通关波和场景筛选运行中的公开局，优先选可进入的最高波。没有合格局时单人开一个可迟入的公开局。Find Public 查找或创建未开局的公开小队。同波并发采用稳定排序和原子席位预留。公开资格、起始波公式、最大队伍、区域轮换和迟入时窗分别登记历史来源。 [公开匹配和特殊波更新](https://github.com/AstRatJP/florr.io-files/blob/main/i18n/en_US/changelog.txt#L1487-L1506)
2. 中途加入时立即生成花朵，同一份世界更新包含队伍、当前波次、实体和控制身份。原版客户端确认这份世界更新后即可移动、攻击和防御。为候选过期、席位满、撤销及重复连接提供原客户端接受的反馈。
3. 大厅断线释放席位并清除准备状态。运行中的对局在重连期限内保留席位，主动退出则释放席位。验证断线、到期、准备失效和回到大厅。清波进度和收益随已提交的资料投影确认。

## 04.3 验收

注册 CTest 标签 `w4`。原生测试使用可控时钟验证重连期限，浏览器通过原版菜单和真实 socket 运行。

| 用例             | 操作和通过条件                                                         |
| ---------------- | ---------------------------------------------------------------------- |
| W4-01 私有房     | 原客户端显示四个已占用席位，满员和错码显示对应的原生提示               |
| W4-02 公开选择   | 未入队的 Ready 在第 4、8、11 波中选第 8 波。Find Public 则进入等待大厅 |
| W4-03 并发席位   | 两个请求争用最后一席，取消和重试有唯一结果，私房不出现在公开候选       |
| W4-04 迟入和恢复 | 同一波内看到当前状态并获得控制。重连恢复旧席位与可见集，到期释放席位   |
| W4-06 结算返回   | 清波、全灭、退队与重复结果消息均只结算一次，原版界面可再次开始         |

```sh
set -eu
cmake --build build/wave/native --parallel
ctest --test-dir build/wave/native --output-on-failure --no-tests=error -L '^w4$'
npm --prefix wave run test:wire -- --snapshot "$WAVE_SNAPSHOT" --stage W4
```

将每个大厅状态的旧协议字节、规则 ID 和联机结果关联到 [执行记录](README.md#执行记录)。状态或字节来源不足时保留缺口和明确范围。

## W4 执行结果

- 私有与公开小队共用四席上限。服务端串行处理加入，席满时保留请求者当前的房间和连接。大厅由第一位成员担任房主，房主离开后由下一席接任，并清掉旧阵容的准备状态。全员就绪后以已提交的装备和通关进度一次创建独立对局。 [大厅与小队协议](../wave/docs/protocol/07-lobby-and-squad.md)
- 未入队的 Ready 按 `match.public.highestEligible` 选最高合格运行波，同波选最早创建的房间。没有符合条件的运行局时单人开启可迟入的公开局。Find Public 优先加入最早创建的可用公开大厅，找不到时创建公开小队。开局波沿用 `match.startingWave` 的最低通关记录乘以 2/3 后向下取整，至少第 1 波。迟入生成于当前波。 [规则及历史来源](../wave/data/evidence/20221030/rules.json)
- 旧存档的全局最高波继续保留。公开局资格使用有明确场景归属的通关记录。
- Desert/Ocean 由宿主的 `WAVE_ROTATION` 决定，默认 Desert。开局前公开状态由房主切换。运行中的队员可在默认 300 秒的重连期限内恢复席位，已结束的对局回到大厅。 [宿主配置](../wave/deploy/README.md)
- C→S `04 01 <房码> 00` 请求加入。失败的响应带上可靠 ACK 和世界命令 `01 12 <文案> 00`（十六进制）。Wave 运行时把原 reader 已解析的 opcode 18 字符串交给原生大厅状态，满员显示 `Squad is full`，错码显示 `Squad doesn't exist`。 [服务端到客户端协议](../wave/docs/protocol/03-server-to-client.md)
