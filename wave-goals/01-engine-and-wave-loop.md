# W1 · 独立 Garden 权威模拟

**前置**　[W0](00-baseline-and-evidence.md) 的早期规则包、场景证据和快照身份。本阶段以原生 C++20 类型化夹具推进，可以和原协议工作并行。

## 01.1 建最小独立服务端

按 [源码复用清单](reuse-audit.md) 从数学原语开始。实体池按 Wave 数据建模，沿用代际句柄和活跃集合设计。需要空间索引时移植四叉树并用朴素查询对照。模拟时钟、RNG 和波次循环由本阶段独立定义。

1. 在 `wave/CMakeLists.txt` 建立模拟库和原生测试。目录按 `wave/server/sim/`、`wave/server/app/`、`wave/server/wire/` 分层。W1 先实现模拟库和直接调用的测试，W2 再接宿主与字节入口。
2. 定义对局、实体、存档玩家和一次生命的独立身份。对局持有地图、波次、时钟、随机种子及参与者。模拟命令按服务器 tick 采纳，先执行命令和已到期生成，再结算移动、碰撞、伤害、死亡及波次。不同对局的时间和随机状态独立。
3. 把模拟步长和广播节奏分开登记。参考消息间隔只能证明广播节奏时，将模拟步长作为复刻设定，避免继承旧版 50 ms 或把画面帧率当成服务端频率。处理计时和重放时使用明确单位和量化规则。
4. 实现圆形场地、出生、移动、击退和生成点选择。有效中心范围受场地半径、实体碰撞半径和已验证的边界差异约束。覆盖圆心、边缘、超大实体和生成阻塞。碰撞、花瓣轨道、朝向、血量和冷却的数值需要同时服务权威计算和 W2 的原版字段投影。

## 01.2 实现波次和生命周期

1. 为每个场景定义可审计配置，包括怪种资格、稀有度、波次预算、批次时间、位置规则、存活阈值、特殊波和截止条件。先用 W1 固定测试表，再接 W0 的 Garden 候选表。进入一波时锁定配置版本和生成计划。
2. 记录计划、待处理、实际生成、存活和击败。只将合格主怪计入波次，分节、召唤物、穴内怪和残怪单独登记。生成阻塞有界重试并记录原因。按照待验证的服务端规则选择是否保留上一波残余，配置标记其证据等级。
3. 波次路径覆盖等待、生成、清理、推进和结束。先按「完成本波生成后剩怪不超过 4 只可推进、达到截止时另行判定」建立测试，阈值来自历史资料，批次时点和清理口径待 10 月证据校准。同 tick 清波、超时、死亡和结束按显式优先级裁决，至多一条转移。 [历史波次资料](https://official-florrio.fandom.com/wiki/Waves) · [原日志](https://github.com/AstRatJP/florr.io-files/blob/main/i18n/en_US/changelog.txt#L1634-L1652)
4. 阵亡时保留玩家身份与装备归属，清除旧身体输入，生成死亡及等待状态。验证有幸存队友时下一波重生。全队阵亡、最后一人断线和超时后复活资格放入规则表，早期测试值标记为复刻设定。重生生成新实体并拒绝旧生命操作。
5. 对 PvE 的玩家、队友、召唤物和花瓣定义敌友表。分别处理物理推挤、碰撞伤害、治疗、毒和伤害来源。录入最小 Garden 生态，扩展怪物及花瓣行为等 W3/W5 校准。

## 01.3 运行确定性夹具

注册 CTest 标签 `w1`。测试表以 `S` 为开波 tick，`S` 生成 2 只，`S+3` 生成 4 只，`S+10` 是测试截止。这些量仅是测试夹具。

| 用例             | 操作                                         | 通过                                                 |
| ---------------- | -------------------------------------------- | ---------------------------------------------------- |
| W1-01 批次       | 第一批清零并推进到 `S+2`，再到 `S+3`         | 第一批清完后仍在本波，第二批准时出现                 |
| W1-02 阈值       | 最后一批后分别留 5 只和 4 只，另测同时到截止 | 5 只等待，4 只推进，同 tick 只有一次转移             |
| W1-03 生成失败   | 堵住候选点直至到期                           | 重试有界，批次能结算，清场按配置，虚假击杀不获奖励   |
| W1-04 生命       | A 阵亡，B 清波，对 A 重放旧输入；另测双死    | A 在合法波次重生一次，旧身体输入无效，全灭只结算一次 |
| W1-05 圆形与敌友 | 冲刺和击退触边，比较友方与敌方接触           | 中心约束及碰撞范围正确，伤害和治疗按敌友表           |
| W1-06 隔离       | 同种子运行两次，再与另一房间交错运行         | 规范化事件、随机抽样和波次摘要一致                   |

注册测试后执行。

```sh
set -eu
cmake -S wave -B build/wave/native -DCMAKE_BUILD_TYPE=Release
cmake --build build/wave/native --parallel
ctest --test-dir build/wave/native --output-on-failure --no-tests=error -L '^w1$'
```

将种子、计划与实际生成 tick、对局转移、伤害和生命代次写入报告。向 W2 交付可供原协议映射的只读视图与可重复测试场景。第一批规则无证据的部分登记在 [执行记录](README.md#执行记录)。

### 复刻设定与待校准项

- 模拟步长暂定 25 ms，广播间隔单独登记为 100 ms。W0 的秒数向上量化到整数 tick。每局持有独立的 MT19937，按有界拒绝抽样选怪种、特殊波组和生成点。初始位置扫描顺序从一次抽样开始，之后按候选表循环。精确历史频率、抽样算法和顺序待证。
- 圆形场地已证实。半径 200、有效中心半径 `max(0, 场地半径 - 实体半径)`、圆外投影、相切判定、八个生成候选点、每槽最多四次尝试，以及碰撞和击退数值属于复刻设定。当前规模以按槽位有序的朴素遍历处理碰撞和生成阻塞。
- W0 前三波的 6/8/10 只、统一 Common、批次时点与 20/25/30 秒截止沿用 W0 估计值。特殊波组采用 W0 候选，先筛掉当波未解锁怪种及空组，再等权抽样。当前 Garden 场景在第三波结算后结束。
- 完成全部生成结算后，主怪存活数不超过 4 或达到截止可推进。优先判断全灭及最后一人断线，其次判阈值，最后判截止。默认全灭或最后一人断线结束，仍连接的阵亡玩家在下一个合法开波 tick 重生，截止推进也可重生。跨波残怪默认清除，可配置保留。分节、召唤物、穴内怪及残怪单独计数，生成失败和清除不计击败。精确计数和生命周期例外待证。
- Garden 基础怪物的移动、碰撞、生命、毒、伤害及 Basic/Rose 的轨道、治疗、冷却和重载均为 W1 复刻值。后续按 W3/W5 校准怪物和花瓣数值与行为。
