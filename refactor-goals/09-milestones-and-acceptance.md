## M3. 结构整理

按独立可验证提交完成：

| 提交主题 | 明确内容 | 检查重点 |
| --- | --- | --- |
| 引擎发布边界 | WorkerApi → SnapshotPublisher/ReplicationSession，单一 codec | 初始、delta、删除、离开/重入、事件 |
| 引擎存储/生命周期 | EntityPool、World 拆分，统一 destroy，移除原始布局镜像 | handle/generation、owner/children、reset |
| 引擎系统 | death/contacts/AI 边界，碰撞缓存归 World，删除实验策略 | 接触顺序、双 World 隔离、RNG |
| 客户端应用边界 | GameApp、session、loop、input、frame renderer | 异步状态、出生冷却、资源 dispose |
| 客户端协议/状态 | 单一 decoder、投影层、字段时钟与 player 索引 | 缺失/0、dense presence、非法包原子性 |
| 客户端 UI/绘制 | 共享 geometry、HUD/art 拆分、RenderResources | 命中、DPR、死亡过渡、缓存释放 |
| 工具收敛 | HTTP/browser/runner helper、唯一 gate 定义、报告拆分 | 失败路径、锁、取消、证据一致性 |

结构提交维持产品行为；性能变化单独标识。没有消费者的 helper 删除，不仅移动后继续保留双入口。

后续实现应提供相应目标命令；以下是目标流程示例，目前不保证根 package 已存在这些命令：

这些步骤在不含 archive、旧 `dist*`、旧 `reports`、旧 `client/public` 编译物的源码副本执行；工具链和依赖按项目固定版本准备。离线构建指依赖/工具链已安装后的产品生成与构建不访问原版或远程服务，不声称空缓存 `npm ci` 无需联网。

`test:all` 内部已覆盖的步骤无需外部重复运行；实际落地应给出一条完整验收命令和各局部命令，避免为同一次发布重复编译/测试。

## 最终验收矩阵

| 目标 | 检查方式 | 不可接受的替代证明 |
| --- | --- | --- |
| 历史归档完整 | 清单、源/目标哈希、链接解析、迁移记录 | 只有一个 archive 文件夹但兼容链接仍可运行 |
| 归档不再生效 | 构建/测试/生成/发布的依赖图及实际无归档运行 | 只搜索不到 upstream 字符串 |
| 删除重复实现 | 单一数据来源、当前 codec/publisher、命中与绘制共用 layout | 仅把大文件分成许多共享全局的小文件 |
| 产品功能保留 | native、字节向量、跨端集成、真实页面输入 | 删除失败测试后通过或只测 can boot |
| 新鲜产物 | 源码、工具配置、编译记录、交付 manifest 绑定 | 读取历史报告或只看文件存在 |
| 真实性能收益 | 相同机器/配置/负载、多次分布、计数器 | 冻结 worker 的 FPS 代表模拟提速 |
| 内存有界 | owner/cache/queue 计数、生命周期 soak、估算资源预算 | 一次 heap 截图或要求 wasm 高水位归零 |
| 可继续扩展 | 新数据项生成两端、局部行为模块、模块测试 | 增加物种时复制旧 switch 到多处 |
| 发布可执行 | 干净副本生成包、交付 smoke、版本与哈希、上一产品包回退 | 每次发布重新验证原版等价或恢复整个上游 |

## 回退和范围控制

- 归档迁移提交与产品行为/性能提交分开；回退一个性能优化不应重新激活原版入口。
- 发布回退使用上一份通过验收的当前产品包，不恢复原版 worker 或旧 skeleton fallback。
- 改变 wire 格式、RNG、碰撞顺序、固定步长、存储键或玩法数值时，独立列行为变更、版本与迁移，不混入“删除重复代码”。
- 更新数据生成、编译配置或当前产品源码后重新生成对应证据；只改本文档不应使产品源码哈希变化。
- 未实现的目标继续保持未完成，不用旧原版通过率、历史恢复覆盖率或计划中的收益数字填充完成状态。
