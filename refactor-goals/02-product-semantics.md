# 02 — 当前语义与协议模型

## 目标与判定规则

当前代码、注释、活动 schema 和使用文档应能独立描述当前产品，不以旧函数编号、旧虚表、旧记录大小、旧地址、旧内存偏移或归档探针作为解释依据。

这是表示和说明的治理，不是重做玩法或网络协议。当前项目真实使用的 opcode、字段号、组件 mask、包内偏移、字节宽度、ABI 导出名和支持的浏览器 API 都应按其现行契约保留。需要清理的是历史实现身份，以及为了模拟它而存在的无用表示。

## RF-H1：区分协议标识和旧实现细节

| 内容 | 处理规则 |
| --- | --- |
| `orbitFunctionIndex`、`orbit_function`、旧攻击 callback 数字 | 依照 [01](01-fields.md) 改为当前行为与参数 |
| `func587`、`original 43/85/394` 等注释、测试名和断言文字 | 删除编号依赖，重写为当前行为、顺序和边界条件 |
| `AI+144`、`entity+212`、`loadout+292`、旧记录大小和地址 | 移除；必要信息改写为当前字段含义、所有权或单位 |
| `constructor: 478`、历史 `offset`、`kDenseFieldsMinus16` | 移除旧模型，建立当前协议字段与组件表示 |
| 真实 wire 字段号、协议组件序号、包头内的实际字节位置 | 保留数值契约，用 schema 和具名常量描述 |
| JavaScript/TypeScript 的类 `constructor`、字节 reader 的 `offset` | 属于当前编程或解析概念，不做关键词误删 |
| `const original = structuredClone(...)` 等备份变量 | 与历史实现无关；按普通可读性要求处理 |
| 工具对 `archive/` 的构建输入隔离或输出路径保护 | 属于当前工程约束，保留；说明采用当前职责语言 |

## RF-H2：替换协议中的构造函数和布局映射

### 当前依赖链

`schema/protocol.yaml → tools/schema/protocol.mjs → 生成 C++/TS 元数据 → snapshot decoder/projection → WorldState 合并 → 渲染和 UI`

同时，`schema/multiplayer.yaml`、多人生成器、公开字段过滤、测试向量和 C++ dense 查询使用旧偏移作为组标识，必须在同一个阶段迁移。

### 目标表示

1. schema 以真实 `fieldId`、wire 类型、索引类型/容量、所属协议组件及 dense 编码顺序定义字段。
2. dense 组以当前组件的具名标识及真实组件序号识别；序号仍负责计算现有 component mask，不以旧内存偏移作为 key。
3. 对实际使用的字段生成 `SnapshotField`、组件和相关标志常量；通用 codec 的数字索引只在协议表和边界实现中出现。
4. 客户端用按字段标识组织的权威值表示完成投影，移除 `components[constructor][offset]`。领域对象只暴露当前坐标、生命、物种、装备等含义明确的数据。
5. 不增加新的“旧 offset → 新 enum”永久适配层；修改所有活动调用者和测试后直接移除旧接口。

字段名称从当前生产者和消费者确定。对于必须支持但当前未投影的 wire 字段，可以在协议边界明确标注为保留字段及其读写约束；不猜测旧实现含义，也不把保留字段扩散为领域成员。

### 实施步骤

1. 建立字段与组的迁移表：旧内部 key、当前 wire 字段、组件序号、值类型、编码次序、现有生产/消费模块、新符号。
2. 固定当前手写字节向量和 native → TS 行为断言；这一步只记录当前产品契约，不调用归档。
3. 改造 protocol 编译器，删除历史 `constructor/offset` 校验和输出，增加字段/组件映射完整性检查。
4. 修改 C++ dense 表、查询入口和 snapshot writer。将 `dense_group_by_offset` 换成按当前组件职责查询，移除公共旧名称转发。
5. 修改客户端 decoder、投影、snapshot 类型、WorldState 的合并和 reset 逻辑，删除历史嵌套状态及只为它存在的拷贝。
6. 更新多人 schema 的公开 dense 组选择和生成器校验，验证公开字段集合、真实组件 mask、隐私边界和编码顺序未改变。
7. 修改 codec/结构测试，断言真实字段值、原子提交和组件存在性；不再断言某旧构造函数等于某数字。
8. 重生成全部输出和清单，更新现行协议文档，清除所有旧接口及无消费 metadata。

### 必须保持的约束

- 同一输入得到相同的包字节、字段顺序、位宽、大小端、索引语义和实体 handle 表示。
- 稀疏字段累计越界、截断、无效字段类型、重复或错误组件等依旧拒绝；失败时不提交部分删除、字段或 component mask。
- dense 的组件存在性、扩展字段开关、全量/增量、删除及再次出现的行为不变。
- 多人公开/私有字段、baseline、事件去重及本地玩家身份不变。

这些约束由字节和行为测试验证，而不是以旧 metadata 是否保持相同来验证。

## RF-H3：清理其他历史 schema 壳层

审查 `schema/protocol.yaml` 的 `output.packet` 中 `heapPayloadOffset`、`inlinePayloadOffset`、`inlinePayloadBytes` 等字段，以及 worker function 的 `args` metadata。

这些内容不能仅因位于 protocol 文件中就被认定为真实 wire 契约。分别核对当前 `OutputPacket`、Worker 消息、C ABI 和生成常量消费者：若只是旧堆内存结构信息，则删除输入、校验、生成常量和相关文档；若当前仍有用途，则用当前包或接口语义重新定义。`sp_server_init`、`sp_server_send` 等实际导出是否保留，以当前 Worker 和 ABI 清单为准。

## RF-H4：重写注释、名称与当前说明

按模块与其语义重构同步修改，最后全项目复查：

- 引擎模型和 sim：说明单位、状态机、随机消耗、遍历次序和生命周期；保留精度和顺序约束的理由。
- 客户端绘制：说明坐标系、变换顺序、alpha、缓存所有权和动画状态，不用旧绘图函数编号代指行为。
- 测试：按触发条件和预期命名，输出文字不再声称“原版一致”或“旧 WASM 案例通过”。现有数值只有具备当前行为依据时才保留。
- 文档：重写 `docs/semantics/` 中的旧布局表、回调编号等，核对 engine/client README 及 protocol/catalog 说明。

例如注释应说明“同一 tick 对同一代实体的伤害合并为一次命中事件”，不再附加它对应哪个历史函数或记录偏移。删除历史注释时要保留这类真实约束，不能仅把整段说明清空。

`docs/refactor-continuation.md`、`docs/test-migration.csv`、已发布版本记录及旧验收记录属于历史事实，可保留并明确标记其历史性质；当前规格不能要求读者依赖它们理解代码。不修改 `archive/`，不把历史记录伪装为当前通过证据。

## RF-H5：防止重新引入

在活动源码、测试和 schema 中检查编号式未知字段、函数编号型注释和旧布局型标识；扫描范围使用明确的当前目录和生成清单，不遍历归档。配合类型检查与人工审阅，避免误判类构造函数、真实 wire offset 或备份变量。

已确认的历史表示应零残留。扫描规则的正常语言误报要修正规则或提供明确的当前职责说明，不能通过整目录忽略掩盖问题。审阅记录可引用旧符号定位问题，运行时代码和当前接口不能依赖旧符号。

## 输出与验收

迁移表逐项完成；旧构造函数表和旧 offset 索引从活动 schema、生成输出及运行时状态移除；当前文档独立成立；通过 schema、协议向量、双端 codec、事务失败和多人公开字段验证。内部 metadata 变化本身不要求改变协议版本；发现真实 wire 变化则应停下拆分处理。
