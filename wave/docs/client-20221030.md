## WebSocket 层次

1. 原始 hello：字节 `0x30`、40 字节构建标识、NUL 账号串与 NUL 访客串。本地账号串为空；访客串来自 `cp6_player_id`。
2. 每 socket、每方向独立推进外层置换/22 字节 XOR 状态。C→S 初始状态为 `0x99df460b`，S→C 为 `0x13bde6d7`；消息负载另有 256 字节循环掩码。具体置换、生成器及已固定捕获见 `data/wire/20221030/w2-bootstrap.md` 和 `tools/w2/codec.mjs`。
3. C→S 类型 2 为 world ACK；类型 1 为 `epoch, sequence, opcode, fields` 的可靠批次。批次序号连续，重传不能重做动作。整数为无符号 LEB128，实体引用为 LE u32，实数为 LE binary32，字符串为 NUL 结尾。
4. S→C world 包包含 epoch、tick、已消费可靠序号、长度限定删除段、实体记录和命令段。记录头的标志字节须先 XOR `0xac`：目前普通记录 `0xcc → 0x60`，带扩展装备记录 `0xc4 → 0x68`。两者不能不加区分地视为固定 magic。后接 LE 24 位组件存在掩码。实体列表由 LE u32 零句柄终止，**其后还有一个被 `$601` 跳过的分隔 byte**，随后才是命令列表；省略它会让 opcode 被当成 envelope，下一字段被当成非法 opcode，直接触发 Wasm `unreachable`。

### 旧错映射的因果链

旧实现向每个实体发送 `0x2000`，内容为 health ratio 和实体颜色。原版把第一个花朵的黄色当成全屏场地色；花朵死亡删除后，又把怪物的红色当底色。health ratio=1 则成了半径 1 的地图，比玩家还小，本地控制约束由此失真，出现移动反向和花瓣位置异常。

花朵 `0x200000` 最后一个 byte 原先发 1，只相当于 `1/255` 血量，并非布尔 alive。当前由权威 `health / max_health` 量化到 0..255。场地只向句柄 8196 发送，RGB 为本地 Garden 设定 `(30,167,97)`，半径来自 W1 场地。

### 显示单位与装备

W1 的紧凑单位统一乘 5 投影到客户端：实体位置、半径、镜头坐标、场地半径和尺寸全部同步缩放。2026-11-08 将正式花朵的权威半径由 8 调为 5，对应 wire 半径由 40 调为 **25**；测试夹具仍为 2 → 10。这是**本地重建约定**，不是已恢复的历史服务器比例。不能只放大花朵而保留原位置/轨道/边界单位。

花朵位置照常移动，但投影 heading 为 0，保持脸正立；花瓣位置由 W1 `update_orbits` 随时钟产生。原版 opcode 9 的左键为 buttons bit 0，右键为 bit 1。权威轨道和碰撞一并按 idle/attack/defend 切换：本地倍率 1/1.8/0.6，同时按下时 defend 优先；其他高位不触发攻击。断线、重生和移除会清理按住的模式。

快捷栏按玩家权威 loadout 发送，当前 n 个 active 后接 n 个 reserve；不是 active/reserve 交错。W2 的 n 固定为 5，W3 按等级在 15/30/45 解锁 6/7/8 槽，适配 Store 的固定主槽 `[0,8)`、副槽 `[8,16)`。八个回充值按 `floor(65535 × (1 - remaining_ticks / slot_reload_ticks))` 发送并夹在 0..65535：破碎为 0，就绪为 65535。W3 使用各槽目录给出的总冷却。客户端 `$126/$998` 自行插值，绘制比例平方对应的扇形；单位是归一化比例，不能发送剩余毫秒。W2 兼容夹具保持 level 1，W3 显示提交后的等级和 XP 进度。

### 镜头与实际绘制

`$991` 使用 profile 内存 `+2376` 为 X、`+2264` 为 Y、`+2316` 为 scale；空 profile 的对应 wire 偏移是 327、283、314。旧实现将 X/Y 对调，所以权威实体位置虽正确，镜头仍漂移。profile `+2336` 尚未完整命名，不能称为镜头坐标。

原版实体池基址为 `world + 22848 + (handle & 8191) × 376`，实体 `+28` 是完整句柄。`$973` 更新 transform，`$41` 合成最终绘制位置，结果在 transform `+176/+184`（f64），不是 wire 的原始 x/y。W2-11 读取这些最终坐标验证绕转和扩缩，并通过两条真实鼠标方位的交点检查非原点处花朵仍位于屏幕中心；只比较服务端坐标或 profile 字段不足以证明跟随正确。

### Wave 进度与怪物目录

`0x800` 的格式为：首 byte、wave-index vu、biome-index vu、**216 个 vu**、尾 byte。首/尾 byte 位于 world `+820/+2560`，由 `$828` 绘制两条归一化进度；wave index 位于 `+824`，biome 位于 `+828`，目录从 `+832` 起。目录索引为 `type × 6 + rarity`（36 类型 × 6 稀有度），不能将 biome 写成 alive 总数，也不能用 217 个零代替整个目录。

按用户确认的顺序，尾 byte 是先推进的蓝色刷怪条，首 byte 是刷怪结束后覆盖其上的红色清场计时条。旧版同时发送整波 elapsed 和击杀比例，阶段含义错误。Garden 的底条实际使用 biome 配色，不能据颜色名改变原版调色。

本地将蓝条映射为 `(planned - pending) / planned`；分批生成及阻塞重试尚未结算时，红条保持 0。W1 在 `spawn_due` 真正结算最后一个待生成槽时记录 `spawn_complete_tick`（包括尝试耗尽），红条随后按 `(last_simulated_tick - spawn_complete_tick) / (deadline_tick - spawn_complete_tick)` 推进，沿用现有 deadline。切波清空完成时刻，两条均量化到 0..255。阶段顺序来自用户确认，精确时长和批次比例仍是本地复刻参数；没有恢复历史服务器计时公式。击杀不直接增加任一条，但仍按 W1 阈值触发提前切波。

存活目录统计权威 view 内的敌方怪物与子实体，包含跨波存活的怪物。Egg 友军和死亡淡出的只绘制记录不计入。原版可能合并某些子类型为同一目录项，不能只按最终卡片数量推断存活实体数量。

### 回充后的花瓣出现

快捷栏扇形与花瓣实体重现是两条独立消费路径。旧 W2-11 只验证前者，不能证明后者有动画。`$601` 的 dense 首次创建将旧位置直接设为目标位置；直接发送轨道终点会让回充后的新句柄瞬间出现。后续位置更新由 `$973/$41` 逐帧插值至目标位置。运行时还确认，同一首次快照内重复发送中心与终点仍被首帧初始化覆盖，因此须跨两次正常广播建立过渡。

本次排查还排除了一个假象：`0x1000` 的半径更新虽使 `$460` 的包围盒插值，但 Basic/Rose 的图形使用独立绘制对象；只读包围盒不能证明花瓣图像缩放。实际对象的虚表绘制入口为 Basic table 1037 → `$1512` → `$247`，Rose table 1043 → `$247`，最终 Canvas 图像复查确认二者与包围盒尺寸是不同消费路径。

投影为每 socket 首次可见的花瓣句柄，先在首次广播发送位于所属花朵中心的完整记录，下一次广播发送权威轨道位置记录。客户端自行插值，使重现的花瓣从花朵中心展开至轨道；后续广播只发目标记录，不重复初始化。该操作仅改变显示，不修改模拟位置、半径、碰撞、回充时刻或死亡淡出。它是已确认位置更新机制上的服务端适配，不声称恢复了独立的历史出生 opcode。W2-11 跟踪真实回充后的新句柄，断言原版最终绘制位置经过中心与轨道之间并最终到达轨道，在对应 RAF 保存原版 Canvas 图像 `W2-11-petal-appear.png`。

### 怪物与导弹的绘制尺寸

投影将服务端实际碰撞半径写入 `0x1000`，使用与坐标相同的单位换算。`web/local.js` 在 `$597` 的世界绘制分支补偿各物种原图的比例，使主体对应碰撞直径；足、触角等装饰保留原样。Baby、Worker、Soldier、Queen、Fire Ant、Square 和 Missile 原图使用固定尺寸，适配后以怪物 35、Missile 15 客户端单位为基准缩放。水蛭的 `$1795` 沿原有坐标和引用绘制整条身体，主体外缘计入原图描边后与各节碰撞半径对应。此适配保留归档哈希，不改变背包、图鉴或提示框的绘制。

### AFK 限制

Wave 宿主沿用旧服务端的设置，不启用 WebSocket 空闲超时。原版客户端 `$991` 还有独立的本地 AFK 计时：倒计时剩 15 秒时警告，60 秒到期后调用 `$987` 发送离开命令。Wave 在加载固定快照时让该分支走已有的清除倒计时路径。主动离开仍使用原版命令。

### 受击、消失与事件投递

`$601` 的命令 envelope：0 终止，1 不带可靠序号直接执行，2 以上参与旧序号过滤。当前受击事件使用 `vu 1, vu 32, LE u32 handle, u8 strength`。`$988` 校验句柄代次，以 `clamp((strength / 255)^0.2, 0.1, 1)` 追加通用组件的 24-byte 事件；`$51` 消费约 150 ms 的闪白/红色衰减。本地强度由实际伤害 / max health 量化，范围 1..255。

每房保存递增序号的非治疗 `HealthChange` 日志；每个 socket 有独立游标。25 ms 模拟与 100 ms 发布之间的事件不会因只读取最后一 tick 而遗漏，重复快照不重放，新连接跳过连接前的事件。日志上限为 4096 条，极端饱和时会淘汰最早事件；不承诺无限积压下无丢失。

`$597` 确认通用组件 `+8` bit 0 是死亡绘制：原版从首次绘制开始记时（组件 `+40/+48`），150 ms 内 alpha 由 1 降到 0、比例由 1 增至 2。服务端投影对该 socket 曾见过的消失实体保留旧记录 400 ms，设置此 bit，之后再真正删除并释放句柄。这些记录不参与碰撞、波次计数和控制；换局或离场直接清理。若实体此前未被该 socket 绘制，不补造历史动画。句柄在淡出保留期内不能复用，代次检查也避免旧受击命中新的花瓣。

飞行弹体到期直接移除。Peas/Grapes 分裂后用 `0x4000` 绘制单粒，bit 0 选择紫色；Egg 友军用 `0x100000` 的第二字节 bit 0 选择黄色。每段闪电用 `vu 1, vu 33, f32 x1, f32 y1, f32 x2, f32 y2` 交给 `$988`，按各 socket 的事件游标投递。

新掉落的首个记录设置解码后记录头 bit 1（`0xce`），让原版从零开始放大旋转。入库事务提交后，投影为已见过掉落的 socket 保留同一句柄约 700 ms，更新坐标向拾取者收拢，并设置 `0x400000` 首字节 bit 0，触发原版缩小和反向旋转。随后正常删除句柄。

旧服务端不认识 11/21/34，会发送 `00 00` 并关闭。原版 `$3309` 对该消息走 ASM_CONST `144369`，延时调用 `qc()`，后者 `location.reload(true)`，因此用户看见重载/Connecting 循环。修复应恢复合法请求的结构与语义，不能靠吞掉任意未知 opcode 或修改原客户端来掩盖错误。

`$939` 的死亡 UI 状态位于本快照 `839920`：0 为初始死亡界面，第一次 Continue 置 1 并发送 21；服务端离场状态抵达后置 2，显示 GAME OVER Continue；第二次 Continue 置 -1，关闭结算、尝试广告并发 34，返回原菜单。再次 Ready 才产生 7。W2-08 用真实碰撞验证两段流程与满血新控制对象，不能把 34 当 Ready。

`$991` 生成退队 opcode 38（无参数），运行时点击小队右上 X 复验。旧实现拒绝它，也会出现整页重载；W2-10 验证 roster 删除、原版邀请 hash 清除与 socket/文档加载次数不变。hash 变化是同文档导航，不能计作整页刷新。

开队 27 和快速开始 3 携带变长请求号；该值不决定房间类型。W2-10 连续开队、退出两次，验证第二次请求号为 2 且仍能正常操作。

原客户端不发送 W1 `LifeId`。每个已发布 tick 保存其控制生命；ACK 后的输入只携带那一生命的权限。阵亡、跨波重生与重连都必须重建控制引用，旧 ACK、重复可靠序号和旧连接不能回退或劫持新生命。

## 本地场景发现与恢复

Garden 使用 `florrio-waves-0`；Desert 与 Ocean 使用旧版共用的 `florrio-waves-1`。`web/local.js` 将两者转为同源发现，并根据左上角选择连接对应的本地 socket。Ocean 选择保存在 `?biome=ocean`，访客身份与存档跨场景保留。PvP 发现仍显示返回 Garden 的对话框。W2-09 用原版客户端实际进入 Desert 和 Ocean，核对地图配色、怪物池、Wasm 场景字段及访客身份。

同一访客只由最近打开的连接控制。旧连接以 WebSocket 4001 关闭，不发强制刷新的 `00 00`。非法请求仍按原协议拒绝；本地适配层收到 `00 00` 或连接中断时显示可点击的 Reconnect，由玩家选择重连。存档预加载使用有超时的异步请求；短暂收不到数据时同样显示重连入口，数据恢复后提示自行消失。W2-12 验证这几条路径以及同一访客身份的恢复。
