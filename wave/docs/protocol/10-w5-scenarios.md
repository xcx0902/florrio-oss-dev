# W5 · 蚁穴区域与独立 PvP

基于 2022-10-30 原件 `client.wasm`，SHA-256
`68094577a0ac1254fcffedbb46c0181d90893bd063e3eafa76489bba2776e7b0`。
REA `inspect_wasm_artifact` 使用 WABT 1.0.42 验证原件有效，完整证据父 ID 为
`ev_912e711639c51ce4eedad60b64a3c1a727549a7d0721cf8289127987a4fb7b1a`。
静态分析并不证明旧服务器数值；浏览器结果另见 `reports/wave/W5/wire.json`。

## PvP 入口和模式

原版有三个菜单槽位，`florrio_gamemode` 为 0/1/2：Garden、轮换场景和 PvP。
`$183` 按 `% 3` 选择槽位；第三项的发现名称是 `florrio-pvp`（字符串 28711）。
原版 `$977` 维护 `cached_pvp_unlocked`，表槽 159 的 `$3411` 使用等级大于 14 的条件。
宿主的签名缓存使用单 byte 布尔值和 `cached_pvp_unlocked` 的原缓存哈希，
与等级使用的 zigzag 整数编码不同。服务端同样验证等级 15 的准入。

`0x2` 元数据的首字节为 `2`，后跟 NUL 服务器 ID 和 `vu rotation`。
本地固定 ID 是 `wavepvp`，发现响应的本地 IPv4 是 `127.0.0.3`；启动壳把
`ws://127.0.0.3:443/` 或 `wss://wavepvp.s.m28n.net/` 映射到 `/wave/socket/pvp`。
原版菜单的模式变化重新连接对应 socket，资料身份不变。

PvP 不发送四席 `0x200` 小队组件，也不发送 `0x800` 波次组件。
世界、花朵、装备、受击、死亡页和地面掉落仍用原有字段。
`0x10` 末字节 bit 1 在该玩家 PvP 生命结束时置位，使原版 Continue 进入结算路径。
击杀者的玩家名通过 profile 的 killer 字符串传入原生死亡页。
场地底色采用原客户端进入游戏前的菜单底色：Garden `#1ea761`、Desert `#decf7c`、
Ocean `#5785ba`、PvP `#4d5e56`。蚁穴内部采用对应入口外圈的原生填色：
Ant Hole `#b58500`，Fire Ant Burrow `#b52d00`，与所在 biome 无关。
这些 RGB 从固定原件的真实 Canvas 绘制中提取；菜单到主场、入口外圈到内部的映射按本次需求采用。
[冻结配色](../../data/wire/20221030/w5-backgrounds.json)同时用于编译规则，浏览器比较菜单像素、
线上 `0x2000` RGB 与入场后的实际像素，单独保存六种背景截图。
原件 `$3424` 还会构造 RGBA `(50,96,168,80)` 的 Ocean 全屏滤色层，
导致 `(87,133,186)` 实际显示为 `(75,121,180)`。现有 `local.js` 兼容适配在字节
`2268863` 处校验 `41 b2 c0 a1 85 05`，同宽替换为 `41 b2 c0 a1 85 00`，
只将此滤色层 alpha 清零，让最终画面满足指定的菜单／蚁穴配色。

## 原版排行榜 `0x8`

原来的协议说明已识别字段结构，W5 补齐 `$939` 的实际消费者。
记录仍使用保留句柄 8195，组件 `0x8` 的 body 按以下顺序编码：

| 顺序 | 线上字段        | 原版内存        | 含义                                     |
| ---- | --------------- | --------------- | ---------------------------------------- |
| 1    | `vu`            | world +124      | 场内存活花朵总人数                       |
| 2    | 10 × `vu`       | world +128..164 | 排名前十的分数                           |
| 3    | 10 × `LE32`     | world +208..244 | 对应身份句柄（本人为 profile 句柄 8193） |
| 4    | `u8`，最大 10   | world +288      | 有效榜单人数                             |
| 5    | 10 × NUL 字符串 | world +292..411 | 对应名字                                 |

`$601` 解析这些字段；`$939` 从 world+116 的统计对象读取 +8、+12、+92、
+172、+176，构造名字和分数条，按照分数显示数值或 K/M 缩写。
其 +8 用于 `N Flowers` 标题；本人的分数由 profile killer 字符串后的 f32
（profile +2336）提供，榜单本人身份使用 profile 句柄，避免原版重复追加本人一行。
本地排序为分数递减、同分按玩家 ID 递增；这项同分约定属于复刻设定。
投影将 uint64 分数夹到客户端 u32 上限，排行榜人数不受四席小队限制。

## 蚁穴可见区域

服务端区域 ID 不直接发给原客户端。切场通过同一个世界更新完成：
删除旧区域的怪物、掉落和队友实体，发布新区域的实体、控制身份、相机、圆形场地及目录。
跨区删除不保留死亡淡出，首次新区域的位置使用 arrival bit，避免旧场景残影。
小队名字和装备保持，异区花朵句柄为 0；受击、闪电和拾取也按区域过滤。

`0x10` 的宽高、`0x2000` 的圆半径/RGB 改成洞内值，返回时恢复主场值。
原版 HUD 的生物群系编号是 Garden=0、Desert=1、Swamp=2、Ocean=3；
已检查字段与字符串没有确定一个专用蚁穴子场景编号或数秒倒计时文本字段。
因此洞内沿用母场的原生场景名和 Wave 数字，目录只统计洞内怪物；
蓝色原生进度条用于剩余实例时间比例。这是明确的本地显示设定，不是历史编码结论。

切场保留身体、血量、装备和资料，但推进服务端控制生命代次。
新快照 ACK 之前的输入使用旧代次，服务端拒绝它，避免进出瞬间的迟到输入越区执行。
返回、断线恢复或新连接均由服务器重新计算可见集，不在浏览器保存区域副本。

## 验证入口

```sh
cmake --build build/wave/native --target wave_host_fixture wave_w3_seed --parallel
npm --prefix wave run test:wire -- --snapshot "$PWD/wave-reference/20221030" --stage W5
```

`wave_host_fixture` 的 `/wave/test/w5/` 操作只准备遭遇、血量和分数，正式
`wave_host`/`wave_host_dev` 没有这些路由。进入、移动、攻击、拾取和离开通过原版
Canvas 菜单及真实 socket 操作，报告保存旧协议帧和截图。
