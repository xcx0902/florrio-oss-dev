# 05 · 本地资料组件（`0x8000`）

`0x8000` 是**每个连接自己的**资料实体（句柄 8193），不是其他玩家的资料。它携带
本地等级、经验进度、库存、怪物图鉴、镜头/缩放和控制句柄。字段是变长的，但
**基线 607 字节的顺序已经完全确定**；下面按 parse 顺序给出。

本文的结论来自三条独立证据：

- **A**：`wave/server/wire/world_projection.cpp` 的参考投影按该顺序写字段，
  且原客户端能正常显示等级、库存、图鉴、镜头与缩放；
- **A**：W3 `success` / `failure` 用例的 `before`/`after` 给出同一份数据的
  语义快照（`level`、`flags`、`progress`、276 项 `inventory`、27 字节
  `gallery`），与 wire 顺序逐项对应；
- **B**：客户端 `$601` 的 profile 分支把每个字段写到固定的 profile 对象偏移，
  访问器 `$2350`（等级）、`$2348`（经验）、`$3750`（图鉴）给出读取点。

> 证据分级按 [09-field-audit.md](09-field-audit.md)：本文写“write-only/无读取者”
> 的地方，除 `unknown[4]` 外都只是**未找到读者（U）**，不是穷举证明；
> `unknown[4]` 的四个立即数偏移在全模块没有 load，可归 W。不要把
> “服务端参考实现只写 0”当成客户端无用的证据。

## 1. 记录外形

```
handle = 8193 (LE32: 01 20 00 00)
flags  = 0xcc
mask   = 0x008000 (LE24: 00 80 00)
body   = 607 字节（flags bit 3 置位时再追加 1 个 vu 经验值）
```

- 资料实体没有世界位置，mask 只置 `0x8000`；不要与 `0x100/0x400/0x200000`
  等叠加。
- `flags` 不是“渲染标志”，而是**资料能力位**：

| 位 | 名称 | 含义 | 证据 |
| ---: | --- | --- | :---: |
| 1 (`0x02`) | profile data valid | 置位时 `$436` 允许合成、`$3750` 读取 27 B 图鉴；与 bit 3 组成已保存账号的基础标志 `10` | A/B |
| 3 (`0x08`) | progression valid | 置位时 `$2350` 返回等级、`$2348` 返回经验；同时决定 body 末尾是否追加经验 vu | A/B |
| 4 (`0x10`) | ready | 本地准备状态；`$2588` 对此位取反并由 `$382` 发送 C→S 7 | A/B |
| 其他 | — | 参考数据中恒为 0；未找到语义 | C |

- 游客资料写 `flags = 0`，body 恰好 607 字节；已保存账号写 `flags = 10`
  （bit 1 + bit 3），body 为 607 字节 + 末尾经验 vu（0 时 1 字节，共 608）。
- 玩家准备时额外 OR `0x10`，取消准备时清除此位；经济和经验能力位保持不变。
- `$140` 构造资料的默认等级是 1；线上 level=0 能解码但不可玩。

## 2. 基线字段顺序（空数组 / 游客）

下表偏移只在“所有数组为空、字符串为空”时成立；数组非空时后续偏移会移动。
**读取必须按序号推进，不能把偏移当固定 ABI。**

| # | wire 偏移 | 类型 | 字段 | 客户端目标 | 语义 / 消费者 | 证据 |
| ---: | ---: | --- | --- | --- | --- | :---: |
| 1 | 0 | u8 | `level` | profile `+8` | 等级；`$2350` 读取，UI 显示 | A |
| 2 | 1 | u8 | `flags` | profile `+9` | 能力位，见上表 | A/B |
| 3 | 2 | 276 × vu | `array0[276]` | profile `+12`，每项 u32（stride 4） | 服务端注释称其为 2022-10-20 前的伪随机合成失败计数；参考实现只写 0；**未找到客户端读取点**（write-only） | B/C |
| 4 | 278 | 4 × vu | `unknown[4]` | profile `+2220..2235`，u32 | 索引整数集合；`$601` 增量读取支持按索引更新；**无任何读取者**，不能命名为 highest wave | B |
| 5 | 282 | NUL 字符串 | `string_a` | profile `+2252` | 本地玩家名/昵称（推断）；`$939` @757421 读取并复制到 UI 字符串；最终标签未定位 | B/C |
| 6 | 283 | f32 | `camera_y` | profile `+2264` | 镜头 Y；`$991` 每帧使用 | A |
| 7 | 287 | 27 B | `gallery[216 bits]` | profile `+2288` | 怪物图鉴：`kind * 6 + rarity`，36 类 × 6 稀有度 = 216 位；`$3750` 读取（无直接 caller，但函数表含 `$3750`，可被间接派发） | A/B |
| 8 | 314 | f32 | `zoom` | profile `+2316` | 缩放；`$991`/`$3384` 使用 | A |
| 9 | 318 | NUL 字符串 | `string_b` | profile `+2320` | 第二字符串；`$939` @678063/678081 复制到全局 `839924` 并在 UI 中使用；参考数据为空。精确标签未定 | B/C |
| 10 | 319 | f32 | `scalar3_target` | profile `+2336` | 第三个平滑标量的目标值（与 zoom `+2316` 同组消费）；`+2340` 是渲染值、`+2352` 是时间戳。服务端恒写 0。**不是镜头坐标** | B |
| 11 | 323 | LE u32 | `control_handle` | profile `+2372` | 本地控制实体句柄；经 `$201` 插入 `+2360` 列表，`$973` 把输入映射到该实体 | A |
| 12 | 327 | f32 | `camera_x` | profile `+2376` | 镜头 X；`$991` 每帧使用 | A |
| 13 | 331 | 276 × vu | `inventory[276]` | profile `+2400`，每项 u32 | 46 种花瓣 × 6 稀有度的数量；全模块未找到从 profile 基址读取该数组的消费者（write-only）；W3 `before.inventory` 是服务端快照，不是客户端 UI 读取证据 | A/B |
| 14 | 607 | vu（可选） | `xp_fraction` | profile `+4608`，u16 | `0..65535` 的当前等级内进度；`$2348` 读取；仅当 flags bit 3 置位时存在 | A/B |

### 2.1 为什么 283 是 Y、327 是 X

- `$991`（每帧更新）把 profile `+2376` 当 X、`+2264` 当 Y、`+2316` 当缩放。
- 空数组时 wire 偏移 327/283/314 正好落到这三个字段；X/Y 与直觉相反，旧实现
  对调后会出现“实体位置正确、镜头漂移”。
- `+2336` 在 `$991` 的相机路径中**不出现**；它只在 `$939` 的 UI/插值路径和
  `$601` 的 getter 中读取，因此不能称为第三个镜头坐标（C 级旧说法不成立）。

## 3. 变长规则

1. `array0[276]`、`unknown[4]`、`inventory[276]` 都是 **固定 276/4 个 vu 元素**，
   不是“先读计数再读元素”；基线全为 0，所以每个元素占 1 字节。
2. `unknown[4]` 在客户端内存中是 4 个 u32（`+2220/+2224/+2228/+2232`）；
   全模块没有任何 `load` 命中这四个偏移，**已证明 write-only**。
3. `gallery` 是**定长 27 字节**，不是 vu 数组；216 位按
   `kind * 6 + rarity` 编号，位序为小端字节内 LSB 优先。
4. `xp_fraction` 是 u16 量化的 `0..65535`；`$2348` 返回
   `u16 / 65535.0`。它只在 flags bit 3 置位时追加，所以“607 字节”是游客
   基线，“608 字节”是带经验的服务端保存账号。
5. 两个字符串都是 NUL 结尾；空字符串仍占 1 字节。
6. 内存布局（对象 4880 B）：`+12` 的 276 × u32 占 1104 B，止于 `+1116`；
   `+1116..+2220` 是另一个 1104 B 的清零洞（**不在线上**）；`+2220` 才是
   4 个 unknown；`+2400` 的 276 × u32 止于 `+3504`；`+3504..+4608` 是第二个
   清零洞；`+4608` 是 u16 经验。不要把 `+12` 数组和 `+2400` 数组之间的空洞
   当成线上字段。

## 4. 消费点

| 字段 | 消费者 | 行为 |
| --- | --- | --- |
| `level` | `$2350`、`$939` | 返回 profile `+8`；UI 显示与解锁槽数 |
| `xp_fraction` | `$2348` | 返回 profile `+4608 / 65535` |
| `gallery` | `$3750` | 复制 profile `+2288` 的 27 B 图鉴位图（函数表间接可达） |
| `camera_x/y` | `$991` | 每帧写相机；X=`+2376`，Y=`+2264` |
| `zoom` | `$991`、`$3384` | 视野缩放；`$3384` 用 `1920/scale`、`1080/scale` 算边界 |
| `control_handle` | `$973`、`$939` | 输入绑定到该句柄；重生后换新句柄，旧输入被拒绝 |
| `array0[276]` | — | 无读取者；write-only |
| `inventory` | — | 无读取者（write-only）；W3 `before.inventory` 是服务端快照 |
| `string_a` | `$939` | 复制到 UI 字符串，与本地昵称比较；最终标签未定位 |
| `string_b` | `$939` | 复制到全局 `839924`；参考数据为空 |
| `scalar3_target` | `$939` | 第三个平滑标量的目标；参考数据恒 0 |

- `$991`（948126–971914）是每帧更新函数，读取资料并写相机。
- `$973`（914325–915130）用控制句柄把输入映射到实体。
- `$2350` / `$2348` / `$3750` 是资料访问器；它们都先检查
  `profile+9 & 8`（flags bit 3），未置位时直接返回而不写输出。

## 5. 与服务端投影的对应

`wave/server/wire/world_projection.cpp` 的 `viewer.profile` 分支：

```text
level                     1 B
flags (saved ? 10 : 0)    1 B
276 × integer(0)          276 B   # array0 (legacy craft counters)
4 × integer(0)            4 B     # unknown
text("")                  1 B     # string_a (local nickname)
real(camera.y)            4 B
27 × gallery byte         27 B
real(1 / vision)          4 B     # zoom
text("")                  1 B     # ui string
real(0)                   4 B     # camera aux
word(controlled)          4 B
real(camera.x)            4 B
276 × integer(count)      276 B   # inventory
if (saved) integer(frac)  1..3 B  # xp fraction
```

空数组、游客时总计 **607 字节**；带经验时 608 字节起。W3 的
`before.flags = 10`、`progress = 10922`、`inventory[276]`、`gallery[27]`
与这张表逐项一致。

## 6. 常见错误

| 现象 | 原因 |
| --- | --- |
| 镜头漂移/地图偏移 | X/Y 对调，或把 `+2336` 当镜头 |
| 移动反向/边界异常 | 缩放或控制句柄错误；或场地 `0x2000` 半径被写成 1 |
| 快捷栏空白 | 装备槽数量/顺序错误，或回充未按 u16/65535 |
| 等级显示 0 | 资料首字节为 0；必须写 1 |
| 资料解析越界 | 用固定 607 偏移读取变长数组；库存/经验非空后偏移移动 |
| 经验条不动 | flags 未置 bit 3，客户端不读取末尾 xp_fraction |
| 合成按钮灰色 | flags 未置 bit 1，`$436` 直接返回 |

## 7. 未决问题（已缩小）

- `unknown[4]`（profile `+2220..2235`）的语义：已证明**无读取者**，但无法从
  原客户端命名；不是 highest wave。
- `string_b`（wire 318 / profile `+2320`）在参考数据中恒为空；`$939` 把它
  复制到全局字符串，但具体 UI 标签未定。
- `scalar3_target`（wire 319 / profile `+2336`）在参考数据中恒为 0；它和
  zoom `+2316` 同组消费，`+2340` 是渲染值、`+2352` 是时间戳；可以安全地写 0。
- `array0[276]`：参考服务端只写 0，客户端未找到读取点；服务端注释称其为旧版
  伪随机合成失败计数，但本构建没有消费者，不能据此推断 UI 行为。
- `inventory[276]`：同样未找到从 profile 基址读取的消费者（write-only）；
  客户端的装备槽/快捷栏来自 S→C 36/12，而不是这个数组。
