# 03 · 服务端 → 客户端（S→C）

服务端到客户端只有四种外层消息（[01-transport.md](01-transport.md) 第 4 节）。
本文件展开类型 1 的**世界更新**与其中的**命令列表**。

## 1. 世界更新包（类型 1）

```
01
vu   epoch
vu   tick
------------------------------------------ 内层掩码从这里开始
vu   ack              客户端应确认到的序号
vu   remove_len       删除段的字节长度；空删除为 2（初始 world 可整段省略）
vu   remove_count
u8   0
LE32 remove_handle × remove_count
u8   0
record × N           见 04-entities.md
00 00 00 00          实体列表终止（零句柄）
u8   0               分隔符
命令列表:
  vu tag
  vu opcode
  fields...
  ...
  00                  结束
```

字段说明：

| 字段 | 编码 | 说明 |
| --- | --- | --- |
| `epoch` | vu | 每次连接为 0；客户端回显 |
| `tick` | vu | 服务端模拟帧号；客户端用类型 2 回 ACK |
| `ack` | vu | 服务端已执行到的客户端序号；客户端据此释放队列 |
| `remove_len` | vu | 删除段总长度，允许客户端整段跳过 |
| `remove_count` | vu | 句柄数量 |
| 删除标志 | u8 | 当前恒 0；保留 |
| 句柄 | LE u32 | 低 13 位槽位、高 19 位代次（见 04） |
| 分隔符 | u8 | 固定 0，`$601` 显式跳过 |
| `tag` | vu | 0 结束；1 无序号；≥2 表示序号 `tag-1` |

- `tick` 之前不掩码；`ack`、删除段、实体、命令全部与 256 字节内层掩码 XOR。
- 初始 world 可以不带删除段，在 `ack` 后直接写 4 字节零句柄；增量快照才带
  `remove_len/count/flag/handles/flag`（A，`bootstrap.cpp`）。
- 删除段使用“长度 + 数量”双前缀，是为了让客户端在重复 tick 时零解析跳过。
- 实体列表的零句柄**不是**命令列表的结束；后面还有一个分隔字节。历史最小更新
  可以在分隔符处直接结束，命令列表为空（A，`w2-bootstrap.md`）。

证据：`$601`（394231–468963）是唯一完整读取该结构的函数；`$3309`
（1503445–1505525）负责类型分派；`wave/server/wire/bootstrap.cpp` 的
`world()/snapshot()` 生成同构字节并与原版互通（A）。

## 2. 命令 envelope

命令列表不是“opcode 数组”，每条命令前有一个 `tag`：

| tag | 含义 | 行为 |
| ---: | --- | --- |
| `0` | 列表结束 | 停止解析 |
| `1` | 无序号 | 立即执行，不参与去重 |
| `n ≥ 2` | 有序号 | `seq = n - 1`；`seq ≤ last_seq` 时**只解析、不执行** |

- 客户端在 `$601` 中读取 `tag`：`tag = 1` 直接分支到“执行”，不参与序号比较；
  `tag >= 2` 才计算 `(tag - 1) <= lastSeq` 并把“重复”标志作为第三个参数传给
  `$988`；`$988` 在执行副作用前检查该标志（B）。
- 这与 C→S 的 `seq` 是两套独立计数：S→C 序号由服务端维护，客户端只做单调过滤。
- 当前服务端投递受击/闪电与经济结果都使用 `tag = 1`（A，
  `garden_projection.cpp`、`economy-wire-20221030.md` 的 35 示例）。

## 3. 命令 opcode 总表

`$988`（928289–938245）在读取 opcode 后做 `br_table (opcode - 11)`，覆盖
11–40。**只有下表 12 个 case 有副作用**；11–40 内其余编号（11–13、15–17、19、
21–22、24–25、27–31、34、38）落到 `$block10`（忽略分支），只读 opcode、不读
字段（B）。**0–10 与 41 及以上会命中 `br_table` 的默认目标 `$block22`**，即
按 opcode 40 读取三个 f32，属于协议错误。

| op | 名称 | 字段（opcode 之后） | 消费点 | 证据 |
| ---: | --- | --- | --- | :---: |
| 14 | 设置访客 ID（`cp6_player_id`） | NUL 字符串 | `$65(34440, str)` | B |
| 18 | 文本消息（未定） | NUL 字符串 | 仅复制到临时串 | C |
| 20 | 进入结算/死亡界面 | — | 置 `898504=1`，`$145()`，`$461(world+22168)` | C |
| 23 | 返回菜单/清理 | — | 清 `world+17965`，`$268()`，`$375()` | C |
| 26 | 击杀/玩家信息 | `vu handle`、NUL 字符串 | 写入临时结构 | C |
| 32 | 受击闪光 | `LE u32 handle`、`u8 strength` | `$51`（27160–27904） | A |
| 33 | 闪电 | `f32 x1`、`f32 y1`、`f32 x2`、`f32 y2` | 粒子/线段 | A |
| 35 | 合成结果 | `u8 success`、`vu created`、`vu returned` | 经济 UI | A |
| 36 | 快捷栏槽位更新 | `LE u32 handle`、`u8 slot (0..15)` | 737568 数组 | B |
| 37 | 小队/玩家资料 | 4 × NUL 字符串、`f64`、NUL 字符串 | 临时结构 | C |
| 39 | 玩家信息（未定） | `vu handle`、NUL 字符串 | 临时结构 | C |
| 40 | 三点特效 | `f32 × 3` | 追加到 `world+22136` 向量 | B |

> 34 在客户端出站是“广告完成”；S→C 的 34 没有处理分支，收到即忽略。

### 14 · 设置访客 ID（`cp6_player_id`）

```
14 <NUL 字符串>
```

- `$988` 调用 `$65(34440, str)`；`$65` 是 C 字符串赋值（`strlen` + 拷贝），
  `34440` 是全局 `cp6_player_id` 缓冲区（B）。
- 静态数据段在 `34440` 处就是 `"cp6_player_id"`；`$2627` 在握手/连接路径把
  该缓冲区拷入请求（`$1+4144`），说明运行时它保存的是**访客 ID 值**。
- 类型 `5` 的访客 ID 也最终落到该缓冲区（A，W2 运行时写回 `cp6_player_id`）；
  静态上 `14` 直接调用 `$65`，类型 `5` 经 `$601/$939` 间接写入（C）。两者是
  首帧下发与会话内更新两条路径。
- 不是“游戏模式”：`"game mode"` 字符串在 `33728`，只被 `$63`/`$1571`
  引用，与本命令无关。

### 18 · 文本消息

```
18 <NUL 字符串>
```

只把字符串复制到栈上临时对象后释放，没有调用任何 UI 函数（B）。在本构建中
**没有可观察副作用**；它不是聊天协议，也不需要另一个状态才显示。

### 20 · 结算/死亡界面

```
20
```

副作用：`*(u8*)898504 = 1`；调用 `$145()`（设置切换）；`$461(world+22168)`
清空该向量（B）。操作名：本地玩家进入结算/死亡状态。

### 23 · 返回菜单

```
23
```

清除 `world+17965` 标志，调用 `$268()`（内部清 OAuth 暂存）、`$375()`（B）。
操作名：会话/对局清理（返回登录或菜单）。

### 26 · 击杀/玩家信息

```
26 <vu handle> <NUL 字符串>
```

读取一个最多 5 字节的 vu 和一个 NUL 字符串，写入 `$3+288..319` 的临时结构
（B）。不调用 UI，临时结构没有下游读者，因此本构建中**无副作用**。

### 32 · 受击闪光（已捕获）

```
32
LE u32  handle
u8      strength   0..255
```

- `$988` 校验句柄代次（`handle >> 13` 与实体代次比较），把
  `clamp((strength/255)^0.2, 0.1, 1)` 追加到通用组件 `0x80000` 的 24 字节事件
  向量（B）。
- `$51` 消费该向量，绘制约 150 ms 的闪白/红色衰减（A）。
- 服务端投影按 `实际伤害 / max_health` 量化到 1..255（A，
  `garden_projection.cpp`）。

### 33 · 闪电（已捕获）

```
33
f32 x1, f32 y1, f32 x2, f32 y2
```

- 四个 LE binary32，世界坐标（已乘显示比例）之间的线段（B）。
- 服务端为每段电弧发送一条，按 socket 游标去重（A，`garden_projection.cpp`）。
- 客户端在 `$988` 中把线段追加到闪电粒子批次；绘制在渲染帧统一提交（B）。

### 35 · 合成结果（已捕获）

```
35
u8  success      0/1
vu  created      新生成物品类型（0 = 无）
vu  returned     返还物品类型（0 = 无）
```

- 读取顺序在 `$988` 中为：`u8 & 1` → `vu` → `vu`（B）。
- `wave/data/wire/20221030/w3-economy.json` 记录了 craft 5 / equip 12 /
  swap 28 → 35 的完整往返（A）。
- `success = 0` 时 `created/returned` 仍可能存在，用于“失败但返还”的展示。

### 36 · 快捷栏槽位

```
36
LE u32 handle
u8     slot     0..15
```

- 校验句柄存在、`slot ≤ 15`，在 `737568 + slot*4` 创建 664 字节 UI 对象（B）。
- 操作：单槽快捷栏更新，与 12 的批量装备不同；它不改库存，只改显示槽。

### 37 · 小队/玩家资料

```
37
string × 4      NUL 结尾
f64             数值（无消费者）
string × 1      NUL 结尾
```

- 字段顺序由 `$988` 的连续读取确定（B）：四个字符串写入
  `+240/+256/+272/+288`，随后 `f64`，再一个字符串。
- 四个字符串写入栈上 `+240/+256/+272/+288` 后没有被读取；本构建中该命令
  **无副作用**（B）。它与实体组件 `0x200` 的“四姓名 + 房间码”同形，但不要
  据此把它当作小队数据的必需路径。

### 39 · 玩家信息

```
39 <vu handle> <NUL 字符串>
```

与 26 同形，但无去重检查、无 UI 调用；临时结构无下游读者，本构建中
**无副作用**（B）。

### 40 · 三点特效

```
40 f32 a, f32 b, f32 c
```

把三个 f32 追加到 `world+22136` 的 16 字节元素向量（`+12 = 1.0f`），容量翻倍
策略与通用 vector 相同（B）。消费端未定位；可能是屏幕震动/颜色/音量参数。

## 4. 客户端忽略的 opcode

`br_table` 的 case 目标只有 11–40。两类值必须区分：

- 11–13、15–17、19、21–22、24–25、27–31、34、38：落到 `$block10`，
  **不解析字段**，直接继续下一条 `tag`；
- 0–10、41 及以上：`opcode - 11` 下溢或超界，命中默认目标 `$block22`
  （opcode 40），按“三个 f32”解析并追加特效；字节不足时可能越界。必须视为
  协议错误。

`$block10` **不读取任何字段**，因此 11–40 内的未知 opcode 只会被跳过，解析
继续到下一个 `tag`。如果发送方为未知 opcode 附带了字段，这些字节会被误读成
`tag`，从而破坏整段命令列表；这是“只发送已实现的 opcode”的硬性原因。0–10 与
41 及以上不是“跳过”，而是误入 case 40，后果更严重。

## 5. 命令与实体组件的分工

| 信息 | 走实体组件 | 走命令 |
| --- | --- | --- |
| 位置、半径、朝向 | `0x400` / `0x1000` | — |
| 生命值 | `0x200000` | — |
| 受击闪光 | `0x80000` 的向量 | `32` 触发 |
| 死亡淡出 | `0x80000` bit 0 | — |
| 花瓣/怪物类型 | `0x10000` / `0x100000` | — |
| 掉落物 | `0x400000` | — |
| 合成结果 | — | `35` |
| 闪电 | — | `33` |
| 快捷栏单槽 | — | `36` |

原则：**持续状态**放实体组件，**一次性事件**放命令。这也解释了为什么
`32/33/35` 没有对应的实体字段。

## 6. 闭合结论

下表把 12 个 case 的**客户端可观察行为**全部给出；没有“未知字段/未知长度”：

| op | 字节 | 客户端行为（本构建） | 结论 |
| ---: | --- | --- | --- |
| 14 | 字符串 | `$65(34440, str)` 写 `cp6_player_id` | 设置访客 ID |
| 18 | 字符串 | 复制到栈上临时串后释放，无 UI 调用 | **无副作用**（可按 no-op 处理） |
| 20 | — | 置 `898504=1`、`$145()`、清空 `world+22168` | 进入结算/死亡状态 |
| 23 | — | 清 `world+17965`、清 OAuth 暂存、`$375()` | 会话/对局清理 |
| 26 | `vu handle`、字符串 | 写入 `$3+288..319` 临时结构，无消费者 | **无副作用** |
| 32 | `LE32 handle`、`u8 strength` | `$51` 受击闪光 + 击退 | 已捕获 |
| 33 | 4 × f32 | 生成闪电线段粒子 | 已捕获 |
| 35 | `u8`、`vu`、`vu` | 经济结果 UI | 已捕获 |
| 36 | `LE32 handle`、`u8 slot` | 更新 `737568+slot*4` 快捷栏槽 | 已实现 |
| 37 | 4 字符串、f64、字符串 | 写入栈上临时结构，无消费者 | **无副作用** |
| 39 | `vu handle`、字符串 | 写入栈上临时结构，无消费者 | **无副作用** |
| 40 | 3 × f32 | 追加到 `world+22136` 向量；该向量只在析构时清零，**无渲染读取** | **无可见效果** |

> 结论级别：18/26/37/39/40 的“无副作用”由“字段读取后无调用、目标地址无其他
> 读者”两部分组成（B）；32/33/35 有 A 级抓包。服务端若需要兼容，只需按上表
> 长度写出，不必赋予额外语义。

## 7. 明文示例

以下为命令列表片段的**解码后**字节（不含外层变换和内层掩码）：

```text
01 20 78 56 34 12 80          # tag=1, op=32, handle=0x12345678, strength=0x80
00                            # 结束

01 21 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00
                              # tag=1, op=33, 4 × f32 = 0

01 23 01 07 00 00             # tag=1, op=35, success=1, created=7, returned=0
00
```

- `32` 的 handle 为 LE u32，strength 为 0..255。
- `33` 的四个 f32 是线段两端的世界坐标（已乘显示比例）。
- `35` 的 `created/returned` 是 `vu`，0 表示无。
- 这些片段用于单元测试的字节级回归；完整帧仍由 `$992`/`$601` 加解密。
