# 03 · 服务端 → 客户端（S→C）

服务端到客户端只有四种外层消息（[01-transport.md](01-transport.md) 第 4 节）。
本文件展开类型 1 的**世界更新**与其中的**命令列表**。

## 1. 世界更新包（类型 1）

```
01
vu   epoch
vu   tick
------------------------------------------ 内层掩码从这里开始
vu   ack              客户端应确认到的序号
vu   remove_len       删除段的字节长度；空删除为 2（初始 world 可整段省略）
vu   remove_count
u8   0
LE32 remove_handle × remove_count
u8   0
record × N           见 04-entities.md
00 00 00 00          实体列表终止（零句柄）
u8   0               分隔符
命令列表:
  vu tag
  vu opcode
  fields...
  ...
  00                  结束
```

字段说明：

| 字段 | 编码 | 说明 |
| --- | --- | --- |
| `epoch` | vu | 新连接从 0 开始；离开对局时递增，客户端回显并重建原生世界 |
| `tick` | vu | 服务端模拟帧号；客户端用类型 2 回 ACK |
| `ack` | vu | 服务端已执行到的客户端序号；客户端据此释放队列 |
| `remove_len` | vu | 删除段总长度，允许客户端整段跳过 |
| `remove_count` | vu | 句柄数量 |
| 删除标志 | u8 | 当前恒 0；保留 |
| 句柄 | LE u32 | 低 13 位槽位、高 19 位代次（见 04） |
| 分隔符 | u8 | 固定 0，`$601` 显式跳过 |
| `tag` | vu | 0 结束；1 无序号；≥2 表示序号 `tag-1` |

- `tick` 之前不掩码；`ack`、删除段、实体、命令全部与 256 字节内层掩码 XOR。
- 初始 world 可以不带删除段，在 `ack` 后直接写 4 字节零句柄；增量快照才带
  `remove_len/count/flag/handles/flag`（A，`bootstrap.cpp`）。
- 删除段使用“长度 + 数量”双前缀，是为了让客户端在重复 tick 时零解析跳过。
- `$3309` 收到更大的 epoch 时先析构旧世界并调用 `$587`，再消费新快照。
  原生可靠请求序号从 1 重新开始；服务端同步重置 ACK、生命绑定和投影，丢弃旧
  epoch 的在途请求，保留 socket 外层密钥状态。装备/制作事务键包含 epoch，
  避免不同世界相同请求序号的幂等键冲突。
- 实体列表的零句柄**不是**命令列表的结束；后面还有一个分隔字节。历史最小更新
  可以在分隔符处直接结束，命令列表为空（A，`w2-bootstrap.md`）。

证据：`$601`（394231–468963）是唯一完整读取该结构的函数；`$3309`
（1503445–1505525）负责类型分派；`wave/server/wire/bootstrap.cpp` 的
`world()/snapshot()` 生成同构字节并与原版互通（A）。

## 2. 命令 envelope

命令列表不是“opcode 数组”，每条命令前有一个 `tag`：

| tag | 含义 | 行为 |
| ---: | --- | --- |
| `0` | 列表结束 | 停止解析 |
| `1` | 无序号 | 立即执行，不参与去重 |
| `n ≥ 2` | 有序号 | `seq = n - 1`；`seq ≤ last_seq` 时**只解析、不执行** |

- 客户端在 `$601` 中读取 `tag`：`tag = 1` 直接分支到“执行”，不参与序号比较；
  `tag >= 2` 才计算 `(tag - 1) <= lastSeq` 并把“重复”标志作为第三个参数传给
  `$988`；`$988` 在执行副作用前检查该标志（B）。
- 这与 C→S 的 `seq` 是两套独立计数：S→C 序号由服务端维护，客户端只做单调过滤。
- 当前服务端投递受击/闪电与经济结果都使用 `tag = 1`（A，
  `garden_projection.cpp`、`economy-wire-20221030.md` 的 35 示例）。

## 3. 命令 opcode 总表

`$988`（928289–938245）在读取 opcode 后做 `br_table (opcode - 11)`，覆盖
11–40。**只有下表 12 个 case 被单独分派**；其中 14/20/23/32/35/36/37 有
客户端副作用，18 解析后丢弃，26/39 条件分支不可达，33 只建 Path2D 不绘制，
40 只写不读。11–40 内其余编号
（11–13、15–17、19、21–22、24–25、27–31、34、38）落到 `$block10`（忽略
分支），只读 opcode、不读字段（B）。**0–10 与 41 及以上会命中 `br_table` 的默认目标 `$block22`**，即
按 opcode 40 读取三个 f32，属于协议错误。

### 14 · 持久化访客 ID

```
14 <NUL 字符串>
```

- `$988` 调用 `$65(34440, str)`。`$65` 不是 RAM `strcpy`：它把 key 哈希后在
  字符串表里查找/创建条目，最终调用 JS 导入 `148573`，即
  `localStorage[key] = value`（B；`client.js` 的 `148573` 明确是
  `window.localStorage[E(a)]=E(b)`）。
- `34440` 是 **localStorage 的 key** `"cp6_player_id"`，不是值缓冲区；
  值由 `14` 写入浏览器存储。`$2627` 在握手/连接路径读取该 key 拼进首包
  （`$1+4144`），所以它跨连接保留（A/B）。
- 类型 `5` 的首帧访客 ID 与 `14` 是两条路径：`5` 是会话内下发，`14` 是
  显式持久化；不要再说“`14` 写 RAM 全局缓冲区”（旧说法已修正）。
- 不是“游戏模式”：`"game mode"` 字符串在 `33728`，只被 `$63`/`$1571`
  引用，与本命令无关。

### 18 · 死字符串（无消费者）

```
18 <NUL 字符串>
```

只把字符串复制到栈上临时对象后释放，没有调用任何 UI 函数（B）。在本构建中
**没有可观察副作用**；它不是聊天协议，也不需要另一个状态才显示。

### 20 · 结算/死亡界面

```
20
```

副作用：若 `898504 == 0`，置 1 并调用 `$145()`（设置切换）；随后调用
`$461(world+22168)`。`$461` 的参数只是用来反推 `world` 基址，函数本身重建
`location.hash`（有本地玩家名则写 `#name`，否则清空），**不会**清
`world+22168`/`world+22172`（B；`client.js` 的 `144628`/`144897`）。
操作名：本地玩家进入结算/死亡状态；`898504` 由 `$991` 读取并清回。

### 23 · 返回菜单

```
23
```

清除 `world+17965` 标志，调用 `$268()`（从 localStorage 重新加载账号资料）、
`$375()`（释放账号单例与头像）、`$453(38912)`（删除
`localStorage["oauth2_data_DO_NOT_SHARE"]`）（B）。
操作名：会话/对局清理（返回登录或菜单）。

### 26 · 请求 id + 字符串（latent，不可达）

```
26 <vu request> <NUL 字符串>
```

- 第一个字段**不是实体句柄**：没有 slot/generation 校验，只与
  `world+22184` 比较（B）。该字只在 `$587` 中被清零，全模块**没有其他写点**；
  所以它不是有效的请求计数器，匹配条件实际上也恒不成立（B）。
- 字符串写入栈上 `+288`，随后有一个完整条件分支：
  `world+22168 == 1` → 置 2、把名字复制到 `world+22172`、清 OAuth 暂存并
  `$fimport$0(144897, 53037)` 清 URL hash（B，WAT 929382–930660）。
- 但 `world+22168` 在全模块只被写成 0（`$587` 初始化）、2（26）和 4（39）；
  **没有任何代码写 1 或 3**。因此 26/39 的条件分支不可达（B）。
- `world+22172` 也没有 `load` 读者（只有 `$452` 释放、26/39 写入）。所以
  本构建中 26 无可观察副作用；它不是击杀信息，也不是玩家名通道。

### 32 · 受击闪光（已捕获）

```
32
LE u32  handle
u8      strength   0..255
```

- `$988` 校验句柄代次（`handle >> 13` 与实体代次比较），把
  `clamp((strength/255)^0.2, 0.1, 1)` 追加到通用组件 `0x80000` 的**本地**
  24 字节事件容器（这不是 0x80000 的 wire 字段）。
- `$51` 消费该向量，绘制约 150 ms 的闪白/红色衰减（A）。
- 服务端投影按 `实际伤害 / max_health` 量化到 1..255（A，
  `garden_projection.cpp`）。

### 33 · 闪电 Path2D（未绘制）

```
33
f32 x1, f32 y1, f32 x2, f32 y2
```

- 四个 LE binary32，逐字段做 bounds/NaN/Inf/denormal 清洗；用 RNG 生成
  `dist/70 + 3` 个抖动中间点，调用 `145586`（new Path2D）、`145767`（moveTo）、
  `145801`（lineTo）（B）。
- 结果存 `world+22124`（size）、`+22128`（cap）、`+22132`（ptr），每条 8 B
  `{1.0f, pathId}`（B）。
- 读者只有 `$452` 析构（`145535` 释放 Path2D）和 `$988` 自己；没有
  `150379`（stroke）调用，也没有渲染函数读取该向量。所以本构建**不会画出
  闪电**（B）。
- 服务端仍可按 4 × f32 发送；客户端会解析并建 Path2D，但没有可见效果。

### 35 · 合成结果（已捕获）

```

u8  success      0/1
vu  created      新生成物品类型（0 = 无）
vu  returned     返还物品类型（0 = 无）
```

- 读取顺序在 `$988` 中为：`u8 & 1` → `vu` → `vu`（B）。
- **门槛**：`if (!*(u8*)(4351576)) br $block25`（WAT 932869）。`4351576` 只在
  C→S 5 的构造器 `$436` @256148 置 1，并由 `$972` 清 0；所以 35 只在“合成
  请求待处理”时被接受，其他时候直接丢弃（B）。
- `wave/data/wire/20221030/w3-economy.json` 记录了 craft 5 / equip 12 /
  swap 28 → 35 的完整往返（A）。
- `success = 0` 时 `created/returned` 仍可能存在，用于“失败但返还”的展示。

### 36 · 快捷栏槽位

```

u8     slot     0..15
```

- 校验句柄存在、`slot ≤ 15`，在 `737568 + slot*4` 创建 664 字节 UI 对象（B）。
- 操作：单槽快捷栏更新，与 12 的批量装备不同；它不改库存，只改显示槽。

### 37 · 账号身份（OAuth2）

```
37
string  provider      # "discord" / "appleid" / "appleid-native" …
string  account_id
string  secret
f64     numeric       # 8 B LE，NaN/Inf/denormal 归零
string  display_name
string  avatar_url
```

- **字段顺序修正**：f64 在第 3 个字符串之后、第 4 个字符串之前；旧文档写成
  “4 字符串 + f64 + 1 字符串”是错的（B，WAT 934074/934814/935139）。
- 写入全局单例 `4029336`：`+0` provider、`+12` account_id、`+24` secret、
  `+36` display_name、`+48` f64、`+56` avatar_url、`+68` URL 副本、`+80` Image id、
  `+96`/`+84` 状态标志（B）。
- 首次 37 调用构造器 `$971`（913544–914087）；之后原地 patch 六个字段
  （936288/936373/936455/936509/936533/936620）。
- 副作用：
  1. `$939` @721218 把 `+36` 设为 UI 文本（账号/玩家名）；
  2. `$988` 把 `provider‖id‖secret‖display_name‖f64‖avatar_url‖hash` 做 base64，
     写入 `localStorage["oauth2_data_DO_NOT_SHARE"]`（936835–937251，`$141`）；
  3. 非空 `avatar_url` 会用 `$fimport$0(153534, 54003, &url)` 创建 JS
     `new Image`，旧图用 `154177` 释放（`client.js` 的 153534 明确是
     `new Image`）；`+80` 保存 image id；
  4. `provider == "appleid"/"appleid-native"` 时触发 Apple 登录 UI
     （722109–722193）。
- C→S 22 只回传 provider/id/secret/f64，不回传 display_name/avatar_url。
  它不是“小队资料”，也不是“无副作用临时结构”。

### 39 · 请求 id + 字符串（latent，不可达）

```
39 <vu request> <NUL 字符串>
```

- 与 26 同形，但要求 `world+22168 == 3`，然后置 4 并写同一个
  `world+22172`（B，WAT 938026–938120）。
- 由于 3 从未被写入、`world+22172` 没有读者，39 同样不可达且无可观察副作用。
  26/39 不是加入流程的两个活阶段；它们是一段未接线的旧版状态机。

### 40 · 三点特效

```
40 f32 a, f32 b, f32 c
```

把三个 f32 追加到 `world+22136` 的 16 字节元素向量（`+12 = 1.0f`），容量翻倍
策略与通用 vector 相同（B）。该向量没有渲染读者，**无可观察效果**。
处理前还会调用 `$79()` 懒初始化选项，并检查 `4351220`
（`florrio_reduce_flashes`）；该标志只影响是否提前退出，不改变“无人绘制”的结论（B）。

## 4. 客户端忽略的 opcode

`br_table` 的 case 目标只有 11–40。两类值必须区分：

- 11–13、15–17、19、21–22、24–25、27–31、34、38：落到 `$block10`，
  **不解析字段**，直接继续下一条 `tag`；
- 0–10、41 及以上：`opcode - 11` 下溢或超界，命中默认目标 `$block22`
  （opcode 40），按“三个 f32”解析并追加特效；字节不足时可能越界。必须视为
  协议错误。

`$block10` **不读取任何字段**，因此 11–40 内的未知 opcode 只会被跳过，解析
继续到下一个 `tag`。如果发送方为未知 opcode 附带了字段，这些字节会被误读成
`tag`，从而破坏整段命令列表；这是“只发送已实现的 opcode”的硬性原因。0–10 与
41 及以上不是“跳过”，而是误入 case 40，后果更严重。

## 5. 命令与实体组件的分工

| 信息 | 走实体组件 | 走命令 |
| --- | --- | --- |
| 位置、半径、朝向 | `0x400` / `0x1000` | — |
| 生命值 | `0x200000` | — |
| 受击闪光 | `0x80000` 的向量 | `32` 触发 |
| 死亡淡出 | `0x80000` bit 0 | — |
| 花瓣/怪物类型 | `0x10000` / `0x100000` | — |
| 掉落物 | `0x400000` | — |
| 合成结果 | — | `35` |
| 闪电 Path2D（无绘制） | — | `33` |
| 快捷栏单槽 | — | `36` |

原则：**持续状态**放实体组件，**一次性事件**放命令。这也解释了为什么
`32/33/35` 没有对应的实体字段。

## 6. 闭合结论

下表把 12 个 case 的**客户端可观察行为**全部给出；没有“未知字段/未知长度”：

| op | 字节 | 客户端行为（本构建） | 结论 |
| ---: | --- | --- | --- |
| 14 | 字符串 | `$65(34440, str)` → `localStorage["cp6_player_id"]` | 持久化访客 ID |
| 18 | 字符串 | 复制到栈上临时串后释放，无 UI 调用 | **无副作用**（可按 no-op 处理） |
| 20 | — | 置 `898504=1`、`$145()`、`$461` 重建 URL hash | 进入结算/死亡状态 |
| 23 | — | 清 `world+17965`、清 OAuth 暂存、`$375()` | 会话/对局清理 |
| 26 | `vu request`、字符串 | 状态 1→2 分支存在，但 1 从未写入；`world+22172` 无读者 | **不可达**（B） |
| 32 | `LE32 handle`、`u8 strength` | `$51` 受击闪光（不改位置，无击退） | 已捕获 |
| 33 | 4 × f32 | 建 Path2D 存入 `world+22124`；无 stroke/无读者 | 无可见效果（B） |
| 35 | `u8`、`vu`、`vu` | 经济结果 UI | 已捕获 |
| 36 | `LE32 handle`、`u8 slot` | 更新 `737568+slot*4` 快捷栏槽 | 已实现 |
| 37 | 3 字符串、f64、2 字符串 | 写账号单例；UI 文本、JS Image、base64→localStorage、C→S 22 | 账号身份 |
| 39 | `vu request`、字符串 | 状态 3→4 分支存在，但 3 从未写入；`world+22172` 无读者 | **不可达**（B） |
| 40 | 3 × f32 | 追加到 `world+22136` 向量；该向量只在析构时清零，**无渲染读取** | **无可见效果** |

> 结论级别：18/26/39/40 的“无副作用/无可见效果”由“字段读取后无调用、目标
> 地址无其他读者”或“条件分支不可达”组成（B）；37 的副作用已逐条给出；
> 32/35 有 A 级抓包。服务端若需要兼容，必须按上表长度写全字段；26/37/39
> 都不能按“无字段”省略。
>
> 客户端侧复核（`tools/protocol/memops.py` 全模块 175,242 条访问）：
> `+22136/+22124` 无任何 load（只有 `$988` 写、析构清零）；`+22168` 只被写
> 0/2/4，从未写 1/3；`+22172` 只有析构 `$452` 的 load。因此 18/26/39/40
> 的结论不依赖“参考服务端不发”。详见 [09-field-audit.md](09-field-audit.md)。

## 7. 明文示例

以下为命令列表片段的**解码后**字节（不含外层变换和内层掩码）：

