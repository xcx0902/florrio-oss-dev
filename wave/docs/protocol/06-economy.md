# 06 · 经济协议（合成 / 装备 / 交换 / 商店）

经济域只有四条 C→S 命令与一条 S→C 结果事件。物品编码统一为：

```
item := vu kind            # 1..45；0 表示空
        if kind != 0: u8 rarity   # 0..5
```

## 1. 合成（C→S 5）

```
opcode 5
u8  all        # 1 = 一键合成全部
vu  keep       # 额外保留数量（Shift/已装备副本）
item            # 输入 tier
```

- 构造 `$436`（256002–256867）；服务端校验 `all ≤ 1`、`kind ≤ 45`、
  `rarity ≤ 5`（A）。
- **Shift 与 Autocraft 都发送 `all = 1`**，没有独立的自动制作 opcode（A）。
- `keep` 包含已装备的同种同稀有度副本；应用层读取已提交装备后，减去实际已装备
  数量，转换成 Store 的“额外保留未装备数量”（A）。
- 五份不足时菜单禁用按钮，**不发送** opcode 5（A）。

真实明文示例（含批次头）：

```text
01 00 | 05 05 00 00 05 00      # seq 5, opcode 5, all=0, keep=0, Rose/Common
01 00 | 06 05 01 00 05 00      # seq 6, opcode 5, all=1, keep=0, Rose/Common
```

## 2. 装备（C→S 12）

```
opcode 12
重复 16 次:
  vu   kind        # 0 = 空槽
  if kind != 0: u8 rarity
```

- 构造 `$939` @843354，字段写入 `$997`（B）；服务端 `case 12` 读取 16 槽（A）。
- 客户端槽位顺序：主槽 `0..n-1`，副槽 `n..2n-1`；`n = 5/6/7/8`，其余槽必须
  为空（A）。Store 内部则是固定 `[0,8)` 主槽、`[8,16)` 副槽，两者不能混用
  （见第 5 节）。
- 解锁等级：W3 为 15/30/45 时 `n = 6/7/8`（A）。
- 制作不改变装备；菜单换装不改变总库存（A）。

## 3. 交换（C→S 28）

```
opcode 28
u8   slot_a
item a
u8   slot_b
item b
```

- 构造 `$463`（275857–276588）；服务端要求 `slot < 16`、两槽不同、
  携带的是**交换前**的物品（A）。
- 客户端在发送前校验旧值；服务端再次校验后原子交换（A）。

真实明文示例：

```text
01 00 | 1a 1c 06 05 01 01 01 00
        seq=26 op=28 slot=6 Rose/Unusual slot=1 Basic/Common
```

## 4. 结果事件（S→C 35）

```
opcode 35
u8  success      # 0/1
vu  created      # 新生成物品；0 = 无
vu  returned     # 返还物品；0 = 无
```

- 读取顺序在 `$988` 中确定（B）。
- 命令 envelope 为 `vu 1`（无序号），结果在存档提交后发出（A，
  `economy-wire-20221030.md`）。
- 失败范围 1–4 对应原版提示；服务端使用独立均匀损耗（A，有范围标注的复刻）。
- 拒绝操作没有可信的原版错误码：队列满时保留请求、不推进 ACK；终止性拒绝走
  断开/重新加载恢复（A）。

## 5. 商店与槽位映射

| 概念 | 客户端 | Store 内部 |
| --- | --- | --- |
| 主槽 | `0..n-1` | 固定 `[0,8)` |
| 副槽 | `n..2n-1` | 固定 `[8,16)` |
| 槽数 `n` | 5/6/7/8 | 等级 1/15/30/45 |

- `$70` 清除索引 `>= 2n`；`$237` 按 `index + n` 取副槽（B）。
- 不能在 level 1 时把 Store 的副槽 8 当作客户端副槽 0（A，W3）。
- 适配层负责两套索引的转换；协议与缓存都以客户端槽位为准。

## 6. 库存与缓存

- 库存是“稀有度优先、kind 次序”的稀疏列表；等级和槽数是 zigzag 正整数（A，
  `economy-wire`）。
- 缓存格式：序列化值 + MurmurHash3 x64_128 的两个 vu64，再 Base64。
  装备 seed `-2107407757`；通用键 seed `19089779` 的 x86_32 作为 x64 seed（A）。
- 公开花朵组件只发送等级、装备和 8 个归一化回充值；库存、图鉴、XP 只在私有
  profile 中（A）。
- 文档 `profile-highest-wave-20221030.md` 记录了“最高波未恢复”的负证据，不能
  把四个未命名整数改称最高波。

## 7. 禁止事项

- 不要为“自动制作”新增 opcode；Shift/Autocraft 都是 `all=1`。
- 不要把 `keep` 当作“保留总数”；它是额外保留量，已装备副本另行扣除。
- 不要用 `created` 非零推断成功；`success` 独立。
- 不要发送 16 个非空槽来“预解锁”；超出等级的槽必须为空。
- 不要在失败时发送伪造的 35；宁可保留请求等待重试。
