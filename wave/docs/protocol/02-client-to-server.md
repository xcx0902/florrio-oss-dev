# 02 · 客户端 → 服务端（C→S）

所有命令都走 [01-transport.md](01-transport.md) 第 5.1 节的可靠批次：

```
01 <epoch vu> <掩码> seq vu, opcode vu, fields... </掩码>
```

`seq` 从 1 开始，每个命令 +1；服务端只接受严格递增。客户端在
`world+22268` 维护下一个序号，`+22272` 为已确认序号，`+22284` 为最高确认
序号；队列元素 16 字节（`seq`、命令对象指针、dirty、释放器）（B，`$992`
971915–973183）。

> 命令对象统一 `call $4 (i32.const 4112)` 分配，`+16` 为 opcode，
> `+4` 为引用计数，`+8` 起为变长字段缓冲（B，`$4` 6039–6059）。
> 入队包装 `$113`（55789–56093）把对象放入拥有者的 vector。

## 1. 身份与握手

### 13 · 身份（agent / token / guest）

```
opcode 13
u8      1
string  agent   （NUL 结尾，≤512 B）
string  token   （NUL 结尾，≤1024 B）
string  guest   （NUL 结尾，≤64 B）
```

- 构造 `$587` 374846；字段读取见 `wave/server/wire/bootstrap.cpp` 的
  `case 13`（A）。
- 抓包：启动批次为 `25, 13, 6` 三条（A，`w2-bootstrap.md`）。
- 语义：把浏览器端登录态交给服务端；`guest` 即 `cp6_player_id`。

### 6 · 不透明客户端信息

```
opcode 6
vu      len
bytes   len
```

- 服务端实现直接跳过这段不透明数据（A，`bootstrap.cpp`）。
- 抓包中位于启动批次最后一条（A）。

### 17 · 四条字符串（未命名）

```
opcode 17
string × 4   （NUL 结尾）
```

- 构造 `$929`：4 个 `std::string` 依次 `$103` 追加（B）。
- 调用点 `$939` @722777、@723903，位于设置/账号相关菜单分支（C）。
- 四段由账号 UI 流程提供；线上只需按 4 × NUL 字符串解析，**不要**按 13 的
  agent/token/guest 复用。

### 3 · 自增请求

```
opcode 3
vu      counter   （每次 +1）
```

- 构造 `$986`：UI 对象的计数器 `+16` 先 +1，再把新值写成 `vu`（B）。
- 调用点 `$991` @952256、`$2240` @1366493，与 27 相邻（C）。
- 操作名：公开匹配/快速加入；计数是请求号，服务端应忽略其数值。

## 2. 大厅与小队

### 27 · 创建小队

```
opcode 27
vu      mode    （客户端首次为 1，之后自增）
```

- 构造 `$985`：与 3 相同的自增计数（B）。
- 既有文档把它记为“opcode 27 + 布尔值创建”，服务端实现按 `u8 0/1` 读取
  （A）。两者在首次发送（值 1）一致；重复创建会发送 ≥2，需要服务端宽松处理。
  这是当前唯一已知的 **B 级布局冲突**，见 [08-traceability.md](08-traceability.md)。

### 4 · 加入小队

```
opcode 4
u8      1
string  room code （NUL 结尾）
```

- 构造 `$984`（926556–926795）：`$978(01 <vu len> <code>)`（B）。
- 服务端读取 `01` + 字符串（A，`bootstrap.cpp`）。
- 真实邀请链接形如 `#wavelocal-<房间码>`（A）。

### 7 · 准备

```
opcode 7
u8      ready
```

- 构造 `$382`：opcode 7，`+17` 存布尔（B）。
- 调用点 `$991` @951866/@951936/@951950、`$2240` @1377616、
  `$2588` @1435018（B）。

### 30 · 昵称

```
opcode 30
string  nickname （NUL 结尾，≤64 B）
```

- 构造 `$939` @843749（B）；服务端 `case 30` 读取字符串（A）。

### 38 · 关闭小队面板 / 离队

```
opcode 38
```

- 构造 `$991` @953112（B）；服务端按 `Leave` 处理（A）。

## 3. 对局操作

### 9 · 移动

```
opcode 9
vu      buttons    bit0 = 左键（攻击），bit1 = 右键（防御）
f32     角度       弧度，0..2π
f32     距离       鼠标距屏幕中心，像素
```

- 构造 `$991` @950361：先写 `vu` buttons，再写两个 f32（B）。
- 服务端 `case 9` 读取 `vu + f32 + f32`，拒绝负距离（A）。
- 角度以弧度存 LE binary32；距离 100 对应 W1 全速是本地复刻参数，不是历史值
  （A，W2）。同时按左右键时防御优先（A）。
- 该命令每帧可发；序号照常 +1，因此高频移动会快速消耗序号。

### 11 · 退出对局

```
opcode 11
```

- 构造 `$987` 928030–928288（B）；服务端 `Leave`（A）。
- UI 返回/关闭按钮触发，调用点 `$939` @693617、`$991` @951772。

### 21 · 死亡界面“继续”

```
opcode 21
```

- 构造 `$939` @681284（B）；服务端 `Leave`（A）。
- 死亡结算第一段 Continue；第二段 GAME OVER 之后会先发 34，再发 7（A，
  `playability.json`）。

### 15 · 调试命令

```
opcode 15
```

- 构造 `$939` @677691，位于 `counter == 3382` 的分支内，分支还调用
  `$fimport$0(148488, 53035)`（B）。正常 UI 不会走到这里。
- 调试分支：只有内部计数等于 3382 时才发送；正常游戏不可达。

## 4. 经济

### 5 · 合成

```
opcode 5
u8      all       1 = 一键合成全部
vu      keep      Shift/保留数量
vu      item      物品类型（1..45）
u8      rarity    0..5
```

- 构造 `$436` 256002–256867（B）；服务端 `case 5` 校验 `all ≤ 1`、
  `keep`、`1 ≤ item ≤ 45`、`rarity ≤ 5`（A）。
- Shift 与 Autocraft 都使用 `all = 1`，没有独立自动制作 opcode（A，
  `economy-wire-20221030.md`）。
- 五份不足时菜单禁用按钮，不发送该命令（A）。

### 12 · 装备 16 槽

```
opcode 12
重复 16 次:
  vu    type      0 = 空槽
  u8    rarity    仅 type != 0 时存在
```

- 构造 `$939` @843354，字段写入 `$997`（B）；服务端 `case 12` 读取 16 槽（A）。
- 前 8 槽为主槽，后 8 槽为副槽（本地映射，A，W3）。
- `type` 上限 45，`rarity` 0..5。

### 28 · 交换两个物品

```
opcode 28
u8      slot_a    0..15
vu      type_a
u8      rarity_a  仅 type_a != 0
u8      slot_b
vu      type_b
u8      rarity_b  仅 type_b != 0
```

- 构造 `$463` 275857–276588：先写 `slot`（`+17`），`$113` 追加
  `(type, rarity)`，再写第二个（B）。
- 服务端 `case 28` 要求两槽不同、`slot < 16`、`type ≤ 45`（A）。
- 抓包示例见 `wave/data/wire/20221030/w3-economy.json` 的 `swap`（A）。

### 34 · 广告完成

```
opcode 34
```

- 构造 `$456` 273132–273625（B）；服务端视为无参可靠请求（A）。
- 触发点 `$939` @678435/@681529/@682876、`$987` @928279（B）。
- 只推进可靠序号，不改变对局状态；死亡结算会先发 34 再发 7（A）。

### 25 · 无参取消

```
opcode 25
```

- 构造 `$587` @373840（B）；服务端按无参请求接受（A）。
- 操作名：启动批次首位的无参取消请求（服务端按 no-op/Leave 处理）。

## 5. 闭合结论

出站命令的**字节布局**已全部确定；下表给出每个曾有疑问的编号的最终结论：

| op | 结论 |
| ---: | --- |
| 0 / 1 | **不可达**：门控字节 `838864`/`838851` 在全模块只被读一次、从未写，恒为 0 |
| 19 / 24 | **不可达**：门控 `838852`/`838854` 同样只读不写 |
| 2 | 无参；在 `$2240` 大厅处理器中与 3/27 相邻，字段布局完整 |
| 8 | 单 `vu`；布局完整（`$939` @874479） |
| 16 | 单 `vu`（`$939` @875368）；字段布局完整 |
| 22 | 单 NUL 字符串（`$587` @374205）；字段布局完整 |
| 17 | 4 个 NUL 字符串；布局完整，语义属 UI 账号绑定，不影响解析 |
| 29 | 1 个 NUL 字符串；由 `$601` 接收路径构造并入队，布局完整 |

“不可达”不是猜测：`grep -c` 对四个门控地址的结果均为 1（仅读），且
`client.js` 中没有这些地址的写入。它们是从未接线的调试/旧版分支。

## 6. 批次字节示例

以下为**解码后**的完整批次（类型 + epoch + 命令），来自真实原版客户端：

```text
01 00 | 05 05 00 00 05 00
        seq=5  op=5  all=0 keep=0 item=5(Rose) rarity=0

01 00 | 06 05 01 00 05 00
        seq=6  op=5  all=1 keep=0 item=5(Rose) rarity=0

01 00 | 1a 1c 06 05 01 01 01 00
        seq=26 op=28 slot=6 Rose/Unusual  slot=1 Basic/Common
```

- 前两例证明 Shift 与普通合成都用 `all=1` 的“全部”路径。
- 第三例的 `1a` 是可靠序号，不是业务 ID；它随此前鼠标移动次数变化。
- 抓包与回归：`wave/data/wire/20221030/w3-economy.json`、
  `wave/tests/native/w3_wire.cpp`（A）。
