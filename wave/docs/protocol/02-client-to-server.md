# 02 · 客户端 → 服务端（C→S）

所有命令都走 [01-transport.md](01-transport.md) 第 5.1 节的可靠批次：

```
01 <epoch vu> <掩码> seq vu, opcode vu, fields... </掩码>
```

`seq` 从 1 开始，每个命令 +1；服务端只接受严格递增。客户端在
`world+22268` 维护下一个序号，`+22272` 为已确认序号，`+22284` 为最高确认
序号；队列元素 16 字节（`seq`、命令对象指针、dirty、释放器）（B，`$992`
971915–973183）。

> 命令对象统一 `call $4 (i32.const 4112)` 分配，`+16` 为 opcode，
> `+4` 为引用计数，`+8` 起为变长字段缓冲（B，`$4` 6039–6059）。
> 入队包装 `$113`（55789–56093）把对象放入拥有者的 vector。

## 1. 启动与环境

### 13 · 客户端环境（UA / referrer / language）

```
opcode 13
u8      1
string  user_agent    （NUL 结尾）
string  referrer      （NUL 结尾）
string  language      （NUL 结尾）
```

- 构造 `$587` 374600–374846：三段分别调用 JS 导入
  `146024/146073/146120`，把返回值缓存到 `837740/837748/837756`，再用 `$87`
  复制成 C 字符串（B）。
- `client.js` 明确映射：`146024 = navigator.userAgent`、
  `146073 = document.referrer`、`146120 = navigator.language`（A/B）。
  所以 13 是**浏览器环境信息**，不是 agent/token/guest，也不是登录凭据。
- 抓包：启动批次为 `25, 13, 6` 三条（A，`w2-bootstrap.md`）。
- guest 标识不在这里：它来自 localStorage 的 `cp6_player_id`（由 S→C 14
  持久化），在 WebSocket 首包 `30 <hash> <account>\0 <guest>\0` 中发送。
  旧文档把 13 写成“身份/agent/token/guest”是错的。

### 6 · 不透明客户端信息

```
opcode 6
vu      len
bytes   len
```

- 服务端实现直接跳过这段不透明数据（A，`bootstrap.cpp`）。
- 抓包中位于启动批次最后一条（A）。

### 17 · 登录/注册（provider + nickname + 两个空串）

```
opcode 17
string  provider    # "discord" 或 "appleid"（7 B）
string  nickname    # 与 opcode 30 共用 UI+81872 缓冲区
string  ""          # 空
string  ""          # 空
```

- 构造 `$929` 639034–639574：签名是 `$929(queue, {ptr,len} × 3)`，第 4 段恒为
  空字面量 134321（B）。
- 调用点 `$939` @722777（Discord）与 @723903（Apple），紧跟在
  `https://florr.io/?oauth2=discord` / `Sign in with Discord` 控件之后；
  字符串常量在 34281（`discord`）与 34432（`appleid`）（B）。
- 第 2 段就是 opcode 30 昵称使用的同一个 UI 缓冲区 `UI+81872`（B）。
- 线上按 4 × NUL 字符串解析；**不要**把它当成 13 的环境字符串复用。

### 3 · Play：快速匹配

```
opcode 3
vu      request   （每个 UI 对象从 1 开始自增）
```

- 构造 `$986` 927413–928029：`obj[0] != 1` 时先清字符串，`obj[16] += 1`，把新值
  写成 `vu`，再入队；随后 `obj[0] = 1`（B）。
- 唯一决定性的调用点 `$991` @952253：
  ```text
  if (l$10) $986(obj) else $985(obj)
  ```
  同一个 Play 按钮按 `4351256`/游戏模式标志选择 **3（快速匹配）** 或
  **27（创建小队）**（B）。
- `request` 是请求号，不是房间号/模式；服务端应接受任意值并忽略其数值。

## 1.1 菜单 / 实体点击 / 凭据

### 2 · 实体点击

```
opcode 2
u8      flag    # !entity[72]
```

- 构造 `$2240` 1362788–1362814：`cmd+4 = 2`（负载长度 1），`cmd+17 = !(entity+72)`，
  `cmd+16 = 2`，并把 `world+22276` 的本地请求 id 写到 `cmd+0`（B）。
- 触发条件：`world+22176 == 5`（对局中）且鼠标命中一个可见实体
  （`$3(entity+24, …)`，并检查 `entity+52/+60`）（B）。
- 这是**实体点击/交互**，不是无参大厅请求；`flag` 的确切语义（玩家/花瓣）未定，
  但线上必须保留这 1 字节。

### 8 / 16 · 两条菜单行请求

```
opcode 8   /   opcode 16
vu      row_id      # 232 B UI 行对象的 +12 字段
```

- 8：`$939` @874479，行对象 `$13+232`，读 `+244`（B）。
- 16：`$939` @875368，行对象 `$13+464`，读 `+476`（B）。
- 两条都只在 hover/press 状态匹配 `835584` 时入队；`row_id` 是行枚举，不是
  请求计数器。具体标签未映射（C）。

### 22 · 凭据回传

```
opcode 22
s1 \0  s2 \0  s3 \0  f64(8 B LE)  \0
```

- 构造 `$587` 373900–374205：依次复制身份单例的 `+0/+12/+24` 三个字符串，
  再追加 `+48` 的 8 字节 f64，最后补 NUL；`cmd+4 = 1`（B）。
- 它发送的是 S→C 37 下发的同一组凭据（provider / id / secret / 数值），
  **不是**任意单字符串。负载含内嵌 NUL（三个字符串的分隔符和 f64 的零字节），
  服务端不能按一个 `read_string` 读到第一个 NUL 就结束；必须按
  “3 × NUL 字符串 + 8 原始字节 + 末尾 NUL”解析（B）。

### 25 · 启动占位

```
opcode 25
```

- `$587` 373820–373900：账号单例（S→C 37）未就绪（`4029440 == 0`）时发送，`cmd+4 = 1`
  （B）。启动批次 `25, 13, 6` 的第一条（A）。
- 无参；服务端可忽略。

### 29 · 名称公告 `"admin"`

```
opcode 29
string  "admin"
```

- `$601` 468174–468260：`world+17968` 为 0 时，把静态字符串 29402（`"admin"`）
  复制进命令，置 `world+17968 = 1` 后入队；每个 world 只发一次（B）。
- 数据段 29390 附近是 `…Dandelion\0Mon\0admin\0Admin\0emscripten…`；
  同一常量也用于 `$939` @777233 的退出路径（B）。
- 不是聊天，也不是用户输入；是客户端的 fallback 名称公告。

## 2. 大厅与小队

### 27 · Play：创建小队

```
opcode 27
vu      request   （每个 UI 对象从 1 开始自增）
```

- 构造 `$985` 926796–927412：与 3 相同的 `obj[16] += 1` 请求号（B）。
- 与 3 是**同一个按钮的两条分支**，不是“布尔创建”与“模式”两个字段。此前
  “27 是 vu 还是 bool”的冲突到此关闭：线上始终是 `vu`；首次值通常为 1，
  但服务端必须按请求号接受任意值（B）。
- 服务端若只读 `u8 0/1`，第一次创建仍能工作；重复点击会发送 2、3……，
  必须按 `vu` 读取，否则会把后续字节误当命令。

### 4 · 加入小队

- 构造 `$984`（926556–926795）：`$978(01 <vu len> <code>)`（B）。
- 服务端读取 `01` + 字符串（A，`bootstrap.cpp`）。
- 真实邀请链接形如 `#wavelocal-<房间码>`（A）。

## 3. 对局操作

### 9 · 移动

```
opcode 9
vu      buttons    bit0 = 左键（攻击），bit1 = 右键（防御）
f32     角度       弧度，0..2π
f32     距离       鼠标距屏幕中心，像素
```

- 构造 `$991` @950361：先写 `vu` buttons，再写两个 f32（B）。
- 服务端 `case 9` 读取 `vu + f32 + f32`，拒绝负距离（A）。
- 角度以弧度存 LE binary32；距离 100 对应 W1 全速是本地复刻参数，不是历史值
  （A，W2）。同时按左右键时防御优先（A）。
- 该命令每帧可发；序号照常 +1，因此高频移动会快速消耗序号。

### 11 · 退出对局

```
opcode 11
```

- 构造 `$987` 928030–928288（B）；服务端 `Leave`（A）。
- UI 返回/关闭按钮触发，调用点 `$939` @693617、`$991` @951772。

### 21 · 死亡界面“继续”

```
opcode 21

- 构造 `$939` @681284（B）；服务端 `Leave`（A）。
- 死亡结算第一段 Continue；第二段 GAME OVER 之后会先发 34，再发 7（A，

### 15 · 调试命令

## 4. 经济

### 5 · 合成

```
opcode 5
u8      all       1 = 一键合成全部
vu      keep      Shift/保留数量
vu      item      物品类型（1..45）
u8      rarity    0..5
```

- 构造 `$436` 256002–256867（B）；服务端 `case 5` 校验 `all ≤ 1`、
  `keep`、`1 ≤ item ≤ 45`、`rarity ≤ 5`（A）。
- Shift 与 Autocraft 都使用 `all = 1`，没有独立自动制作 opcode（A，
  `economy-wire-20221030.md`）。
- 五份不足时菜单禁用按钮，不发送该命令（A）。

### 12 · 装备 16 槽

```
opcode 12
重复 16 次:
  vu    type      0 = 空槽
  u8    rarity    仅 type != 0 时存在
```

- 构造 `$939` @843354，字段写入 `$997`（B）；服务端 `case 12` 读取 16 槽（A）。
- 前 8 槽为主槽，后 8 槽为副槽（本地映射，A，W3）。
- `type` 上限 45，`rarity` 0..5。

### 28 · 交换两个物品

```
opcode 28
u8      slot_a    0..15
vu      type_a
u8      rarity_a  仅 type_a != 0
u8      slot_b
vu      type_b
u8      rarity_b  仅 type_b != 0
```

- 构造 `$463` 275857–276588：先写 `slot`（`+17`），`$113` 追加
  `(type, rarity)`，再写第二个（B）。
- 服务端 `case 28` 要求两槽不同、`slot < 16`、`type ≤ 45`（A）。
- 抓包示例见 `wave/data/wire/20221030/w3-economy.json` 的 `swap`（A）。

### 34 · 广告完成

```
opcode 34

- 构造 `$456` 273132–273625（B）；服务端视为无参可靠请求（A）。

## 5. 闭合结论

出站命令的**字节布局**已全部确定；下表给出每个曾有疑问的编号的最终结论：

| op | 结论 |
| ---: | --- |
| 0 / 1 | **不可达**：门控字节 `838864`/`838851` 在全模块只被读一次、从未写，恒为 0 |
| 19 / 24 | **不可达**：门控 `838852`/`838854` 同样只读不写 |
| 2 | 1 字节 `!entity+72`；实体点击，不是无参大厅请求 |
| 13 | `u8 1` + userAgent/referrer/language；浏览器环境，不是身份凭据 |
| 8 / 16 | 各 1 个 `vu` 行枚举；两条不同菜单按钮 |
| 22 | 含内嵌 NUL 的凭据 blob：`s1\0 s2\0 s3\0 f64(8B) \0` |
| 17 | 4 个 NUL 字符串：`provider`、`nickname`、空、空 |
| 25 | 无参启动占位；不是取消/Leave |
| 29 | 常量 `"admin"`，每 world 一次；不是聊天 |
| 3 / 27 | 同一个 Play 按钮的两条分支，均带自增 `vu` 请求号；`27` 不是 bool |

“不可达”不是猜测：`grep -c` 对四个门控地址的结果均为 1（仅读），且
`client.js` 中没有这些地址的写入。它们是从未接线的调试/旧版分支。

## 6. 批次字节示例

以下为**解码后**的完整批次（类型 + epoch + 命令），来自真实原版客户端：

```text
01 00 | 05 05 00 00 05 00
        seq=5  op=5  all=0 keep=0 item=5(Rose) rarity=0

01 00 | 06 05 01 00 05 00
        seq=6  op=5  all=1 keep=0 item=5(Rose) rarity=0

01 00 | 1a 1c 06 05 01 01 01 00
        seq=26 op=28 slot=6 Rose/Unusual  slot=1 Basic/Common
```

- 前两例证明 Shift 与普通合成都用 `all=1` 的“全部”路径。
- 第三例的 `1a` 是可靠序号，不是业务 ID；它随此前鼠标移动次数变化。
- 抓包与回归：`wave/data/wire/20221030/w3-economy.json`、
  `wave/tests/native/w3_wire.cpp`（A）。
