# 07 · 登录、大厅与小队

本文把“从握手到进入对局、死亡与重连”的状态流程串起来，命令的字节定义见
[02](02-client-to-server.md) 与 [03](03-server-to-client.md)。

## 1. 启动顺序

```
1. GET  api.n.m28.io/.../findEach/       → 选择服务器 id
2. WS   wss://<id>.s.m28n.net/
3. send 30 <build> <account>\0 <guest>\0
4. C→S  25 + 13 (UA/referrer/language) + 6 (不透明信息)   ← 启动批次
5. recv 05 <epoch> <visitor id>          → 写回 cp6_player_id
6. recv 01 world                         → 首帧含资料实体 8193
7. recv 房间/小队状态（0x200 组件）
8. C→S  7 ready=1
9. 进入 Garden
```

- 启动批次固定为 `25, 13, 6`（A，`w2-bootstrap.md`）；它与 05/01 的精确
  交错顺序以逐帧抓包为准，图中按“先发批次、后收首帧”排列。
- 首帧资料必须是等级 1 的 607 字节；全零会停在加载画面（A）。
- 连续三张更新后原版才开始消费并显示 Ready/Garden/Squad（A，W2）。

## 2. 身份与环境

| 命令 | 字段 | 说明 |
| --- | --- | --- |
| 13 | `01` + user_agent + referrer + language | 浏览器环境信息；`146024/146073/146120` 分别是 `navigator.userAgent`、`document.referrer`、`navigator.language` |
| 6 | `vu len` + bytes | 不透明客户端信息，服务端跳过 |
| 17 | provider、nickname、空、空 | 登录/注册；provider 为 `discord`/`appleid` |

- guest 标识来自 localStorage 的 `cp6_player_id`（S→C 14 持久化），在首包
  `30 <hash> <account>\0 <guest>\0` 中发送；13 不携带它（A/B）。
- 每次新 socket 重置外层变换和可靠序号，但 `cp6_player_id` 会恢复同一访客
  身份（A）。
- 服务端不得把 guest 字符串当作可信用户；它只是会话提示（A，W2 安全边界）。

## 3. 小队

### 创建和查找（C→S 27 / 3）

```
27 <vu request>  # New
3  <vu request>  # Find Public
```

- New 创建私有小队。Find Public 加入同场景的首个有空位、尚未开局的公开小队。
  若没有可加入的房间，新建一个公开小队；新房码让原版界面退出 Creating 状态。
- 本地宿主每队最多两人。`request` 是每个 UI 对象从 1 开始的自增请求号，
  服务端按 `vu` 读取并忽略其值。

### 切换公开状态（C→S 2）

```
2 <u8 public>
```

- 原版小队面板的 Public 复选框发送新状态：1 为公开，0 为私有。
- 私有小队可通过邀请链接加入；仅公开的等待中小队可被 Find Public 找到。

### 加入（C→S 4）

```
04 01 <room code>\0
```

- 邀请链接 `#wavelocal-<code>`；真实双端已验证（A）。
- 房间码为空或过长（>32）应拒绝（实现建议，非原版字节级证据）。

### 准备（C→S 7）

```
07 <u8 ready>
```

- 服务端把 `ready` 映射为席位状态；房间内全员准备后开局（A，W2）。
- 准备中的成员在面板显示绿色 Ready。再次点击自己的准备按钮会取消准备；
  按钮读取本地资料组件 `0x8000` 第二字节的 bit 4。
- `$991` 收到存活花朵后会自动发 `Ready(false)`；服务端确认并清除准备位，
  保留当前对局，结束 `$382` 的准备状态重试。

### 昵称（C→S 30）

```
30 <NUL nickname>
```

- 客户端 UI 限制 64 B；空串合法（显示默认名）（实现限制）。
- 客户端在菜单中即时更新本地显示，不等服务端回包（A）。

### 离开（C→S 38 / 11）

- `38`：关闭小队面板/离队；`11`：退出对局。两者服务端都按 `Leave` 处理（A）。
- 离开后房间席位释放。主动离场排入 `Departure`，下一模拟步清理花朵、花瓣和该生命所属实体，
  从旧对局移除该玩家；临时断线仍使用可重连的 `Connection(false)`。留队者继续原 arena，
  最后一名成员离场后删除房间。
- 离开已有对局时递增该连接的 world epoch，重新发送全量大厅状态。`$987` 设置
  原生退出标记 `4350150`；只删实体不会清除它，必须由 `$3309` 的新 epoch
  路径调用 `$587` 重置，否则再次 Ready 会出现服务端开局、客户端仍停菜单。
  同一连接上的新世界启动身份请求复用原成员；旧 epoch 的 ACK/命令被忽略。

### 小队组件（`0x200`）

组件挂在专用小队实体 8194 上，字节顺序见 [04 · 小队 roster](04-entities.md#0x200--小队-roster)。
名字后的首个字节反映小队公开状态；最后四个席位标志各自描述对应成员是否存在、是否准备。
装备预览每槽依次发送四个成员的花瓣类型和稀有度，空槽填 0。

## 4. 对局生命周期

```
Ready → Garden → 死亡 → Continue(21) → 等待复活 → Garden
全队结束 → Continue(21) → GAME OVER → Continue / 广告完成(34) → 菜单 → Ready(7)
```

| 阶段 | 信号 | 客户端行为 |
| --- | --- | --- |
| 进入 | 世界更新 + 资料 | 相机绑定控制句柄 |
| 受击 | S→C 32 | 150 ms 闪光 |
| 死亡 | `0x200000` health=0 + `0x80000` bit0 | 150 ms 膨胀淡出 |
| 等待复活 | 场地存在，`0x10` 末字节 bit 1 = 0 | 点击 Continue 后显示 You will respawn next wave |
| 继续 | C→S 21 | 对局进行中保留队员；结束后离场并显示 GAME OVER |
| 广告 | C→S 34 | 仅推进可靠序号 |
| 回菜单 | C→S 7 或 38 | 重新准备/离队 |

- 死亡第一段 Continue 发 21；仍有队友存活时继续留队，下一波或 Yggdrasil 可复活。
  GAME OVER 后先发 34，再发 7（A，`playability.json`）。
- 旧实现把合法请求当未知命令，返回 `00 00` 会触发整页重载（A）。

## 5. 重连与替换

- 新连接使用全新外层状态、全新可靠序号、全新投影；不能复用旧 socket 的密钥。
- 同访客第二次连接会替换旧连接；旧 socket 立即失去输入、发布和断开新连接的
  权限（A，W2）。
- 等待中的队员断线后立即释放席位、清除准备状态；其他玩家可继续留在小队。
  已开局的队员保留对局身份，可用原访客凭证重连。
- 重生使用新句柄/代次；旧生命 ID 的输入被拒绝，过期 ACK 不回退生命（A）。
- 重连时客户端先收到全量可见实体，再收到命令；不会回放连接前的受击事件（A）。
- 原版启动批次会重发装备缓存（12），此时还没有当前生命的 ACK。已开局时，
  与已保存装备完全一致的缓存仅作同步并正常确认，不提交装备事务；实际修改仍须有效的
  存活生命 ACK。W3 双人回归覆盖 Ready 后及对局中双方多次刷新，保留原对局和生命。
- W3 额外覆盖四种 Basic/混合装备的单人、双人场景，各连续 12 轮
  Ready → Abandon → Ready，全程不刷新、不重连；验证原生退出标记、实际移动、
  攻击及再次 Abandon。换装回归覆盖离场后的装备保存和再次开局后的键盘换槽。

## 7. 大厅边界

| 场景 | 本地宿主行为 |
| --- | --- |
| 房间不存在、已满、已开局或场景不同 | 拒绝加入；保留当前小队和连接 |
| 重复 Ready | 幂等；不重复开局 |
| 对局中离开 | 释放席位；其他玩家收到删除记录 |
| 等待中断线 | 释放席位；可凭有效邀请再次加入 |
| 对局中断线 | 保留对局身份；同一访客可重连 |

无法加入的请求仍会推进可靠序号。无效协议帧使用外层类型 `0` 的关闭码（见 01 第 4 节）。
