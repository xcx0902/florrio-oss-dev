# 04 · 实体记录与组件

世界更新包中的实体列表是每个 tick 的可见实体快照：每个可见实体一条记录，
客户端按掩码增量覆盖本地实体池。本文给出记录外壳、句柄编码和每个组件位的
字段顺序。

## 1. 记录外壳

```
LE u32  handle
u8      flags        线上值 = 逻辑值 XOR 0xac
LE24    mask         组件掩码，低位在前
fields...            按 mask 的位从低到高依次排列
```

| flags（线上） | 逻辑值 | 含义 |
| ---: | ---: | --- |
| `0xcc` | `0x60` | 普通实体 |
| `0xc4` | `0x68` | 装备扩展（花朵，含 16 槽与 8 回充） |
| `0xce` | `0x62` | 普通 + 新到达（bit 1） |
| `0xc6` | `0x6a` | 装备扩展 + 新到达 |

- 客户端读取时先 XOR `0xac`，再判断**逻辑值**的 bit 3（装备扩展）与 bit 1
  （新到达）（A/B，`$601` 397900–397930；服务端 `record()` 写
  `(equipment ? 0xc4 : 0xcc) | (arriving ? 2 : 0)`）。
- 注意方向：线上 `0xcc` 是普通、`0xc4` 是花朵；不要把表中的“线上/逻辑”两列
  再对调一次。旧版本曾把 `0x60/0x68` 写成线上值，导致花朵被当成普通实体。
- “新到达”只影响首次插值：客户端会把首帧位置直接设为目标位置；服务端用它标记
  新掉落物，避免从旧缓存位置飞入（A，`garden_projection.cpp`）。

## 2. 句柄编码

```
handle = generation * 8192 + slot
slot   = handle & 0x1FFF          （13 位，0..8191）
gen    = handle >> 13             （19 位）
```

- 实体池：`world + 22848 + slot * 376`；实体对象 `+28` 存完整句柄（B，
  `wave/docs/client-20221030.md`）。
- 保留槽位：`1..5` 分别用于本地资料、玩家列表/小队、世界统计、场地、波次；
  普通实体从槽位 16 开始（A，W2）。
- 句柄复用必须递增代次；客户端用代次拒绝旧句柄的受击/掉落事件（A，W2）。
- `0` 句柄仅用于列表终止，不能作为实体。

## 3. 组件掩码

掩码是 24 位小端；客户端按位升序读取，缺位即跳过。下表“字段”列是**该位存在时**
的字节顺序；“消费者”列给出使用该字段的函数。

| 掩码 | 字段（wire 顺序） | 语义 | 消费者 | 证据 |
| ---: | --- | --- | --- | :---: |
| `0x1` | `u8 flags` | 基础标志；固定 1 字节，写入 transform 对象 `+8`，本构建无读取者（write-only） | `$601` | B |
| `0x2` | `u8`、NUL 字符串 | world 级内部元数据；参考服务端从不发送 | 无 | C |
| `0x4` | 2 × `LE32` 句柄 | 实体内部句柄集合；参考服务端从不发送 | 无 | C |
| `0x8` | 10 × `vu`、10 × `vu`、`u8` | world 级统计表（两排 10 个整数 + 1 字节）；无 UI 读取者，不是“花数” | 无 | B/C |
| `0x10` | `vu w`、`vu h`、`f32`、`u8` | 场景宽高/元数据 | `$601` 读取 | B |
| `0x20` | 4 × `u8`；flags bit3 时 + 16 × (`vu type`,`u8 rarity`) + 8 × `vu` | 花朵状态、装备槽、回充 | `$126`/`$998` | A |
| `0x40` | — | 空标记 | — | B |
| `0x80` | `LE u32 predecessor` | Leech 链的前驱句柄（连续绘制） | `$1795` | B |
| `0x100` | NUL 字符串 | 昵称 | UI 名称 | A |
| `0x200` | 4 × NUL 名、4 个 ready bit、4 × NUL 字符串、4 × `LE32` 句柄、4 × `LE32`、64 × `vu16`、`f32`、4 × `u8` | 小队 roster；服务端的 21 B/84 B 只是近似零填充（见 §4） | 小队面板 | B/C |
| `0x400` | `u16 heading`、`f32 x`、`f32 y` | 位置与朝向（65536 = 整圈） | `$973`/`$41` | A |
| `0x800` | `u8 first`、`vu wave`、`vu biome`、216 × `vu`、`u8 last` | 波次/怪物目录 | `$828`、`$259/$299/$531` | A |
| `0x1000` | `f32 radius` | 碰撞/绘制半径 | `$460` | A |
| `0x2000` | `f32 arena_radius`、`u8 r`、`u8 g`、`u8 b` | 圆形场地与底色 | `$991`、`$973` | A |
| `0x4000` | `u8 palette` | 分裂粒子（Grapes=1） | `$597` | A |
| `0x8000` | 变长（最小 607 B） | 本地资料，见 05 | `$140`、`$991` | A |
| `0x10000` | `vu type`、非零时 `u8 rarity` | 花瓣 | `$597` | A |
| `0x20000` | `u8` | 保留位；写入 `component+8`，无读取者（write-only） | — | B/C |
| `0x40000` | `u8` | 保留位；写入 `component+8`，无读取者（write-only） | — | B/C |
| `0x80000` | `u8 render_flags`、事件向量 | 死亡淡出 bit 0；受击事件 | `$597`、`$51` | A |
| `0x100000` | `u8 mob_type`、`u8 ally`、`u8 rarity` | 怪物 | `$597` | A |
| `0x200000` | `u8`、`u8`、`u8 health` | 花朵生命（第三字节 0..255） | `$939`/`$954` | A |
| `0x400000` | `u8 collected`、`vu target`、`vu item`（`$55` 打包读取，非零时跟 `u8 rarity`） | 地面掉落 | 掉落渲染 | A |
| `0x800000` | 300 × `f64`、300 × NUL 字符串、`vu`、`f32`… | 未文档化的 300 项高分/排行榜表；参考服务端从不发送 | 未知 | C |

### 字段顺序示例

一个非花朵实体（掩码 `0x1|0x400|0x1000|0x80000`）的 body：

```
00                    # 0x1
00 00                 # 0x400 heading = 0
<x f32> <y f32>       # 0x400
<radius f32>          # 0x1000
<generic flags u8>    # 0x80000
```

花朵还会在 `0x1` 之后插入 `0x20`（4 字节 + 16 槽 + 8 回充）和 `0x100`
（昵称），顺序仍按掩码升序；不能把上面的偏移直接套到花朵上。

字段不是“按组件块”排列，而是**所有置位组件的字段按掩码升序拼接**。因此不能用
固定偏移读取整个实体；必须逐位解析。

## 4. 关键组件的细节

### 0x1 · 基础字节

```
u8 flags
```

- 固定 1 字节，写入 transform 对象 `+8`（`$589` 分配，`$601` 398505 读取）。
- 本构建中没有任何渲染/逻辑函数读取该字节；它的实际作用是**标记 transform
  对象存在**，字节值目前是 write-only。参考服务端恒写 0（B）。

### 0x8 · world 统计表

```
10 × vu     # world+124..160
10 × vu     # world+208..244
u8          # world+288
```

- 世界级组件，不是普通实体字段；`$269` 分配，`$601` 读取 21 个值（B）。
- 21 个值都没有 UI/渲染读取者；参考服务端只发 `count + 61 个 0`，所以客户端
  看到的是第一排第 0 项 = 玩家数，其余全 0。它不是“花数”（B/C）。

### 0x2 / 0x4 / 0x40 / 0x800000

- `0x2`：`u8` + NUL 字符串，写 world `+60/+64`；无消费者，参考服务端不发（C）。
- `0x4`：2 × `LE32` 句柄，插入实体 `+144` 的 set；无消费者，参考服务端不发（C）。
- `0x40`：**空载荷**；`$974` 只分配 12 B 节点并挂到 world+624，`$601` 不读取
  任何字节，也没有消费者。是纯 presence/spacer 位（B）。
- `0x800000`：300 × `f64` + 300 × NUL 字符串 + `vu` + `f32`…，world+3088/
  +6688；形似 300 项高分表，参考服务端从不发送，客户端消费点未确认（C）。
  这是本文新记录的一个未文档化大组件，不能按“保留位”忽略其长度。

### 0x20 · 花朵状态与装备

```
u8 a, u8 b, u8 level, u8 d
if (记录 flags 的 bit 3 / 0xc4 置位):
  16 × (vu type, if type != 0: u8 rarity)
  8 × vu reload        # 0..65535，0 = 破碎，65535 = 就绪
```

- 前 8 槽为主槽，后 8 槽为副槽（本地映射，W3 使用 6/7/8 槽解锁）。
- `reload` 是**归一化比例**，不是毫秒：客户端 `$126/$998` 做 u16/65535 后
  插值绘制扇形（A）。
- 等级/槽数判定使用第三字节；默认等级 1（`$140`）。
- 16 槽与 8 回充是否存在的开关是**记录外壳的 flags bit 3**（`0xc4`），不是
  组件内的某个 bit；花朵记录必须置该位，否则客户端会把槽位字节误读成昵称。

### 0x200 · 小队 roster

客户端 `$601` / `$182` 的实际读取顺序（B）：

```
4 × NUL 字符串       # 成员名 → roster +8/+20/+32/+44
4 个 ready bit       # 位打包，写入 roster +72
4 × NUL 字符串       # → +76/+88/+100/+112（成员标签/宠物名）
4 × LE32 句柄        # 分别插入 +140/+152/+164/+176 的四个 set
4 × LE32             # → +216/+220/+224/+228
64 × vu16            # → +248..+374（4 成员 × 16 装备槽）
f32                  # → +632
4 × u8               # → +636..+639
```

- 房间码是**单个** NUL 字符串，写入 roster `+204`；它不在上述 4 字符串组里。
- ready 状态是**1 字节里的 4 个位**；服务端发 4 个独立字节时，只有第一字节的
  bit0..bit3 被消费，后 3 字节是死字节（B/C）。
- `+204` 之后的 488 字节是对象构造时的清零区，不是线上“84 B 默认块”。
- 服务端 `garden_projection.cpp` 目前发的是“4 名 + 21 个 0 + 房间码 + 84 个 0 +
  4 字节”。它只能保证 4 个名字和 ready 位落在客户端前 17 字节内；按客户端的字段顺序，
  房间码不会落在 `+204` 的字符串字段，而会落进后面的整数区。参考服务端的房间码
  实际由 URL hash 提供，而不是 0x200；这一点需动态抓包再确认（B/C）。
- 旧文档的“21 B 默认 + 房间码 + 84 B 默认 + 4 × 席位标志”是服务端投影的
  字节外形，不是客户端的字段 schema；不要再按它推断准备状态或库存。

### 0x800 · 波次与目录

```
u8   first     # 红色清场条（0..255）
vu   wave      # W1.number - 1
vu   biome
216 × vu       # 目录计数，index = type * 6 + rarity
u8   last      # 蓝色刷怪条（0..255）
```

- 36 类型 × 6 稀有度 = 216 项（A）。
- `first/last` 位于 world `+820/+2560`，由 `$828` 绘制两条归一化进度（A）。
- 顺序：蓝条先推进（刷怪），红条在刷怪结束后推进（清场）（A，用户确认）。

### 0x2000 · 场地

```
f32 radius     # 圆形场地半径
u8 r, g, b     # 背景色
```

- 只发给场地实体（句柄 8196），**不要**给每个实体发（A）。
- 半径参与本地控制约束；颜色全屏填充（A）。

### 0x80000 · 通用渲染与受击

```
u8 flags       # bit 0 = 死亡膨胀/淡出
事件向量        # 由 32 命令追加，24 B/条
```

- `$597` 从首次绘制计时 150 ms：alpha 1→0，比例 1→2（A）。
- `$51` 消费受击事件，绘制约 150 ms 闪白/红（A）。

### 0x400000 · 掉落物

```
u8  collected    # 1 = 被拾取，播放缩小旋转
vu  target       # 飞向的实体句柄，0 = 原地
vu  item         # 物品类型
u8  rarity
```

- 与 `0x400/0x1000/0x80000/0x1` 组合使用；服务端投影的 mask 为
  `1 | 0x400 | 0x1000 | 0x80000 | 0x400000`（A）。

## 5. 删除与保留

- 删除段在实体列表之前，按句柄删除；删除后的槽位在淡出保留期内不能复用。
- 服务端对“已见实体”保留 400 ms 的死亡记录：设置 `0x80000` bit 0 后再真正
  删除（A）。
- 客户端不补造未见实体的死亡动画（A）。
- 重生使用新句柄/新代次，不复用旧控制对象（A）。

## 6. 解析伪代码

```python
def read_entity(buf, p):
    handle = le32(buf, p); p += 4
    if handle == 0: return None, p
    flags = buf[p] ^ 0xac; p += 1
    mask = buf[p] | buf[p+1]<<8 | buf[p+2]<<16; p += 3
    body = {}
    for bit in range(24):
        if not mask & (1 << bit): continue
        body[bit] = COMPONENTS[bit] (buf, p)  # 返回 (value, new_p)
        p = body[bit][1]
    return Entity(handle, flags, body), p
```

组件读取器必须严格按上表顺序实现；任何一位解析错位都会连锁破坏后续实体和命令
列表。
