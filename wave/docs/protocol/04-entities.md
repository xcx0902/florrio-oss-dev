# 04 · 实体记录与组件

世界更新包中的实体列表是每个 tick 的可见实体快照：每个可见实体一条记录，
客户端按掩码增量覆盖本地实体池。本文给出记录外壳、句柄编码和每个组件位的
字段顺序。

## 1. 记录外壳

```
LE u32  handle
u8      flags        线上值 = 逻辑值 XOR 0xac
LE24    mask         组件掩码，低位在前
fields...            按 mask 的位从低到高依次排列
```

| flags（线上） | 逻辑值 | 含义 |
| ---: | ---: | --- |
| `0x60` | `0xcc` | 普通实体 |
| `0x68` | `0xc4` | 装备扩展（花朵，含 16 槽与 8 回充） |
| `0x62` | `0xce` | 普通 + 新到达（bit 1） |
| `0x6a` | `0xc6` | 装备扩展 + 新到达 |

- 客户端读取时先 XOR `0xac`，再判断 bit 3（装备扩展）与 bit 1（新到达）
  （B，`$601`）。
- “新到达”只影响首次插值：客户端会把首帧位置直接设为目标位置；服务端用它标记
  新掉落物，避免从旧缓存位置飞入（A，`garden_projection.cpp`）。

## 2. 句柄编码

```
handle = generation * 8192 + slot
slot   = handle & 0x1FFF          （13 位，0..8191）
gen    = handle >> 13             （19 位）
```

- 实体池：`world + 22848 + slot * 376`；实体对象 `+28` 存完整句柄（B，
  `wave/docs/client-20221030.md`）。
- 保留槽位：`1..5` 分别用于本地资料、玩家列表/小队、花数、场地、波次；
  普通实体从槽位 16 开始（A，W2）。
- 句柄复用必须递增代次；客户端用代次拒绝旧句柄的受击/掉落事件（A，W2）。
- `0` 句柄仅用于列表终止，不能作为实体。

## 3. 组件掩码

掩码是 24 位小端；客户端按位升序读取，缺位即跳过。下表“字段”列是**该位存在时**
的字节顺序；“消费者”列给出使用该字段的函数。

| 掩码 | 字段（wire 顺序） | 语义 | 消费者 | 证据 |
| ---: | --- | --- | --- | :---: |
| `0x1` | `u8 flags` | 基础标志；固定 1 字节，按位保留 | `$601` | B |
| `0x8` | 特殊：花数 | 仅 world 实体，非普通记录 | `$828` 等 | A |
| `0x10` | `vu w`、`vu h`、`f32`、`u8` | 场景宽高/元数据 | `$601` 读取 | B |
| `0x20` | 4 × `u8`；扩展时 + 16 × (`vu type`,`u8 rarity`) + 8 × `vu` | 花朵状态、装备槽、回充 | `$126`/`$998` | A |
| `0x40` | — | 空标记 | — | B |
| `0x80` | `LE u32 predecessor` | Leech 链的前驱句柄（连续绘制） | `$1795` | B |
| `0x100` | NUL 字符串 | 昵称 | UI 名称 | A |
| `0x200` | 4 × NUL 字符串、21 B、NUL 房间码、84 B、4 × 席位标志 | 小队 roster | 小队面板 | A |
| `0x400` | `u16 heading`、`f32 x`、`f32 y` | 位置与朝向（65536 = 整圈） | `$973`/`$41` | A |
| `0x800` | `u8 first`、`vu wave`、`vu biome`、216 × `vu`、`u8 last` | 波次/怪物目录 | `$828`、`$259/$299/$531` | A |
| `0x1000` | `f32 radius` | 碰撞/绘制半径 | `$460` | A |
| `0x2000` | `f32 arena_radius`、`u8 r`、`u8 g`、`u8 b` | 圆形场地与底色 | `$991`、`$973` | A |
| `0x4000` | `u8 palette` | 分裂粒子（Grapes=1） | `$597` | A |
| `0x8000` | 607 B | 本地资料，见 05 | `$140`、`$991` | A |
| `0x10000` | `vu type`、非零时 `u8 rarity` | 花瓣 | `$597` | A |
| `0x20000` | `u8` | 保留位；未找到读取分支 | — | C |
| `0x40000` | `u8` | 保留位；未找到读取分支 | — | C |
| `0x80000` | `u8 render_flags`、事件向量 | 死亡淡出 bit 0；受击事件 | `$597`、`$51` | A |
| `0x100000` | `u8 mob_type`、`u8 ally`、`u8 rarity` | 怪物 | `$597` | A |
| `0x200000` | `u8`、`u8`、`u8 health` | 花朵生命（第三字节 0..255） | `$939`/`$954` | A |
| `0x400000` | `u8 collected`、`vu target`、`vu item`、`u8 rarity` | 地面掉落 | 掉落渲染 | A |

### 字段顺序示例

一个非花朵实体（掩码 `0x1|0x400|0x1000|0x80000`）的 body：

```
00                    # 0x1
00 00                 # 0x400 heading = 0
<x f32> <y f32>       # 0x400
<radius f32>          # 0x1000
<generic flags u8>    # 0x80000
```

花朵还会在 `0x1` 之后插入 `0x20`（4 字节 + 16 槽 + 8 回充）和 `0x100`
（昵称），顺序仍按掩码升序；不能把上面的偏移直接套到花朵上。

字段不是“按组件块”排列，而是**所有置位组件的字段按掩码升序拼接**。因此不能用
固定偏移读取整个实体；必须逐位解析。

## 4. 关键组件的细节

### 0x20 · 花朵状态与装备

```
u8 a, u8 b, u8 level, u8 d
if (记录 flags 的 bit 3 / 0xc4 置位):
  16 × (vu type, if type != 0: u8 rarity)
  8 × vu reload        # 0..65535，0 = 破碎，65535 = 就绪
```

- 前 8 槽为主槽，后 8 槽为副槽（本地映射，W3 使用 6/7/8 槽解锁）。
- `reload` 是**归一化比例**，不是毫秒：客户端 `$126/$998` 做 u16/65535 后
  插值绘制扇形（A）。
- 等级/槽数判定使用第三字节；默认等级 1（`$140`）。
- 16 槽与 8 回充是否存在的开关是**记录外壳的 flags bit 3**（`0xc4`），不是
  组件内的某个 bit；花朵记录必须置该位，否则客户端会把槽位字节误读成昵称。

### 0x200 · 小队 roster

```
4 × NUL 字符串     # 成员名
21 字节默认
NUL 房间码
84 字节默认
4 × 席位标志
```

- 默认字节是 W2 最小兼容值，准备状态、库存、XP、击杀者等字段尚未逐项恢复
  （A/B，`w2-bootstrap.md`）。

### 0x800 · 波次与目录

```
u8   first     # 红色清场条（0..255）
vu   wave      # W1.number - 1
vu   biome
216 × vu       # 目录计数，index = type * 6 + rarity
u8   last      # 蓝色刷怪条（0..255）
```

- 36 类型 × 6 稀有度 = 216 项（A）。
- `first/last` 位于 world `+820/+2560`，由 `$828` 绘制两条归一化进度（A）。
- 顺序：蓝条先推进（刷怪），红条在刷怪结束后推进（清场）（A，用户确认）。

### 0x2000 · 场地

```
f32 radius     # 圆形场地半径
u8 r, g, b     # 背景色
```

- 只发给场地实体（句柄 8196），**不要**给每个实体发（A）。
- 半径参与本地控制约束；颜色全屏填充（A）。

### 0x80000 · 通用渲染与受击

```
u8 flags       # bit 0 = 死亡膨胀/淡出
事件向量        # 由 32 命令追加，24 B/条
```

- `$597` 从首次绘制计时 150 ms：alpha 1→0，比例 1→2（A）。
- `$51` 消费受击事件，绘制约 150 ms 闪白/红（A）。

### 0x400000 · 掉落物

```
u8  collected    # 1 = 被拾取，播放缩小旋转
vu  target       # 飞向的实体句柄，0 = 原地
vu  item         # 物品类型
u8  rarity
```

- 与 `0x400/0x1000/0x80000/0x1` 组合使用；服务端投影的 mask 为
  `1 | 0x400 | 0x1000 | 0x80000 | 0x400000`（A）。

## 5. 删除与保留

- 删除段在实体列表之前，按句柄删除；删除后的槽位在淡出保留期内不能复用。
- 服务端对“已见实体”保留 400 ms 的死亡记录：设置 `0x80000` bit 0 后再真正
  删除（A）。
- 客户端不补造未见实体的死亡动画（A）。
- 重生使用新句柄/新代次，不复用旧控制对象（A）。

## 6. 解析伪代码

```python
def read_entity(buf, p):
    handle = le32(buf, p); p += 4
    if handle == 0: return None, p
    flags = buf[p] ^ 0xac; p += 1
    mask = buf[p] | buf[p+1]<<8 | buf[p+2]<<16; p += 3
    body = {}
    for bit in range(24):
        if not mask & (1 << bit): continue
        body[bit] = COMPONENTS[bit] (buf, p)  # 返回 (value, new_p)
        p = body[bit][1]
    return Entity(handle, flags, body), p
```

组件读取器必须严格按上表顺序实现；任何一位解析错位都会连锁破坏后续实体和命令
列表。
