# 01 · 传输层与帧格式

本文件描述从服务发现到 WebSocket 二进制帧的完整外壳。所有“明文”均指**外层变换
之后**的字节；`vu` 表示无符号 LEB128（最多 5 字节，32 位）。

## 1. 服务发现

客户端先向 m28 的调度接口查询房间所在服务器：

```
GET https://api.n.m28.io/endpoint/florrio-waves-0/findEach/
```

响应为 JSON：

```json
{"servers":{"us":{"id":"w0fixture","ipv4":"127.0.0.1"}}}
```

客户端取 `servers.<region>.id`，拼出 WebSocket URL：

```
wss://<id>.s.m28n.net/
```

- 证据：`wave/data/wire/20221030/bootstrap.json` 的 `discovery` 段（A，抓包）。
- 字符串 `florrio-waves-0` 位于数据段地址 `41492`（B，`strings 40000 45000`）。
- 地区选择与多服务器排序属于调度层，不进入二进制帧；线上协议只使用
  `servers.<region>.id` 拼出 `wss://<id>.s.m28n.net/`。

## 2. WebSocket 首包（握手）

socket `open` 后客户端发送一个**不经过外层变换**的二进制帧：

```
30 <40 字节构建哈希> 00 00
```

| 偏移 | 长度 | 含义 |
| ---: | ---: | --- |
| 0 | 1 | 固定 `0x30`（ASCII `'0'`） |
| 1 | 40 | 构建号 ASCII：`b632797f0ee487dd99df460b13bde6d7ce5c9773` |
| 41 | 1 | 本地账号字符串，NUL 结尾；未登录时为空串 |
| 42 | 1 | `cp6_player_id` 访客标识，NUL 结尾；首次连接为空串 |

真实捕获（43 字节，两个字符串都为空）：

```
30 62 36 33 32 37 39 37 66 30 65 65 34 38 37 64 64 39 39 64 66 34 36 30
62 31 33 62 64 65 36 64 37 63 65 35 63 39 37 37 33 00 00
```

- 证据：`wave/data/wire/20221030/bootstrap.json` `socket.request.hex`（A）。
- 有账号时首包形如 `30 <hash> <account>\0 <cp6_player_id>\0`；`cp6_player_id`
  字符串位于数据段 `34440`（B）。
- 该帧的首字节 `0x30` 与后续类型字节共用编号空间但**不参与**变换；收到服务端
  首帧后客户端才开始按状态机解密。

## 3. 外层变换（每帧）

两个方向各自维护一个 32 位状态，**每个 socket 重置**：

| 方向 | 初始状态 | 首字节置换种子 | 固定交换 |
| --- | ---: | ---: | --- |
| C→S | `0x99df460b` = 2 581 504 011 | 249 858 013 | `{3,66,64,65,48}` |
| S→C | `0x13bde6d7` = 331 458 263 | 3 056 761 215 | `{0,64,4}` |

每帧处理顺序：

1. `state = (state * 83875 + 1323) % 2147171462`
2. 用 `state` 生成 100 项置换表（Fisher–Yates，种子来自上一步），再做固定交换；
3. 首字节 `b[0] = table[b[0]]`，重复 `rounds` 次：
   - C→S：`rounds = (state & 15) + 1`
   - S→C：`rounds = state % 12 + 1`
4. 由同一 `state` 继续推进 LCG，生成 22 字节密钥 `key[i] = state & 0xff`；
5. 对 `b[1..]` 做 `b[i] ^= key[i % 22]`。

> 第 3 步的 `rounds` 方向差异来自服务端实现 `seal()` 与 `receive()`：
> 发送 `state % 12 + 1`，接收 `(state & 15) + 1`。两者在已验证抓包上一致；
> 若用其它实现复现，必须按方向分别取轮数。

证据：

- 参考实现 `wave/tools/w2/codec.mjs`（A，逐字节回归）。
- 服务端实现 `wave/server/wire/bootstrap.cpp` 的 `permutation/next/transform/seal`
  （A，与真实客户端互通）。
- Wasm 侧发送桥 `$2150`（1326187–1326235）与带 9 帧背压的发送队列 `$2153`
  （1326266–1326359）；关闭路径 `$3252`；错误路径 `$3281`（B）。
- 变换的 LCG/置换常量不在 `client.wasm` 的立即数中（`refs 83875`/`refs
  249858013` 均为空），WAT 侧只看到发送桥和接收回调；实现位于客户端附带的
  m28 IO 层（C，未在本次静态范围内）。因此本节的常量以 `codec.mjs` 的逐字节
  回归和 `bootstrap.cpp` 的双向互通为准，不能用“WAT 里没有”否定它们。

**明文例外**：只有两类帧不走变换：

- 握手首包 `0x30`：由服务端按 `is_hello`（首字节 + 40 字节构建号）在变换前
  识别，客户端也在发送状态机启动前发出；
- 关闭/错误帧 `0x00`：`00 00` 即 `kUnknown`，由关闭/错误路径直接读取，不按
  数据帧解析（A，`bootstrap.json` 的 `ff`/`00 00` 反例；具体分层为 C）。

其余数据帧（C→S 类型 1/2、S→C 类型 1/5）一律走完整变换。参考实现
`codec.mjs` 用“固定首字节集合”做快速识别，这是实现细节，不是额外的协议分支；
服务端不能依赖它来解析 `00`。

**状态推进时机**：每发送/接收一帧推进一次，与帧内容无关。重连即重置，因此同一
连接内帧序不能乱序或重放，否则密钥错位。

## 4. 外层消息类型

解密后第一个字节为消息类型，`$3309`（1503445–1505525）以
`br_table [0,1,2,3,4,5,6]` 分派：

| 类型 | 方向 | 处理 | 说明 |
| ---: | --- | --- | --- |
| `0` | S→C | `$3309` 分支 1 | 错误/关闭原因：`vu code` + NUL 结尾消息，显示 “Server disconnect reason (N): kN…”，随后主动关闭 |
| `1` | S→C | `$3309` 分支 2 | 世界更新 + 命令列表（见第 6 节） |
| `2` | C→S | `$992` 之外的 ACK 路径 | 确认最新 tick：`vu epoch, vu tick` |
| `3` | 双向 | 忽略 | 保留 |
| `4` | 双向 | 忽略 | 保留 |
| `5` | S→C | `$3309` 分支 2 | 访客标识：`vu epoch, 00 0e, NUL visitor id` |
| `6` | 双向 | 忽略 | 保留 |

- 类型 `0` 的 `vu code` 到名称是**静态完全确定**的（B，`$3309`
  1503505–1503900 的 `br_table` + 嵌套 `select`，字符串地址已按修正后的
  数据段解码复核）：

| code | 名称 | 字符串地址 | 选择路径 |
| ---: | --- | ---: | --- |
| 0 | `kUnknown` | 28963 | 初始化默认 |
| 1 | `kOutdated` | 34769 | `select` |
| 2 | `kServerFull` | 30008 | `select` |
| 3 | `kInvalidToken` | 29517 | `select` |
| 4 | `kProtocolError` | 26992 | `select` |
| 5 | `kShuttingDown` | 29015 | `select` |
| 6 | `kTooManyConnections` | 25572 | `select` |
| 7 | `kIdle` | 33203 | `select` |
| 8 | `kBanned` | 34856 | `select` |
| 9 | `kChangeSimulation` | 29277 | `select` |
| 10 | `kKicked` | 35006 | `br_table` 的 `$block8` |
| ≥11 | `NOT_IN_ENUM` | 38373 | 默认 |

- 所有分支最终都用 `52856` 的 `"Server disconnect reason (%d): %s\n"` 格式化；
  10 号不走 `select`，而是单独构造 `kKicked` 后直接跳到格式化。
- `00 00` 即 `kUnknown` + 空消息，客户端记录后以 WebSocket 1002 关闭（A，
  `bootstrap.json` 反例）。

## 5. 客户端 → 服务端

### 5.1 可靠批次（类型 1）

```
类型 1 (1 B)
epoch        vu     通常 0
------------------------------------------------- 掩码从这里开始
sequence     vu     从 1 开始，逐命令 +1
opcode       vu
fields       ...
sequence     vu
opcode       vu
fields       ...
```

- `epoch` 不参与内层掩码；`sequence` 起全部与 `payloadKey` 逐字节 XOR。
- 内层掩码表：Wasm 内存地址 `53744` 起 256 字节（数据段 `$135`，
  WAT 第 610 行）（B）。
- 空批次不发送；有命令时每帧最多打包当前队列。
- 序号空间按 socket 从 1 递增；服务端只接受严格 `+1`（A，
  `bootstrap.cpp` 的 `read_startup` 校验）。

### 5.2 ACK（类型 2）

```
02 <epoch vu> <tick vu>
```

该帧**不做内层掩码**，只做外层变换。抓包（同一连接内连续两帧）：tick 1 →
`20 1e b8`，tick 2 → `37 05 a0`（A，`w2-bootstrap.md`）。ACK 由主循环在收到
world 更新后发送；`$3437` 每帧调用 `$992` 冲刷命令队列，`$601` 负责更新解析。

### 5.3 首包与心跳

- 首包是第 2 节的 `0x30` 明文帧，不属于类型 1/2。
- 没有独立心跳 opcode；连接保活依赖 WebSocket 层与每帧 tick。

## 6. 服务端 → 客户端

### 6.1 世界更新（类型 1）

```
类型 1 (1 B)
epoch        vu
tick         vu
------------------------------------------------- 掩码从这里开始
ack          vu        已消费的客户端序号
删除段（可省略；初始 world 直接跳到实体列表）:
  length     vu        下面内容的字节数（空删除为 2）
  count      vu
  flag       u8        0
  handles    count × LE u32
  flag       u8        0
实体列表:
  record*              见 04-entities.md
  00 00 00 00          零句柄终止
分隔符       1 B       固定 0（$601 明确跳过）
命令列表:
  tag        vu        0 = 结束；1 = 无序号；n≥2 = 序号 n-1
  opcode     vu
  fields     ...
  0
```

- `tick` 之前的 `epoch`、`tick` 不参与内层掩码；`ack` 起全部掩码。
- 删除段整体被长度前缀包住，客户端在重复 tick 时可直接跳过。
- **初始 world 可以完全省略删除段**，在 `ack` 后直接写 4 字节零句柄；带删除
  的增量快照才写 `length/count/flag/handles/flag`。两种形式原版都接受
  （A，`bootstrap.cpp` 的 `world()` 与 `snapshot()`）。
- 实体列表以 4 字节零句柄结束，**之后还有一个分隔字节**；漏掉它会错位读取命令
  并触发 `$988` 的 `unreachable`（A，`w2-bootstrap.md`）。
- 命令列表末尾的 `0` 可以省略；历史最小空更新在分隔符处直接结束（A）。

证据：`$601`（394231–468963）读取该结构；`$3309` 负责类型分派；
`wave/server/wire/bootstrap.cpp` 的 `world()/snapshot()` 生成同构字节（A）。

### 6.2 访客标识（类型 5）

```
05 <epoch vu> <掩码后的 00 0e + NUL visitor id>
```

- 明文负载以 `00 0e` 开头，随后是 NUL 结尾的 `cp6_player_id`。
- 客户端把值写入 `cp6_player_id` 并用于下次握手（A，W2）。
- 掩码从 `00 0e` 起（`seal(..., masked_offset=2)`，B）。

### 6.3 错误/关闭（类型 0）

```
00 <code vu> <NUL message>
```

- 客户端显示 `Server disconnect reason (<code>): <kName>`，然后关闭 socket。
- 代码枚举见第 4 节。

## 7. 边界与关闭码

| 条件 | 行为 | 证据 |
| --- | --- | --- |
| 单帧 > 4096 B | 应用层保留 4097 B 后 `async_close(1009)`，等待关闭握手 | A，W2-06 |
| 收到 `00 00` | 记录 `kUnknown`，WebSocket 1002 关闭 | A |
| 发送队列积压 9 帧 | `$2153` 暂停继续入队，等待 `bufferedAmount` 回落 | B |
| 非法首字节/长度 | 丢弃并关闭 | B，`$3309` |

## 8. 最小可复现帧

| 场景 | 字节（外层变换前） | 说明 |
| --- | --- | --- |
| 握手 | `30 <hash> 00 00` | 第 2 节 |
| ACK tick 1 | `02 00 01` | 变换后 `20 1e b8` |
| 访客标识 | `05 00 00 0e <id> 00` | 客户端解析为 `00 0e` + id |
| 空世界（初始） | `01 00 <tick> 00 00 00 00 00 00 00 00 00 00` | tick、ack=0、实体终止、分隔、空命令 |
| 空快照（带删除段） | `01 00 <tick> 00 02 00 00 00 00 00 00 00 00 00` | 删除长度 2 / 数量 0 / 两个标志、实体终止、分隔、空命令 |

> 表中“外层变换前”仍需按第 3 节生成首字节置换与 XOR；抓包文件中的 hex 是
> 变换后的线上字节。
