# 客户端接受、复刻服务端从不发送或只发占位值的参数

本文回答一个和 [README](README.md) 的“唯一可信来源”规则配套的问题：
**客户端明明有解析代码，但 `wave/server` 从不发送（或恒发占位值）的字段有哪些？**

三点前提，先写在最前面，避免误用：

1. **“服务端不发”永远不能证明字段无用。** 依据是 [README §0](README.md)：
   `wave/server` 是复刻实现，不是原版。客户端仍然会解析这些字段，只是复刻
   没用到，所以复刻里的对应功能是缺的，不是字段是废的。
2. **反过来也成立：本文件不授权删除任何客户端解析代码。** 表的用途是给
   复刻排优先级、给抓包判读提供“这个 0 是占位还是真值”的对照。
3. 客户端侧证据一律是本构建 `20221030`（SHA-256 `68094577…76e7b0`）的
   `client.wasm`；服务端侧只用于回答“发了没有、发的是什么”，不作为语义证据。

三张表：

- **A**（§1）：客户端接受、复刻**从不发送**的组件位；
- **B**（§2）：复刻**发送但恒为占位值**的字段；
- **C**（§3）：客户端**解析后无读者**的子字段（复刻发了也白读）。

§4 给出“要激活这些字段该怎么编码”，§5 是禁止事项。

---

## 1. 表 A：复刻从不发送的组件位

`wave/server/wire/world_projection.cpp` 的实体掩码只有这几种写法：
`0x400 | 0x1000 | 0x80000`（241）为基础，按条件 `|=` 上
`1`(244)、`0x80`(250)、`0x20|0x100`(254)、`0x4000`(307)、`0x10000`(310)、
`0x20000`(315)、`0x100000`(321)、`0x200000`(328)；单例记录另发
`0x2`(113)、`0x10|0x2000`(524)、`0x800`(555)、`0x8000`(451)、`0x200`(506)；
掉落物发 `1|0x400|0x1000|0x80000|0x400000`(377)。

**从未出现**的位只有 5 个：`0x4`、`0x8`、`0x40`、`0x40000`、`0x800000`。

| 位 | 线上字段（客户端真实读取） | 客户端落点 | 等级 | 复刻现状 | 激活前提 |
| ---: | --- | --- | :---: | --- | --- |
| `0x4` | 2 × `LE32` 句柄 | `$601` 399800 起挂到实体 `+152/+156/+160` 的句柄链表；`$201` 做 handle→指针映射 | P | 不发 | 需要目标实体先存在（句柄可解析），否则 `$201` 查不到 |
| `0x8` | 11 × `vu` + 10 × `LE32` + `u8` + 10 × NUL 字符串 | `*(entity)+116` 内联对象：`+124..+164`、`+208..+244`、`+288`、`+292+i*12` | P | 不发 | 见 §4.1；10 个字符串**必须正好 10 个**（空串也要各写 1 个 `0x00`） |
| `0x40` | **无载荷**（只有掩码位） | `$969` 建 8 B 节点（`+0=entity`、`+4=timestamp`），挂 world `+624` 指针向量 | P | 不发 | 只需置位；置位后 `+624` 向量多一个元素 |
| `0x40000` | `u8` | `$588` 建 16 B 槽（`+0=entity`、`+4=timestamp`、`+8=字节`、`+12=0`），挂 world `+2892` 列表 | **W** | 不发 | 字节无读者；仅插入/析构 |
| `0x800000` | 300 × `f64` + 300 × NUL 字符串 | world `+3088`（f64 表）、`+6688`（300 × 12 B 字符串） | **W** | 不发 | 整表无读者，见 [09 §3.7](09-field-audit.md) |

> `0x40` 容易被误读成“12 B 节点 + world+592”：那是 `0x20`/`0x40` 旧版混淆。
> 现结论是 8 B 节点、world `+624`（[09 §4](09-field-audit.md) 已修正）。

### 1.1 这批字段缺了什么功能

- 没有 `0x4`：复刻的小队/编队关系、以及任何“实体指向另两个实体”的链路
  在客户端侧不会被连起来。`0x200` roster 里的花朵句柄是另一条路径
  （`$954` 直接按句柄定位），不依赖 `0x4`。
- 没有 `0x8`：世界级那块 10 行“名称 + 32 位数值”表永远是空的。这是复刻里
  唯一整块缺失、且客户端确实会解析的 world 组件。
- 没有 `0x40000` / `0x800000`：客户端反正不读（W），**没有功能损失**，
  属于“发了也白发的字节”，可以永久不发。

## 2. 表 B：复刻发送但恒为占位值的字段

这些字段**在线上存在**（掩码位有、字节数对），但复刻写入的值恒为同一个，
客户端读到的永远是那个常量。抓包时看到这些 0 不代表“原版也是 0”。

| 字段 | 客户端落点 | 复刻写入 | 说明 |
| --- | --- | --- | --- |
| `0x1` 的 `u8` | 槽 `+8`；bit 0 参与渲染插值与 Digger 攻击姿态（`$1795`/`$1738`） | `0`，仅 Leech 或 Digger 攻击时为 `1`（246） | 客户端已知读者只看 bit 0；其余位未定位 |
| `0x20` 第 1 字节 | 槽 `+8` | 恒 `0`（255） | 语义未定位；复刻无法给出真值 |
| `0x20` 第 2 字节 | 槽 `+9` | 恒 `0`（256） | 同上 |
| `0x20` 第 4 字节 | 槽 `+11` | 恒 `0`（262） | 同上（第 3 字节是玩家等级，复刻有填） |
| `0x10` 的 `f32` | world `+504`（内存里是 f64） | 恒 `1.0`（516） | 原版可能是缩放/时间比例；复刻固定 1.0 |
| `0x200` 的 4 个标签串 | roster `+76/+88/+100/+112` | `zeros(4)`（483）＝ 4 个空 NUL 串 | 客户端按 NUL 串解析，空串正好各占 1 字节 |
| `0x200` 的 `f32` | roster `+632` | 恒 `0.0`（502） | 位置在 64 个花瓣条目之后、4 个席位字节之前 |
| `0x20000` 的 `u8` | 槽 `+8`（对象被 `$597` 消费，字节本身无读者） | 恒 `0`（316） | 见 [09 §5](09-field-audit.md) 第 5 条 |
| `0x80000` 的 `u8` | 槽 `+8`；bit 0 = 死亡膨胀/淡出 | `0`，幽灵期置 bit 0（177） | 复刻只用到 bit 0 |
| `0x200000` 第 1 字节 | 槽 `+8` | 恒 `0`（329） | 语义未定位 |
| `0x400000` 的 `collected`/`target` | 槽 `+8` / `+12` | 非拾取掉落恒 `0`/`0`（379） | 只有 pickup 记录才非零 |
| `0x8000` 的第一组 276 个整数 | profile `+12`（`array0`） | 全部 `0`（402） | 旧版合成计数；客户端无读者 |
| `0x8000` 的 4 个整数 | profile `+2220`（`unknown[4]`） | 全部 `0`（405） | 未知槽；客户端无读者 |
| `0x8000` 中 `killer` 文本后的 `f32` | profile 尾部 | 恒 `0.0`（429） | 其后是 `word(controlled)` 与 `real(camera.x)` |

### 2.1 判读建议

抓包或对拍时，如果看到上表字段全 0，**先假定是复刻占位**，不要据此推断
原版语义。反过来，如果真机抓包里这些字段非 0，那正是复刻缺的信息：

- `0x20` 的 `+8/+9/+11` 三个字节非 0 → 说明花朵状态还有别的位/枚举；
- `0x200 +632` 非 0 → 多半是倒计时/准备进度（席位字节之外唯一的时间量）；
- `0x10` 的 f32 ≠ 1.0 → 场景缩放/时间比例；
- `0x8000` 的 `unknown[4]` 非 0 → 客户端没有读者，但原版仍可能在别处使用
  （例如未启用的 UI），这类只值得记录、不值得实现。

## 3. 表 C：客户端解析后无读者

| 字段 | 客户端落点 | 无读者的依据 | 等级 |
| --- | --- | --- | :---: |
| `0x20000` 的 `u8` | 槽 `+8` | 对象本身被 `$597` 当光晕/网状态消费，但 `+8` 本身没有任何 load | P |
| `0x40000` 的 `u8` | 槽 `+8` | world `+2892` 列表只有插入（`$588`）与析构/unlink（`$452`/`$587`/`$989`），无遍历 | **W** |
| `0x800000` 全表 | world `+3088`/`+6688` | 常量 `3088`/`6688` 只出现在构造/解析/增量重初始化/析构，无以它们为基址的 load | **W** |
| profile `unknown[4]` | `+2220..+2235` | 全模块零 load | **W** |
| profile 背包 276 | `+2400..+3504` | 只写不读（图鉴读 `+2288`、缩放读 `+2316`，都不在这个数组里） | U |
| profile 旧合成 276 | `+12..` | 只写不读 | U |

`U` 与 `W` 的区别：`W` 是“穷举过、确认没有 load”，`U` 是“没找到，但不保证
穷举”。两者都不等于“字段无用”——只是客户端不用。

## 4. 要激活这些字段时的编码要求

复刻若要开始发送表 A 的组件，必须逐字节对齐客户端的读取顺序，否则不是
“字段被忽略”，而是**整条实体记录错位**（后续实体全部解析成垃圾）。

### 4.1 `0x8`（最容易写错）

```
11 × vu          # → *(entity)+124..+164
10 × LE32        # → +208..+244（定宽 4 字节，不是 varint！）
u8               # → +288
10 × NUL 字符串  # → +292 + i*12，正好 10 个
```

- 第二组**必须是定宽 `LE32`**。客户端读法是四个 `i32.load8_u` 拼
  `b0 | b1<<8 | b2<<16 | b3<<24`；写成 varint 会在第一个 ≥ `0x80` 的字节
  处把后面全部读错。
- 10 个字符串必须**逐个 NUL 结尾**，空串也要写 1 个 `0x00`；少写一个，
  剩余字段就会吃掉下一条记录的头。
- 结构上是“10 行名称 + 10 个 `LE32` + 11 个前导计数 + 1 个标志”，按形态
  最像排行榜，但客户端消费点未闭合（文本绘制走 `call_indirect`）。

### 4.2 `0x400000`

```
u8 collected
vu target
vu type          # = 花瓣/物品类型；为 0 时到此为止
u8 rarity        # 仅当 type != 0
```

复刻已经是这个顺序（`world_projection.cpp` 366–379）。**不要**把
type 和 rarity 合并成一个打包 varint：客户端用 `$55` 读的是两个字段。

### 4.3 `0x200` 的 4 个标签串

`zeros(4)` 正确（4 个空串）。若要发真值，写 4 个各自 NUL 结尾的字符串，
**不能**写成“4 个字节的长度前缀 + 数据”。

### 4.4 `0x20` 的 16 个槽

```
vu type
u8 rarity        # 仅当 type != 0
```

空槽只写一个 `0`。64 个条目（16 槽 × 4 成员）顺序是**槽优先**：同一槽的
四名成员相邻，`$136` 用 `slot*4 + member` 索引。

### 4.5 `0x40`

只有掩码位，**不要附任何字节**。附了字节会被下一条记录当成句柄首字节。

### 4.6 所有 `f32` 字段

客户端用同一个读法（`f32.load align=1` + 三道 `select`）读所有 `f32`：
`NaN`、`±Inf`、非规格化数一律被改写成 `0`。复刻不要发 `NaN`/`Inf`/
非规格化值——它们不会“被忽略”，而是**静默变成 0**，看起来像发了一个
合法的 0。这条对 `0x400` 的 x/y、`0x1000`/`0x2000` 的半径、`0x200` 的
`+632`、`0x10` 的标量都成立。

---

## 5. 禁止事项

1. **不要**因为表 A 就删除客户端解析代码或把字段标成“无用”——那是把
   “复刻没实现”写成“原版没有”。
2. **不要**在未置对应掩码位时附加该组件的 body 字节；也不要在置位后少写。
3. **不要**把 `0x8` 的第二组当 varint、把 `0x400000` 的 item 当单个 `vu`、
   把 `0x200` 的标签当长度前缀串——这三处都会静默错位。
4. **不要**用本文的表 B 反推原版语义：占位值只说明复刻写的是常量，不说明
   客户端只接受这个常量。

## 6. 复现

```bash
# 实体掩码的全部写入点
grep -n "mask |=\|mask =" wave/server/wire/world_projection.cpp

# 客户端侧：0x8 的 10 个字符串循环 / 0x400000 的 $55
python3 tools/protocol/wat.py fn 601 | grep -F -A40 'l$15 = l$15 + 292'
python3 tools/protocol/wtree.py at 427997 --up 3

# 位级等级交叉检查（不一致时退出码 1）
python3 tools/protocol/coverage.py --check
```
