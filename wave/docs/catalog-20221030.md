# October 30, 2022 catalog and petal simulation

This document covers W3 §03.1 and the native portion of W3-01. The authoritative
input is [catalog.json](../data/catalogs/20221030/catalog.json), version
`20221030-w3.1`; [generate.py](../tools/catalog/generate.py) validates the bundled
evidence inputs and emits [generated.hpp](../server/catalog/generated.hpp). The public
API is [catalog.hpp](../server/catalog/catalog.hpp). It is header-only, so the
simulation and Store can consume the same tables without a catalog library or
link dependency cycle. Protocol, persistence and browser execution results have
separate owners and are not acceptance claims made by this document.

`candidateRanges` and `bodyCandidateRanges` are sensitivity intervals, not
measured confidence intervals. Most unknown magnitudes use 0.5–2× adopted
values; zero-valued absent effects stay zero. Known historical contradictions
remain listed above rather than being concealed by those intervals. Per-rarity
historical attack/defense orbit scaling is unresolved; the shared simulation
attack/defend multipliers remain in use. Petal body cooldown/poison ticks are
converted from a 25 ms source tick. Mob body tick fields currently target the
production 25 ms step; arbitrary-step mob calibration is not established.

## Economy and progression authority

`craft_table()` exposes the observed display percentages separately from adopted
server chances `[600000,400000,200000,100000,30000]` per million. Server parity is
reconstruction; only Mythic 3% has additional primary-log support. Successful
attempts consume five inputs. Failure uses explicit
`failureLossRange:[1,4]`, `failureLossWeights:[1,1,1,1]`, and returns `5-loss`.
The range is observed; equal weights and independent loss draws are adopted.
Historical pre-October-20 failure-count import is outside this catalog/sim work.

`level_for_xp()` and `xp_thresholds()` share the reconstructed curve
`100*(level-1)^2`. Levels run from 1 through 255, a compatibility cap for the
original byte field rather than a proven historical maximum. `xp_thresholds()`
contains 256 entries: index `L-1` starts level L, and final index 255 is the
level-256 sentinel for progress encoding. Arbitrarily large uint64 XP still maps
to level 255. `level_table()` and `unlocked_main_slots()` centralize the observed
5/6/7/8 slot progression at levels 1/15/30/45. Store must delegate to these APIs;
projection must use the same thresholds. The old 15-entry exponential table was
an initial reconstruction and is replaced, so eight slots remain reachable.

Mob XP is explicitly reconstructed as 1/2/4/8/16/32 by rarity. The initial
`drop_table()` has four rows for **Common mob rarity**: Ladybug → Common Rose
0.203; Baby Ant → Unusual Leaf 0.028; Centipede → Common Peas 0.041; Spider →
Unusual Web 0.047. These are a bounded adopted tranche, not a complete historical
drop table. `DropDefinition::rarity` is output rarity; `mob_rarity` selects the
input population. Team eligibility/allocation belongs to Garden. Mob gallery
discovery is separate from petal inventory and is not inferred from petal output.

The implementation of these test IDs is
[w3_catalog.cpp](../tests/native/w3_catalog.cpp); the executable prints each ID
on success and identifies the failing ID. The registered CTest is `W3-catalog`;
source/hash validation and 26 malformed-pack rejection fixtures are
`W3-catalog-validation`. `--self-test` also runs the generator from an isolated,
renamed package containing only its script, catalog, bundled evidence and generated
header. Five additional probes reject a changed evidence byte, stale header,
missing external reference, changed external hash and ignored snapshot argument.

The existing `vector<Petal>` API remains available:

```cpp
match.add_player(id, position, kinds, rarities = {});
match.set_loadout(id, kinds, rarities = {}); // immediate on simulation executor
match.equip(id, slot, kind, rarity = Rarity::common);
match.queue(Equip{life, kinds, rarities});    // validated, life-scoped tick command
```

An omitted rarity array means Common. A supplied array must match kind count;
rarities outside 0–5 and more than eight active slots reject atomically.
Unchanged slots retain particles and timers. `PlayerView::loadout_rarities`
parallels `loadout`; `PetalSlotView::entity` remains the first orbit particle,
`.entities` contains all particles, and `.reload_ticks`/`.reload_total_ticks`
describe slot cooldown. Detached projectiles preserve original owner/rarity and
can coexist with a reloaded slot. Owning-life removal reaps its children.

Simulation order is commands, life/slot refresh, scheduled spawn, movement/orbits,
special effects, contacts, old poison, queued impacts, consumption/expiry,
deaths/credit, final orbit update, wave adjudication. New poison starts on the
following tick. A projectile launched after movement first moves next tick.
Egg lifetime only expires owned summons; unrelated mobs in the summon group are
not removed by that timer. `Defeat` snapshots mob metadata before pool removal
so Garden can calculate rewards afterward without resolving a stale entity ID.
`LifeChange::position` similarly snapshots the body position before removal;
birth events include the spawn position. The optional trailing field defaults to
`nullopt` for compatibility with existing three-field aggregate initializers.

The simulation consumes active main-slot vectors only. Translation between the
original packed equipment ordering and Store's internal representation belongs
to the app/wire boundary; this API does not declare the 16 original entries to
be contiguous main/reserve halves.

## Unsupported effects and fallback boundary

The modeled tranche is **12 kinds × six rarities = 72 definitions**: Basic,
Rose, Faster, Leaf, Stinger, Peas, Grapes, Web, Missile, Egg, Honey, Cactus.
None (ID 0) is a valid empty slot and emits no phantom Basic. Every modeled
petal, emitted mob, segment, summon and rarity has an explicit client mapping.

The remaining 33 nonempty original identities map correctly but have no modeled
effect: Light, Rock, Square, Iris, Wing, Bubble, Pollen, Dandelion, Antennae,
Heavy, Yin Yang, Salt, Rice, Corn, Sand, Pincer, Yucca, Magnet, Yggdrasil,
Starfish, Pearl, Lightning, Jelly, Claw, Shell, Cutter, Dahlia, Uranium, Sponge,
Soil, Fangs, Third Eye, Stick. `client_petal()` returning an ID does not establish
equip capability. Catalog-backed `Match` rejects these kinds in initial, live
and queued equipment requests; it never supplies generic contact behavior for
them. App validation can call `catalog::can_equip()` before a Store mutation.
Their storage, inventory display or crafting identity may still be valid under
separate app policies.

Explicit null-catalog W1/W2 fixture rules retain their old vector-body behavior.
This compatibility path does not advertise production support for unmodeled
effects. No modern catalog/schema IDs or numerical values are imported.

To validate this scope:

```sh
python3 wave/tools/catalog/generate.py --check --self-test
python3 wave/tools/catalog/generate.py --check --verify-evidence \
  --evidence-root . --snapshot wave-reference/20221030
cmake --build build/wave/native --target wave_w3_catalog --parallel
ctest --test-dir build/wave/native --output-on-failure -R '^W3-catalog'
```

For a standalone copy named, for example, `/tmp/example/source`, run
`python3 /tmp/example/source/tools/catalog/generate.py --check --self-test`.
The package root is derived from the script location (`parents[2]`), with no
dependency on a directory named `wave` or its containing repository. CMake's
ordinary build check needs `catalog.json`, `evidence-inputs.json`, the generator
and generated header; it needs no W0 reports, original Wasm or wiki cache.

Full original evidence verification is opt-in and requires an explicit
`--evidence-root` containing the retained source paths. `--snapshot` accepts a
directory containing both `client.js` and `client.wasm`, or a Wasm file with the
original `client.js` beside it. If omitted, its path comes from the source
metadata under the explicitly supplied evidence root. This mode verifies every
original source hash, the W0 reference hash, both complete snapshot files and
the extracted selections. Missing files, changed hashes or inconsistent excerpts
fail; no missing input is silently skipped. Supplying `--snapshot` or
`--evidence-root` without `--verify-evidence` is an error. Default output clearly
states that full external verification was not requested.

The same nine native groups also pass a standalone strict C++20 build with
AddressSanitizer and UndefinedBehaviorSanitizer. Browser rendering, original
menu operations and end-to-end persistence require the separately owned W3
integration acceptance; native success alone does not establish those results.
