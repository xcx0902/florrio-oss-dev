# 05 · 对局 HUD、触屏控制与结算

本章以 `wave-reference/20221030/client.wasm`（SHA-256 `68094577a0ac1254fcffedbb46c0181d90893bd063e3eafa76489bba2776e7b0`）为准。**静态**表示可在重新反汇编的 Wasm 中定位；**实测**表示在本地协议夹具里观测到未打补丁的原版绘制。夹具给出的身份、掉落、波次时长等只用来触发分支，不是 2022 年服务器历史参数。函数名 `$n` 使用 Binaryen 132 的编号（浏览器栈为 `wasm-function[n+358]`）。共享字体、比例和 Canvas 状态见 [01 · 渲染器](01-renderer.md)，设置见 [06 · 设置及附加覆盖层](06-settings-and-overlays.md)。

记 `s` 为 `$617` 的 HUD 缩放，`W/H` 为 backing canvas 宽高除以 `s` 并按原版 f32 结果向上取整；下文坐标是乘 `s` 前的 HUD 逻辑单位。1024×768、DPR 1 桌面实测 `s=0.711111...`、`W=1440,H=1080`；844×390、DPR 2、iPhone UA 实测 backing 1688×780、`s=1.31875`、`W=1280,H=592`。如无特别说明，文字用 Canvas `Npx Ubuntu`，居中／middle，先黑描边（`0.12N`）再白填充。

## 1. 绘制顺序与激活条件

- **世界**：`$939 → $3437 → $991`。世界底色、格线、场地、实体、屏幕空间昵称、部分生命反馈与指针方向提示在此；游戏 HUD 用自己的坐标系，跟随镜头的对象不能和固定 HUD 共用变换。对于两个花朵的夹具，远端昵称为 24px，投影到花朵中心后向上 30 HUD 单位；自己的世界昵称没有出现在这组帧，自己的名字在左上行及左下经验条上。
- **入场转场**：按 Ready 并收到控制对象后可见圆形场地从屏幕中心展开，早期帧仍能看见菜单；HUD 随原版状态进入。单独等某个文本出现、用服务端「已开局」直接翻页，均会漏掉过渡。复刻目标需分别锁定开始、中途和完全展开帧。
- **HUD 合成**：`$939` 绘制小队状态、Wave 模块、进度、装备和触屏层到同尺寸离屏 canvas。在本次战斗样本中把整张离屏以 `globalAlpha=.85` 合回主 canvas；例如花瓣图自己的 alpha 可接近 1，空槽在离屏为 .8，再一起合成。死亡幕和离开按钮在主画布上另画。组合 alpha 与分部 alpha 是两层，不能给每条命令统一乘 .85 来替代离屏合成。
- **退出／死亡**：不再有控制对象时装备及对局经验块退场；小队和 Wave 能继续绘制。第一次死亡弹层会在 HUD 后铺黑；等待复活时去掉全屏黑幕，只显示下方提示。结算期间还能看到原版左上的退场键及残留小队行，实测黑底上可见本人的死亡头像、名字；不要用全屏 DOM 层把原版仍会画的元素抹掉。较晚才绘制的 tooltip 仍可盖在按钮上。归档页的本地 DOM「Garden」下拉是宿主附加物，必须从原版截图验收遮罩中排除。

## 3. 小队生命、世界标记与经验

**左上队员。** `$939 → $954 → $981`，队伍槽来自 roster `0x200` 的花朵句柄（包含代次），名字来自 `0x100`，生命取 `0x200000` 的第三字节 `+10`，除以 255。本人头像锚点 `(60,90)`、局部比例 1.25，首名队友实测 `(60,190)`、比例 1；桌面像素分别为约 (42.67,64) 和 (42.67,135.11)。队友还有头像与槽之间的方向尖角，随相对方位变化（实测左右两种方位）；所有席位、离屏方向与重排时序需分别验收。单行以头像为局部原点：

1. `(0,0)→(175,0)` 黑色圆头线，宽 30。内条以 `(110,0)` 为原点，从 `(-65,0)` 出发，总长 130。先画 `#dd3434`（18 宽、拖尾值），再画 `#75dd34`（21 宽、即时平滑值），两者长度独立；没有生命值时二者 alpha 归零。
2. 头像 `$471`：半径 25，`#ffe763` 填色、`#cfbb50` 线宽 3；`$470` 瞳孔中心局部 `(±7,-5)`、活眼半径 3 并纵向×2、白亮部裁在眼睛内。嘴以 `(0,10)` 为原点，活与死用不同方向的二次曲线；死眼用两条交叉线（端点 `±4`，宽 3，`#222222`）。存活与死亡都用 18px 在 `(110,0)` 叠名字。阵亡行保留黑条与叉眼；有队友生还不把整张左上面板移走。
3. `$991 → $982 → $981` 还可在世界实体附近绘制同族生命反馈（本帧可记录到 alpha=0 的黑／红／绿路径，线宽分别 10/6/7）。不要把这个调用与左上血条重复计为两个常亮 UI。世界血条显示条件、受伤与恢复时钟应对照同一组帧分别验证；原版世界受击／死亡动画接法见 [原客户端取证](../client-20221030.md#受击消失与事件投递)。

**左下经验与名字。** 正常桌面、仍控制花朵时实测 `(150,H-148.2)` 为 24px 名字；`(0,H-110)→(300,H-110)` 是宽 40 的 `#333333` 圆头底条，前景 `#f5ff65` 同线宽按经验比推进，级别字样 `Lvl 1 Flower` 用 16px、锚 `(150,H-110)`。其下 `(150,H-78)` 以 14px 显示 `Extra petal slot at level 15`，另有 30、45 两级版本；这些数值是**下一解锁等级**，不能把所有等级提示堆在一帧。资料 `+8` 等级与经验、进度的协议及整数规则见 [05 · 资料](../protocol/05-profile.md)。在本次移动对局中该块隐藏；菜单仍有自己的经验条。

**方向反馈。** 桌面移鼠离开花朵中心时，本地夹具可在原画布捕到半透明的深色方向箭头；它在世界／移动指示层，不能把队友行的白色小方向尖角当作同一箭头。需在同一 RAF 下测中心死区、距离和颜色，及设置切换后的差异（见 [06](06-settings-and-overlays.md)）。

## 6. 触屏控制和手势

ASM_CONST `147419` 根据 UA 子串 `iPhone/iPad/Android/Mobile/Tablet` 判移动，`147661` 再判 `iPad/Tablet`；只模拟 `hasTouch` 而仍用桌面 UA 会走桌面分支。对局 HUD 直接画入离屏层，不放 DOM 浮动按钮：

- `A` 键中心 `(W-230,H-150)`，半径 80；`B` 在 `(W-80,H-80)`，半径 50。黑圆及白字 48px，离屏正常 alpha .6，按键文字无黑描边；这是独立层级的 alpha，之后仍要合成 .85。与移动设备 DPR 无关，先换到逻辑坐标再命中。WAT `$939` 674124–675500 可定位半径、偏移、按压输入和 A/B 文本。
- 默认左侧移动触点使摇杆底圆在初始指尖出现，实测半径 90，黑色，出现 alpha →.6；同帧仍画 A/B。模拟触点 CSS (110,260) 后，原版离屏圆中心逻辑约 (166.825,394.313)，正好是 CSS 坐标乘 DPR 再除以 `s`。静态 `$939`：默认底盘在拖移半径 135 内保留中心；超过时沿旧中心→指尖平移底盘，使指尖距新中心恰为 135。`florrio_fixed_joystick=Y` 对应 `$79` 读取的固定模式，跳过上述中心重定位。135 是移动阈值，90 是底盘半径；激活区分界、滑出按钮、第二触点与释放帧仍需单独实测。
- 移动 UA 的菜单实测没有鼠标教学 `How to play / Use mouse to move / Left click to attack / Right click to defend`；原版 Ready 用触屏点击进入。桌面教学在菜单或入场时，键盘布局可能用 `SPACE to attack`、`SHIFT to defend`（模块字符串）；设置、平台及焦点条件见 [06](06-settings-and-overlays.md)。

## 7. 重建接口和验收

重建时用显式的 `MatchHudFrame`：输入视口／UA／首选项、frame dt、控制实体／roster、波次及 216 项、等级和经验、主副槽和八个就绪值、场地／击杀者／结算输入以及实时指针。保留平滑状态，输出 Canvas 路径、文本、图像和命中框；同一画面单独记录世界层、离屏 HUD、主 Canvas 合成和 DOM。首版优先让原版在同一组输入下给出对照，再逐层换成重建版。现有 W2 入口为：

```sh
npm --prefix wave run test:wire -- --snapshot wave-reference/20221030 --browser /absolute/path/to/chromium --output-dir /absolute/path/to/output
```

W2-02/04/08/11 的客户端启动、输入、步进和观察器分别在 [online.mjs](../../tools/w2/online.mjs)、[playability.mjs](../../tools/w2/playability.mjs)、[protocol-effects.mjs](../../tools/w2/protocol-effects.mjs)。现有完整用例仍使用 `local.js` 运行时适配；做像素基准时，保留同源协议适配，将脚本里的 `adaptWaveClient(new Uint8Array(await response.arrayBuffer()))` 在浏览器路由中替换为原样读取 `new Uint8Array(await response.arrayBuffer())`，不写仓库或归档；资源请求只在本地夹具完成，禁用外部流量。这次使用 Chromium headless、en-US、归档 Ubuntu，先通过真实 Ready／邀请进对局，再用 fixture 的 `POST /wave/test/step/:n` 推进，等待广播与动画帧；不写 Wasm 内存。主画布及 OffscreenCanvas 的 `getTransform`、样式、路径、文本和调用栈应在同一 RAF 中留存。

- 桌面最小回归：Ready 入场、生成 85/255、生成满／清场 0、生成满／清场 51、两类怪物与只剩一种、精简开关前后、空副槽及回充三点、活局两人、单人死亡／结算、双人死亡／等待、离场 hover／点击。核对 alpha、颜色、几何、字体测量及发出的命令；同时保留所有文字的实际可见区域。
- 移动最小回归：同一局用桌面 UA 的触摸仿真与真实 mobile UA 对照；后者在相同 DPR 捕获闲置、左摇杆起点和拖移、A/B 按下和松手、横屏与竖屏；tablet UA 独立核对比例。运动方向、冷却扇形和合成差异要在相同服务器输入及相同插值时间比对。
- 1:1 待补对照：三／四人队伍与方位箭头、部分血量拖尾全时序、高等级全槽与缩放、超长目录与各稀有度入／退场、Desert/Ocean 进度条配色、AFK 原生可见警告与时钟复位、固定摇杆全状态、PvP 和专门的 Boss／观战分支是否可达。未覆盖项需要原版相同分支和输入作为金样，不能用现有本地服务器缺少对应场景当作负证据。
