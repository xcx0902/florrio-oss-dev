## 取证与复采

从仓库根运行。现有资源位于 [资源清单](../../web/resources-20221030.json) 所列位置；归档 HTML 与字体由 W0 取证缓存提供。完整资源与构建方法见 [Wave README](../../README.md)。

```sh
shasum -a 256 wave-reference/20221030/client.wasm wave-reference/20221030/client.js
wave/node_modules/.bin/wasm-dis wave-reference/20221030/client.wasm -o /tmp/wave-20221030.wat
CHROMIUM_PATH=/absolute/path/to/chrome-headless-shell \
  node wave/docs/client-ui/tools/capture-lobby.mjs /tmp/wave-ui-lobby
node wave/tools/reference/tooltips.mjs --snapshot wave-reference/20221030 --check
```

大厅脚本用原 HTML、JS、Wasm、字体和临时本地服务器，拦截其它网络请求；它已经在 Chromium 156.0.8078.47 上生成 13 组 PNG/JSON。每组采样附近帧，背景花瓣、光标和动画相位未冻结。非大厅的截图采用原版 Wasm 加本地测试宿主，分别参照各章的夹具输入。现有协议用例可提供队伍/波次/装备的输入序列；做原版基线时必须校验浏览器实际实例化的是原字节，不能直接以本地 runtime patch 作为基线。

## 实现和比对顺序

1. **固定测试环境。** 每个 case 保存原件摘要、浏览器及平台、字体文件及加载完成时间、语言、CSS/backing 尺寸、DPR、UA、输入序列、存档种子和协议帧。至少有 1024×768@1、1280×720@1、800×600@2、窄桌面和真手机 UA 横/竖屏；平板 UA 另成一组。
2. **固定帧输入。** 在浏览器测试层控制 RAF/时钟、PRNG 输入、服务端 tick、请求完成时机和原始事件；加载期与已加载期分别测。动画测进入、峰值/转折和稳定/退场帧；必要时逐帧。采集同一逻辑帧的命令与像素，记录离屏来源及主 Canvas 目的变换。不得通过修改原件绘制逻辑得到“更稳定”的金样。
3. **先重建共同渲染器。** 按 [01](01-renderer.md) 实现 f32 布局、Canvas2D 路径、字体、合成及命中，复核稳定态；再接大厅与小队、物品与图鉴、对局与世界、各平台设置。各功能向同一绘制器提供控件状态和原版调用顺序。动态图案按 [07](07-world-rendering.md) 提取，不用静态 PNG 代替随状态变化的部件。
4. **分三层判定。** 状态/协议层比较事件、命中与边缘、焦点、设置存储、外链、hash 和 C→S payload；绘制层比较面板逻辑几何、矩阵、字体、路径、透明度、合成次序和 clip；画面层在固定环境逐像素比较全帧 RGBA。支持输出原帧、重建帧、差分图、首个分歧指令和发生帧。不同实现的等价路径可由像素与交互共同证明。
5. **把未验收状态留在矩阵里。** 固定环境和同一输入的目标是零不同像素；不以 SSIM 或整体百分比通过。跨平台的字形/抗锯齿差异单列环境基准；宿主外层 DOM 单独对照。明确排除的本地工具不能成为遮住差异的通用掩码。只有矩阵、残余分支审计和逐像素对照都通过后，才把对应功能标为 1:1。
