# 03 · 背包、菜单装备与制作

本页针对 **2022-10-30** 原件。函数名 `$n` 采用 Binaryen 132 的 WAT 编号。**静态**指原 Wasm 的常量、字段或分支；**实测**指以同目录原始 `client.js` 加载原 Wasm，使用仓库 localhost fixture 提供存档和协议，观察原 Canvas；**待验**的项目不能作为 1:1 已恢复项。当前 `dev-inventory.js/css` 是开发管理工具，不属于这个版本的 UI。

Wasm `$939` 负责面板装配和事件分支。线性内存字符串地址：`20779 Inventory`、`31638 Crafting`、`20904 Mob Gallery`；各自还出现在入口悬停提示（16px），不能仅凭文字存在就认定面板打开。面板切换、图标 hover 和 tooltip 都有中间帧；重建时以浮点矩阵/alpha 统一驱动绘制和命中，验证每帧位置，勿直接将上表 CSS 像素用于点击。标题和框线在本地观测中与原 Canvas 同帧绘制。见 [Mob Gallery 与 tooltip](04-gallery-and-tooltips.md)。

## Inventory 和菜单装备

**画面。** 标题 `Inventory` 下是一行 `Click on a petal to equip it`（16px），随后是 `Stack` 复选框，再下是物品格。面板宽 400；试档显示两行时路径高 291，1024×768 时外框路径左上 (74.67,546.84)。内容从面板左边 +10 开始，原裁剪宽 380；该 fixture 高 217.4，第一格中心 CSS y=672，第二行 y=721.78。栅格最多五列、步长 70，尾行以实占宽度居中。在默认未勾选状态，试档显示第一行 Stinger/Rare、Web/Rare、Peas/Unusual、Rose/Unusual、Faster/Common，第二行 Rose/Common。打开 `Stack` 后，试档按 Basic 空位、Faster、Peas、Rose 两稀有度叠卡、Stinger、Web 排列；Rose 的低稀有度副卡向左下偏移、缩到约 0.8，前景仍为 Unusual。空位没有 Basic 文本。Stack 路径要保留各稀有度的独立数量和可用性；不能用合计数生成一张新卡。多于两个稀有度时的层间距、鼠标展开和排序 tie-break 仍需密集档验证。

复选框路径 25×25，填 `#666666`、4 宽 `#333333` 描边；勾选时中间以 `#dddddd` 插值展开至 20×20 的内方块，不画 ✓。已确认设置键 `florrio_stack_inventory`（`$79` 读取）；不是服务器库存字段。试档 (1024×768) 复选中心 (108.44,627.56)，`Stack` 文本中心 (141.59,627.56)。

**装备互动。** 菜单中同一组装备位于大厅中央，主行在上、副行在下，均相对屏幕中线居中。试档 n=5：主行格中心 x=384/448/512/576/640，y=473.6；副行 x≈415.29/463.64/512/560.36/608.71，y=530.49。主卡缩放 4/3，主、副水平步长分别 90 和 68 逻辑单位。空副格是白填、`#cfcfcf` 边、alpha 0.8。点击主槽 (512,473) 卸下 Common Basic 后，本地库存出现空出的一份；点击库存 Peas/Unusual 卡后，原版填入该槽，可用 Peas 由 `x8` 变 `x7`。既不要扣掉总库存，也不要将两个物品的数据合并为一份。

| 状态     | 来源与重建约束                                                                                                                                                                            |
| -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 仓库总数 | 私有 profile `+2400+4*(kind*6+rarity)`，276 个 u32；本地启动 cache 为 `cached_inventory`。主、副两排均占库存；原 `$308` 计算未装备数，前端读此数生成可用量，数量 1 不画 `x1`。            |
| 主/副槽  | 原版逻辑 5/6/7/8 槽，解锁等级 15/30/45（`$107/$3645`）；`$70` 清理无效索引。客户端缓存和 C→S 12（`$997/$939`）按 n 个主槽接 n 个副槽，补空至 16；Store 内部固定下标须转换，尤其 level 1。 |
| 活局交换 | 原版 `$463` 发 C→S 28，传两槽的旧值。实测 Digit2 交换第 2 对主副槽；主槽上的回充扇形与装备显示见 HUD 文档。不要把菜单库存点击替换为局内任意全量换装。                                     |
| 恢复     | `cached_equipped`、`cached_inventory`、`cached_level`、`cached_num_petals` 可使大厅先画缓存；与私有档同步后更新。保留待发请求、已提交档和视觉过渡之间的区分。                             |

空库存、超过窗口的库存、无可填槽、点击已经选中槽、主副均满时的选择优先级、移动设备输入等需要专门 fixture；不能从单次“点空槽→选花瓣”推导其全部规则。

**状态与协议。** `$902` 根据当前选择与足量状态控制五格、百分比、按钮及动画；选中一组前不显示成功率数值。静态初始 u32 表 `53136+4*rarity` 为 `[60,40,20,10,3,0]`；显示按 `%.0f%% success chance`（33886）构造，空选择/非法 tier 使用 `?% success chance`（33868）。Common Basic 不可制作，Mythic 无再升一级的入口。存档旧计数是 2022-10-20 RNG 迁移的兼容字段；重建历史已有失败计数时需另验显示和请求，不从测试档的固定 RNG 外推。

1. **无选择 / 不足 / 足量选择。** 无选择绘制五个棕槽；试档 Faster/Common 仅四份时用灰卡，不能发送制作请求。选择 Rose/Common 后，五槽出现相同卡，网格立即把本次五份从 `x40` 显为 `x35`，这是预留表现，未触发提交。按钮点击前实际 profile 数未被直接改写。
2. **单次 / 全部 / 自动。** `$436` 发送 5：`all bool, keep vu, item`，Shift-all 和 Autocraft 使用同一命令。自动入口按可用数与需保留数计算批量命令，不能伪造一个“自动”操作码；需保留已装备数，不制作 Common Basic / Mythic。原交互是点击、Shift 和悬停，不把库存和制作混为拖拽网格。
3. **结果和库存同步。** S→C 35（`$988`）提供 `success,created,returned`，是原前端结果动画输入。普通失败按返回数更新，不把协议拒绝或断线显示成普通失败。成功实测：五卡旋转向圆心收拢，叠在中央；下一阶花瓣卡带旋转、放大和 alpha 过渡，最终停在中心（路径宽约 82.5）；按钮在处理中变灰。稳定结果帧仍可能绘制 alpha=0 的输入卡；验收要检查 alpha 与最终像素。失败保留少量输入（原提示销毁 1–4）；失败动画、批量次序和不同结果的精确时间常量仍须从 `$902/$988` 拆解和逐帧采样。
4. **单次示例。** 试档初始 Rose/Common=40、Rose/Unusual=20（副槽装备一个）。选中暂显 Common `x35`；成功后 profile 35 / 21，保持相同选中状态时制作格可暂显 Common `x30`、Unusual `x20`。显示量与总量的差值可用来检出遗漏的装备扣减和选择预留。

参见 [经济协议、操作数和重放用例](../economy-wire-20221030.md) 与 [Store 的确定项/推断项](../store-20221030.md#dated-evidence-and-explicit-reconstructions)。UI 的 60/40/20/10/3 是静态显示证据；失败损耗如何抽样、原服务器是否严格等于显示概率属于服务端问题。

## 重建顺序与像素验收

先接入原布局矩阵、公共文本、关闭按钮、物品卡与 clip，移植 `$939` 中各面板的测量和绘制顺序；再把私有档、缓存和协议结果接到显示状态。用 `wave_w3_seed` 离线建档，`wave_host_fixture` 提供协议状态，Chromium 156.0.8078.47、en-US、Ubuntu 700、1024×768/DPR 1。启动后等待字体与档案就绪，用真实鼠标点击 (35,626)/(35,680)，按钮按下和松开跨原绘制帧；等待面板动画稳定再取样。记录主 Canvas 上的 `save/restore`、路径、`clip`、文本、矩阵、`globalAlpha`、`drawImage` 源/目标矩形和顺序，并以固定时间/随机源和状态回放比对 PNG。测量过的花瓣 tooltip 另见 [第 04 页](04-gallery-and-tooltips.md)。

- 必测原菜单与 Inventory 初始/Stack 开关、撤下再装备、主副槽升级边界、空与密集档、重启后恢复。
- 必测 Crafting 空选、不可选、五份临界、选中预留、取消/切换选择、Shift 改字、滚动到底的 Autocraft、成功/失败动画和协议拒绝恢复；使用 [W3 原件回归入口](../../tools/w3/test-wire.mjs) 复核网络输出。
- 上表稳定布局来自具体原件帧。开关与 hover 缓动、库存超长列表、移动输入、完整制作动画轨迹尚需差分；这些项目不能用“截图相似”判定 1:1。
