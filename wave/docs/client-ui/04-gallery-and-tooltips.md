# 04 · 怪物图鉴、花瓣和怪物提示卡

以 **2022-10-30** 原 Wasm 为准；`$n` 是同一原件的 Binaryen 132 WAT 编号，`+n` 是线性内存偏移。**实测**来自该原件的 Canvas 绘制，不用现代 florr.io 的界面推断。该版已确认的目录入口标题只有 `Mob Gallery`；花瓣的卡片和详情经 Inventory、Crafting、装备与掉落卡片提供。未从本次检查发现一个独立 `Petal Gallery` 入口，不要按现代版补造。

## Tooltip 通用合成

1. 先构造原行树、按原字体 `measureText` 排版，再把 tooltip 排入主 Canvas 的晚绘制层。Ubuntu 700 必须已加载，使用实际 Canvas 的文字度量；每个 fragment 有独立宽度、色彩和字号。白填黑描、`textAlign=center` 和 `textBaseline=middle` 作用在单个 fragment 的中心；整行布局仍是**从左到右贴齐**，不要把整行居中。描边宽约字号 ×0.12，圆角连接、圆端。
2. 容器是黑填、圆角 5 的二次曲线矩形，底色 alpha=0.5×当前过渡值，文字、图标用当前过渡值。布局宽由内容决定，保留 7 左内边距（实测），并给动态宽的数字、描述、掉落网格和冷却区留位置。不要填一个固定卡片宽度。退场可与新卡片同帧共存；以原 draw 顺序和 alpha 比对，勿只检查标签集合。
3. 图鉴与库存 hover 样本的 tooltip 水平对准格中心，背景底边距离该格中心约 36 逻辑单位，即向上展开。边界例：Crafting 的 Common Rose 单格中心 CSS x=129.42；默认宽约 320.51 的提示超左边，原背景左边钳到 5 逻辑单位（CSS x≈3.56），没有因此移动格子。右侧、顶部碰撞与移动端输入需另做原件夹取测试；不能用常规浏览器 tooltip 的默认偏移和截断。
4. 描述与属性严格使用该版文字、标点、空行、顺序、显示缺失和色彩。属性名和值分成不同片段。例如 `Damage: ` 为 `#ff6666`，`Health: ` 为 `#66ff66`，`Heal: ` 为 `#ff94c9`，已测数值为白色；稀有度以该 tier 底色着色。不要把 `20~40` 改成 `20–40`，把区间/浮点缩写解析后再格式化，或对隐藏属性补零。

## 花瓣详情与计时

花瓣 ID 1–45、tier 0–5；ID 0 是空槽，没有物品 tooltip。注册表 `829696+24*id`，`+20` 是构造槽；实例虚表 `+12` 指向该变体自己的 tooltip builder。短名用于物品格，完整名称用于详情头；二者不要合并。冷却 `vtable+28`、`+32` 是毫秒，分别为回充与可选激活准备。`$638` 调用 `$33`，用原格式串 25936 `%.1fs`，或在第二段 >0 时用 25928 `%.1fs + %.1fs`。零也保留原格式，不根据机制推断空白。冷却 16px、白色，位于花瓣 tooltip 右上；其右侧另绘白色回充循环图标，实测为原 Path2D（带描边）；不要用字体字符代替。

主标题 24px、白色；rarity 和其余文本通常 14px；逐行应以 builder 的片段结果为准。实测未选的 Crafting Common Rose：背景左上为逻辑 (5,755)、宽 450.715、高 172.6；相对背景 top 的各文本中线为名称 +21.8，Common +48.4，说明 +84.0，Damage +117.6，Health +137.2，Heal +156.8，冷却 +18.2。损伤、生命与治疗数分别为 5/5/10，右上显示 `3.5s + 1.0s`；库存 Unusual Rose 同结构，6/7/13。该样本同时检验背景测量、两段冷却、彩色属性、左边缘夹取。Rice、无体花瓣 Antennae/Third Eye、含数量或多行说明的 Egg/Peas/Grapes、无第二段和第二段大于零应单独验证；getter 的 `orbitCount` 不总等于内部投射粒数。

## 怪物详情与掉落网格

图鉴怪物标题实测 18px（区别于花瓣标题 24px），tier、描述、Health、Damage 14px。图鉴采用 `record+120+12*rarity` 的缓存行树；注册记录 `909552+216*id`。描述与统计间有空行，原本缺失的字段不能从 getter 值补出来。Rock/Cactus 的生命范围、分节记录、普通 Ant Hole 与高 tier 不显示攻防的 Ant Hole、Fire Ant Burrow 需独立样本。

掉落表 `$63` 从系数计算缓存，`record+192+4*rarity` 指向对应表；`$1002` 在对应详情绘制路径组合掉落区。用原 `drops.panel` 的 `row,column,petalId,rarity,display` 排列：每种花瓣一行，稀有度按面板的列号排，跳过隐去项、不可用项、零项，不额外显示“Drops”标题。显示阈值为概率 `p < 0.0001`（0.01%）；幂运算、f32 百分数与格式化边界见 [原件掉率公式](../client-tooltips-20221030.md#掉率读取方法)。不能按服务端数表生成近似百分比，或将同一怪物不同花瓣种类合成总计 100%。

## 完整数据、复现与 1:1 验收

使用 [原件完整 tooltip JSON](../../data/catalogs/20221030/client-tooltips.json) 与 [人读全表](../client-tooltips-20221030.md)。JSON 保留每种变体的行、字段、显示文本、虚表和 formatter 输入，以及怪物的 `galleryLines`、`drops.panel` 与完整候选。对于像素复刻，已有 JSON 的 `lines` 主要是合并文本；需沿原 builder 另保留每行的 fragment（文本、字号、RGB/alpha、图标、行对齐及间距），不要用重新拆分字符串的规则代替。向量是 count `+0`、data `+8`，行 28 bytes；每行 fragment 数 `+0`、data `+8`、fragment 160 bytes，原研究脚本已用到文字 `fragment+132` 和色彩 `+144`。可以在保留原件字节的研究副本中额外导出布局测量数据。
