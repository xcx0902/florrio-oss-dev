# 01 · Canvas 渲染、布局与输入

以本目录 [README](README.md) 固定的 2022-10-30 二进制为准。本文的 `$N` 是 Binaryen 132 WAT 定义编号；`ASM N` 是原 `client.js` 的 `Kb[N]` 键。两种编号互不相通。

## 原版执行链

- **初始化 [W]**：入口 `$1619` 选择宿主 Canvas2D 路径；`ASM 153149` 以 DOM ID 与 `{alpha: !!arg}` 建上下文，返回 `z[]` 索引。另一分支由 `ASM 146168` 插入紧邻主画布之后的 `#canvasOverlay`，`$939` 在对应模式用 `146438` 同步其 backing store。桌面正常样本只有 `#canvas`；不要总造一张合成层。JS 的 Emscripten/SDL 同时含通用 WebGL 导入；导入存在不能证明常规 UI 是 WebGL。
- **每帧 [W/C]**：`$939` 为主循环入口，负责浏览器尺寸/重绘、状态切换和 UI。经分派进入 `$3437` 的路径先跑 `$601`（更新世界数据），调用 `$991`（世界/相机绘制），再由 `$939` 组织菜单、浮层、HUD、弹窗和交互。不要把 `$991` 当作全部 UI 根；房间操作与世界请求也各有入口。Chrome stack 显示 `wasm-function[1297]` 对应 `$939`，函数导入数为 358；有插桩的研究副本需重新建映射。
- **世界与界面相接 [W]**：主画布可直接绘制，也可合成中间画布；`$939` 的 `151764` 把一张画布原尺寸拷到目标，`$326/$327` 另走缩放/裁片。死亡文案等可能提前画进 buffer、位于 clip 外或 alpha 为零。判断最终可见性，要跟到显示画布的 `drawImage` 和目的矩阵、顺序及遮挡；统计 `fillText` 出现次数不能代替像素检查。
- **生命周期 [W]**：`148760` 探测 OffscreenCanvas 2D，`148914/149223` 分别分配 OffscreenCanvas / 普通离屏 Canvas；`149649` 将尺寸置 0 并回收句柄。保留分配、首次绘制、resize 后状态恢复、丢失上下文及图像未 ready 的分支。不要复用 resize 前的字体/clip/矩阵。WAT `$40/$220` 含 Canvas resize/尺寸访问；`$130` 含清除/合成复位。

## 三套坐标与单精度

HTML 画布 CSS 拉满视窗，截图/鼠标通常以 **CSS px** 表示；Canvas 调用的 transform 平移属于 **backing px**；本目录表格注明 **U** 时是 Wasm 布局单位。另有独立的世界坐标与相机，见 [07](07-world-rendering.md)。

`$617` 的外层 `select` 在移动端检测为真时走第一项，桌面走有下限的第二项。用实际 backing 宽高 `BW,BH`，而非 CSS 尺寸：

```js
const f = Math.fround;
const base = f(Math.max(BH * (1 / 1080), BW * (1 / 1920)));
const mobile = /iPhone|iPad|Android|Mobile|Tablet/.test(ua); // ASM 147419
const tablet = /iPad|Tablet/.test(ua);                     // ASM 147661
const s = mobile ? f(base * (tablet ? 1 : 1.5)) : Math.max(f(0.7), base);
const uiW = Math.ceil(f(f(BW) / s)), uiH = Math.ceil(f(f(BH) / s));
```

`$939` 在 UI 变换后用 `f32.ceil` 得到布局宽高（Binaryen 132 WAT 行 656100 / 656129）。因此右/下和中心锚点按逻辑宽高算，不能一律替换为 `innerWidth/2` 等。以对应 trace 的矩阵为准；f32 运算顺序能留下末位差异。若宿主实际采用的 backing 尺寸/事件比例和 DPR 不一致，优先用实测尺寸比，禁止在已缩放的变换再乘一次 DPR。

| --------------------------- | --------: | -----------: | --------------------------------------------------- |
| 1024×768 @1，桌面           |  1024×768 | 0.7111111283 | 稳态标题 x=512；面板基本尺度。                      |
| 1280×720 @1，桌面           |  1280×720 | 0.6999999881 | 标题 x≈640.150；下限分支。                          |
| 480×854 @1，桌面 UA         |   480×854 | 0.7907407284 | 标题 x≈240.385；窄窗不自动改为手机布局。            |
| 800×600 @2，桌面            | 1600×1200 | 1.1111111641 | 标题 x≈800.000061 backing px。                      |

坐标校验用 `getTransform`，不要把 `save/restore`、`setTransform` 后的原始绘图参数当成屏幕点。主 UI 不是单一自适应 DOM 栅格；子控件另有缩放（例如大厅打开动画、世界文字或 HUD 合成）；面板可能以滑出屏幕和淡出同时完成关闭。

字体使用本仓库 `wave/web/ubuntu-700.css` 与六个摘要固定的 WOFF2 子集。其本地 CSS 只重写字体地址；用同样的 normal/700 声明。等 `document.fonts.ready` 并确认样本文字实际命中相应字形后，重新检查缓存生成时机与断行。Latin、带重音、非拉丁、emoji 的 fallback 由宿主浏览器和 OS 决定，跨环境不承诺像素相同。`measureText` 的结果同时用于摆放、wrap、选择和 hitbox；禁止用估算字宽替代。

## 命中与状态设计

1. 记录输入的 `clientX/Y`、画布 rect、backing 比例和绘制矩阵。鼠标由原 glue 的 Emscripten 事件适配进入 Wasm；拖动、wheel、触控、键盘应重放真实 down/move/up/blur 事件。不要直接把截图里非透明的形状当作热区。
2. 用同一布局结果计算显示和命中；有 clip 的滚动内容不能在裁切区外抢输入。逐帧保留悬停、按住、松开、选中、disabled、拖动、滚动、转场的不同状态。游标由 `145277/145341/145405` 切换 default/pointer/text；精确记录原始进入/退出时机。
3. 只把必须由浏览器提供的控件交给 DOM，例如昵称输入、剪贴板回退、外链、页面状态；保留焦点、选区、输入法和移动键盘。`#textInput` 的位置及样式由原宿主与 Wasm 路径一起决定，正文见 [02](02-lobby-and-squad.md)。
4. 重建时把「服务端输入 → 界面状态」「逻辑布局/交互」「Canvas 指令输出」分开。先用原版产出固定场景的帧，再用同一个输入状态对比两端；每种控件一个稳定 ID 可用于差分，不改变绘制次序。既有 `wave/web/local.js` 的兼容补丁、下拉、重连等只作为本地宿主设施；原版比对用未改动的 Wasm 字节。
