# W2 已复验的协议子集

快照是 `68094577a0ac1254fcffedbb46c0181d90893bd063e3eafa76489bba2776e7b0`。以下 `$...` 是 Binaryen 132 反汇编函数名。浏览器验收使用哈希校验后的原文件。用于定位消费点的跟踪副本只在临时探针中运行。

| 方向与字段   | 编码                                                                                                               | 依据                                                                                                                            |
| ------------ | ------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------- |
| 客户端首包   | `30`、40 字节构建哈希、`00 00`                                                                                     | W0 捕获，W2 在真实 socket 复验                                                                                                  |
| 外层变换     | C→S 状态 `0x99df460b`，S→C 状态 `0x13bde6d7`。首字节走方向独立的置换表，其余字节使用每帧推进生成的 22 字节循环掩码 | `$3296`、`$2744`、`$958`、`$3068`、`$4070`、`$1122` 和 `$631`，与双向捕获比对                                                   |
| C→S 确认     | 明文类型 2，后接 epoch 和 tick 的无符号 LEB128                                                                     | tick 1、2 的原版出站分别为 `201eb8` 和 `3705a0`，顺序影响掩码                                                                   |
| C→S 可靠批次 | 明文类型 1、epoch，随后是掩码后的连续 `sequence, opcode, fields`                                                   | `$992`、`$2627`。启动批次为 25 无参数、13 带版本字节和三个 NUL 字符串、6 带无符号 LEB128 长度的不透明块。报告中的 UA 为测试替身 |
| S→C 访客标识 | 明文类型 5、epoch，负载为 `00 0e` 加 NUL 结尾的标识                                                                | `$3309`、`$988`。原版将值写入 `cp6_player_id`                                                                                   |
| S→C 更新     | 明文类型 1、epoch、tick，之后负载用内层掩码。epoch、tick 和确认序号为无符号 LEB128                                 | `$3309`、`$601`，原版按 tick 回 ACK。W2 固定 epoch 0。内层掩码取自 Wasm 内存 53744 开始的 256 字节                              |

| 异常关闭     | `00 00` 对应客户端 `kUnknown`，随后是 WebSocket 1002。超过 4096 字节由宿主有界读取后完成 WebSocket 1009 关闭       | `$3309`、W2-06。4096 字节是本地引导服务的限制                                                                                   |

`W2-WIRE-BOOTSTRAP` 保留原版出站夹具和原版接受过的最小首张空更新。浏览器报告逐帧记录方向、长度、时间和十六进制。旧夹具的 607 个零字节虽可解码，却把等级设为了 0。当前最小资料为首 byte 等级 1、其余 606 byte 为零，符合 `$140` 的默认值。可解码不代表可玩，已确认的消费结构和旧错映射因果链见 [客户端模块记录](../../../docs/client-20221030.md)。

[单客户端私有房回放](w2-lobby-replay.json) 的房间由合成实体提供。全量记录的掩码为 `00 02 00`，由 `$182` 分配；`$601` 的相应分支读取成员姓名、房间码和席位标记。原版显示两个名字和邀请链接。该回放仅是合成字节回归；双人加入与 W1 对局状态另外由真实原版客户端、真实 socket 的 W2-02 至 W2-05 验证。

## 实服小队、实体与生命周期

以下字段已由 `wire.json`、`online.json` 和 W2 截图共同验证。字段位置来自固定快照读取器，服务端值来自 W1 权威状态；可消费性不等于历史服务端全部字段或数值已恢复。

| 消息域     | 已确认格式与映射                                                                                                                     | 验证                                                                                    |

| 访客恢复   | 原始首包在构建哈希后带两个 NUL 字符串：本地账号空串、`cp6_player_id` 访客标识。每次新 socket 重置变换和可靠序号                      | 原版新上下文加载保存的 storage state，恢复同一 `PlayerId` 与房间                        |

花朵生命组件 `0x200000` 是三 byte，第三 byte 为 0..255 生命值，不是布尔 alive。场地组件 `0x2000` 是 **binary32 圆形场地半径 + RGB**，只发给场地实体。旧版误发每实体 health ratio 和颜色，导致地图半径 1、黄色/红色底色和移动预测失真。W2-07/08 复查真实血量、绿色背景、花瓣轨道及可见边界。

花朵状态 `0x20` 包含四个 byte；记录扩展 bit 3 开启时再读 16 个装备槽（type vu，非零 type 后跟 rarity byte），随后 8 个回充 vu。前五槽按 W1 loadout 发送 Basic/Rose，剩余为空，等级默认 1。`$126/$998` 将回充值解码为 u16 / 65535，并插值绘制扇形。本地映射 `65535 × (1 - remaining_ticks / reload_ticks)`，破碎为 0，就绪为 65535。不伪造库存/XP 进度。

原版左/右鼠标对应 opcode 9 buttons 的 bit 0/1，分别切换 attack/defend；同时按下时 defend 优先。权威轨道及碰撞统一采用本地倍率 1/1.8/0.6，非历史数值。正式 flower radius 为 W1 5 → wire 25，夹具仍为 2 → 10。W2-11 检查 `$41` 合成后的 f64 绘制坐标，不再以 wire 位置变化冒充视觉绕转/扩缩。

实体列表的 LE u32 零句柄之后，**还有一 byte 分隔符**，再接命令列表；`$601` 明确跳过该 byte。受击命令为 `vu 1, vu 32, LE u32 handle, u8 strength`，最后 `vu 0` 结束。缺少分隔符会错读 envelope/opcode 并触发 `$988` 的 `unreachable`。首张历史最小空更新在分隔符处直接结束，由原版容忍为空命令列表；当前快照显式终止列表。

`$988` 校验句柄代次后追加事件，`$51` 绘制约 150 ms 的受击闪光。每房非治疗伤害日志最多 4096 条，每 socket 独立游标，避免普通 25 ms 模拟 / 100 ms 发布间丢失或重复；新连接不回放旧事件，超限淘汰最旧条目。`$597` 的 generic bit 0 启动 150 ms 膨胀/淡出，投影对已见的消失实体保留 400 ms 后真正删除，保留期不复用句柄且不计入存活目录、碰撞和控制。W2-11 的原版逐帧观察和截图保存于 `protocol-effects.json`。

按用户确认的阶段顺序，尾 byte 为先推进的蓝色刷怪条，首 byte 为刷怪结束后推进的红色清场计时条（Garden 底条沿用原版 biome 配色）。本地蓝条为 `(planned - pending) / planned`，不是击杀比例；只要还有 pending，红条保持 0。W1 记录最后一次生成/耗尽结算的 `spawn_complete_tick`，红条按该时刻至现有 deadline 的已用比例推进；切波重置完成时刻。两条量化到 0..255。阶段顺序已确认，精确历史时间公式仍未恢复。

回充扇形与实体出现动画分别验证。`$601` 的 dense 首次创建直接使用轨道终点；投影对新花瓣句柄首次广播发送所属花朵中心位置的完整记录，下一次广播发送权威轨道位置记录，由 `$973/$41` 的原生位置插值使其从中心展开至轨道。后续广播不再发送种子记录，模拟尺寸、位置和回充时刻不变。这是利用已确认位置消费者的本地适配，不是新恢复的出生 opcode。不能以包围盒半径插值冒充花瓣图像缩放：Basic/Rose 图形有独立绘制对象。W2-11 检查回充后的新句柄经过多个中间最终绘制位置并到达轨道，保存对应原版 Canvas 帧 `W2-11-petal-appear.png`。

退出 opcode 11、死亡第一段 Continue opcode 21、小队关闭 opcode 38 均无参数，映射离开当前房间；广告尝试完成 opcode 34 也无参数，仅推进可靠序号。死亡还有第二段 GAME OVER Continue：原版关闭结算后产生 34，再回菜单，随后 Ready 才发送 7。旧版将合法请求当未知命令，发送 `00 00` 会触发原版 `qc()` 整页重载。完整字节记录保存于 `playability.json`，W2-08/10 检查无额外 socket 或页面加载。

小队组件 `0x200` 由四个姓名、21 个默认字节、NUL 房间码、84 个默认字节及四个席位标记构成。默认字节仅用于 W2 最小兼容，准备状态、库存、XP/等级进度、击杀者与完整排行榜字段尚未全部恢复。

客户端没有独立发送 W1 `LifeId`。会话为已发送的每个 tick 保存当时的控制生命，收到原版 ACK 后才将该生命绑定给后续输入。旧生命输入由 W1 拒绝，过期 ACK 不回退生命，重复可靠序号不重复执行。重连使用全新投影与完整可见状态；同访客替换连接后，旧 socket 失去输入、发布和断开新连接的权限。这些边界通过 `W2-GARDEN` 的原版启动捕获及合成加密 ACK/命令夹具验证。

`online.json` 将真实捕获标为 `captured`，每条帧保存连接内顺序、相对时间、方向、长度与原始十六进制；另外保存解码命令、每次权威步进后的状态及截图索引。`w2-lobby-replay.json` 的服务端字节继续标为 `synthetic`，不与实服双客户端证据混用。

超长消息处理在应用缓冲中最多保留 4097 字节，然后由 `async_close(1009)` 排空剩余帧并等待关闭握手，受 Beast 的关闭超时限制。这样避免在尺寸错误时过早关闭 TCP 导致浏览器偶发只见 1006。W2-06 对 4096 字节边界验证正常协议拒绝，对 4097 与 65536 字节各重复 20 次，逐次检查关闭码；之后再启动合法原版客户端。正式宿主的测试状态/步进路径也验证为不可用。
