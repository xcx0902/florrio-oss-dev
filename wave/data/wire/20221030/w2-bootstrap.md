# W2 已复验的协议子集

快照是 `68094577a0ac1254fcffedbb46c0181d90893bd063e3eafa76489bba2776e7b0`。以下 `$...` 是 Binaryen 132 反汇编函数名。浏览器验收使用哈希校验后的原文件。用于定位消费点的跟踪副本只在临时探针中运行。

| 方向与字段   | 编码                                                                                                               | 依据                                                                                                                            |
| ------------ | ------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------- |
| 客户端首包   | `30`、40 字节构建哈希、`00 00`                                                                                     | W0 捕获，W2 在真实 socket 复验                                                                                                  |
| 外层变换     | C→S 状态 `0x99df460b`，S→C 状态 `0x13bde6d7`。首字节走方向独立的置换表，其余字节使用每帧推进生成的 22 字节循环掩码 | `$3296`、`$2744`、`$958`、`$3068`、`$4070`、`$1122` 和 `$631`，与双向捕获比对                                                   |
| C→S 确认     | 明文类型 2，后接 epoch 和 tick 的无符号 LEB128                                                                     | tick 1、2 的原版出站分别为 `201eb8` 和 `3705a0`，顺序影响掩码                                                                   |
| C→S 可靠批次 | 明文类型 1、epoch，随后是掩码后的连续 `sequence, opcode, fields`                                                   | `$992`、`$2627`。启动批次为 25 无参数、13 带版本字节和三个 NUL 字符串、6 带无符号 LEB128 长度的不透明块。报告中的 UA 为测试替身 |
| S→C 访客标识 | 明文类型 5、epoch，负载为 `00 0e` 加 NUL 结尾的标识                                                                | `$3309`、`$988`。原版将值写入 `cp6_player_id`                                                                                   |
| S→C 更新     | 明文类型 1、epoch、tick，之后负载用内层掩码。epoch、tick 和确认序号为无符号 LEB128                                 | `$3309`、`$601`，原版按 tick 回 ACK。W2 固定 epoch 0。内层掩码取自 Wasm 内存 53744 开始的 256 字节                              |

| 异常关闭     | `00 00` 对应客户端 `kUnknown`，随后是 WebSocket 1002。超过 4096 字节由宿主有界读取后完成 WebSocket 1009 关闭       | `$3309`、W2-06。4096 字节是本地引导服务的限制                                                                                   |

`W2-WIRE-BOOTSTRAP` 保留原版出站夹具和原版接受过的最小首张空更新。浏览器报告逐帧记录方向、长度、时间和十六进制。607 个零字节是原客户端可以消费的访客默认资料，资料字段的历史取值仍待确认。

[单客户端私有房回放](w2-lobby-replay.json) 的房间由合成实体提供。全量记录的掩码为 `00 02 00`，由 `$182` 分配；`$601` 的相应分支读取成员姓名、房间码和席位标记。原版显示两个名字和邀请链接。该回放仅是合成字节回归；双人加入与 W1 对局状态另外由真实原版客户端、真实 socket 的 W2-02 至 W2-05 验证。

## 实服小队、实体与生命周期

以下字段已由 `wire.json`、`online.json` 和 W2 截图共同验证。字段位置来自固定快照读取器，服务端值来自 W1 权威状态；可消费性不等于历史服务端全部字段或数值已恢复。

| 访客恢复   | 原始首包在构建哈希后带两个 NUL 字符串：本地账号空串、`cp6_player_id` 访客标识。每次新 socket 重置变换和可靠序号      | 原版新上下文加载保存的 storage state，恢复同一 `PlayerId` 与房间                        |
| 私有小队   | 原版 opcode 27 + 布尔值创建；opcode 4 + `01` + NUL 房间码加入；opcode 30 + NUL 字符串更新昵称；opcode 7 + 布尔值准备 | 两端各自操作原版菜单；真实邀请片段为 `#wavelocal-<房间码>`                              |

小队组件 `0x200` 由四个姓名、21 个默认字节、NUL 房间码、84 个默认字节及四个席位标记构成。默认字节仅用于 W2 最小兼容，准备状态、库存、等级、击杀者与完整排行榜字段尚未全部恢复。

客户端没有独立发送 W1 `LifeId`。会话为已发送的每个 tick 保存当时的控制生命，收到原版 ACK 后才将该生命绑定给后续输入。旧生命输入由 W1 拒绝，过期 ACK 不回退生命，重复可靠序号不重复执行。重连使用全新投影与完整可见状态；同访客替换连接后，旧 socket 失去输入、发布和断开新连接的权限。这些边界通过 `W2-GARDEN` 的原版启动捕获及合成加密 ACK/命令夹具验证。

`online.json` 将真实捕获标为 `captured`，每条帧保存连接内顺序、相对时间、方向、长度与原始十六进制；另外保存解码命令、每次权威步进后的状态及截图索引。`w2-lobby-replay.json` 的服务端字节继续标为 `synthetic`，不与实服双客户端证据混用。

超长消息处理在应用缓冲中最多保留 4097 字节，然后由 `async_close(1009)` 排空剩余帧并等待关闭握手，受 Beast 的关闭超时限制。这样避免在尺寸错误时过早关闭 TCP 导致浏览器偶发只见 1006。W2-06 对 4096 字节边界验证正常协议拒绝，对 4097 与 65536 字节各重复 20 次，逐次检查关闭码；之后再启动合法原版客户端。正式宿主的测试状态/步进路径也验证为不可用。
