# M07：网络时钟、插值与本地移动预测

状态：未开始。依赖：M06；协议所需字段在 M04 预留并测试。产出：可测量的公网操作体验，以及不会改变权威战斗结果的基础移动预测。

## 07.1 范围与正确性边界

先保留 M06 的「纯服务端结果 + 插值」模式作为对照，再增加移动预测开关。预测不运行第二个完整 World，不在客户端结算伤害/拾取/经验/装备/出生，也不要求浏览器加载 WASM。

动态碰撞、敌方击退、AI 和未知效果仍由服务端校正。初版不做命中回溯；画面中的接触与服务端裁决可能存在网络时间差，测试须量化并在能力说明中写明。

## 07.2 先补齐可重建的时间与 selfState

1. 每个快照有真实 serverTick；客户端把 tick×50ms 转成模拟时间，不能继续使用 decoder 写死的 `serverTime=0`。
2. Ping/Pong 采样 RTT 和单调时间偏移，拒绝异常样本；使用滚动窗口平滑，重连后重新采样。时钟调整只影响显示/输入目标 tick，不改变服务器 dt。
3. Input 带 inputSeq 和 targetTick，客户端预测每个 50ms 步都有对应时间线。服务端限制未来窗口并在快照中返回实际采用 seq/tick、inputExpiresTick 和当前有效意图。
4. selfState 补齐权威 position、velocity、body handle/生命代次、当前移动效果/倍率和所需边界参数。传输 velocity 时保持现有数值精度，不能随意把原本 double 的计算链压成低精度再要求逐位一致。
5. 区分「最后收到」「最后实际采用」和「仍在复用的当前意图」。服务端一个输入可能持续数 tick，也可能合并掉多个输入；ACK 不能被解释成每个 packet 都恰好执行一 tick。

## 07.3 远端插值步骤

计划新增 `client/src/state/network-clock.ts`、`snapshot-buffer.ts`，调整 `interpolation.ts`、相机目标和 entity scalar 的时间来源。

1. 为远端实体保留短小的按 serverTick 排序快照环，不再只按接收时刻固定 120ms 拉向最新目标。
2. renderTime = estimatedServerTime - interpolationDelay。起始 delay 为 2 tick（100ms），按测得的抖动在 1—4 tick 内调节；参数有上限且计入报告。
3. 在相邻权威状态间插值位置/角度；缺少未来快照时最多外推 1 tick，然后冻结等待。重连、传送、出生和 handle 换代直接重置历史。
4. 生命/装备/死亡等离散权威状态按其事件 tick 应用；视觉平滑不能复活已死身体或延后本地交互权限。
5. 本地预测对象与远端插值分开，避免本地位置同时被 120ms 插值和预测双重处理；相机跟随其当前显示位置。

## 07.4 本地移动预测步骤

计划提取 `engine/sim/player_motion.*` 的纯移动计算契约，并新增 `client/src/state/local-prediction.ts`。C++/TS 实现使用同一份参数与独立 fixture；保留现有 f32 narrowing、double velocity、摩擦/边界/慢速效果的实际运算顺序。

1. 先把领域移动计算从碰撞/战斗中提取成可单测函数，证明原生单玩家轨迹没有变化。
2. 浏览器按固定 50ms 维护本地预测时间线，InputPump 发送相同意图及目标 tick。渲染帧率变化不改变预测步长。
3. 环形缓存保存近期输入及其计划 tick、预测状态、seq。上限 256 条；超过上限停止预测并请求全量，不能持续增长内存。
4. 收到服务端 selfState 后，以权威 tick 的 position/velocity/有效输入重置预测基点；丢弃已确认或属于旧生命的输入，再按模拟时间线重演到当前预测 tick。
5. 对尚未采用的迟到输入，用已知 targetTick 与实际采用反馈映射到未来未执行区间；不把「seq 大于 ACK 的每条包」机械地各积分 50ms。最多前瞻/重演 4 tick；长期超出范围回到权威显示并请求重新同步。
6. 输入超时、中立、慢速等状态进入同一时间线；不能让预测端继续移动而服务端已因 TTL 停止。
7. 误差拆为逻辑校正和显示校正：权威基点立即更新；小的显示偏移在至多 100ms 内衰减，大于一个玩家碰撞半径、生命代次变化或服务端传送时立即对齐。阈值写入配置，不散布 magic number。
8. 服务端发生碰撞/击退时，客户端接受 position/velocity 校正，不试图用本地猜测去覆盖敌方实体状态。
9. 死亡、body 删除、重生、全量 resync、SessionEpoch/RoomEpoch 改变时清空预测环与旧输入。旧生命的预测不能把新身体拉回尸体位置。
10. 花瓣可沿用权威数据插值并相对本地显示身体做有限视觉跟随；它的接触、发射、伤害和冷却仍以快照为准。

## 07.5 测试和测量

测试分三类，不相互替代：

| 类别 | 场景 | 要证明的内容 |
| --- | --- | --- |
| 数学 fixture | 无碰撞移动、停止、转向、摩擦、地图边界、慢速效果 | C++/TS 对相同输入时间线的结果在定义精度内一致 |
| 时序 fixture | 输入重复/合并/迟到、同 seq 复用、TTL、ACK 缺口、重连 | 重演按 tick，不多积分/少积分；缓存有界 |
| 真实网络 | RTT 0/80/150/250ms，抖动 0/±20ms，受控连接中断 | 操作延迟、校正幅度、AOI/死亡/重生仍正确 |

WebSocket 基于可靠有序传输。模拟 TCP 丢包时用受控网络代理造成重传/延迟，不能随意丢一条 WebSocket message 后宣称那就是 TCP 行为；主动省略快照只用于验证应用层 resync。

记录 input-to-local-presentation、RTT、server processing、prediction error、correction distance/count、buffer depth、resync count。输入显示时间从真实键盘/指针事件采集，不能用发送/接收同一个 promise 的耗时替代。

初始验收目标：前台无碰撞场景、本地输入 p95 视觉响应不超过 50ms；250ms RTT 稳定输入且无碰撞时，停止输入后不迟于 1 秒收敛到最新权威轨迹；动态碰撞后以有界校正恢复，不产生额外伤害或越权拾取。阈值为待实测目标，失败必须保留报告并调整实现/发布范围。
