# M07 网络时间与移动预测

在线预测只改变受控身体的显示坐标。权威实体表、血量、碰撞、花瓣发射、拾取、经验、装备、死亡和出生仍来自原生服务。默认开启预测；URL `?prediction=off` 或公开 `connection.json` 的 `prediction: false` 选择相同网络入口的权威插值对照。它们都不加载 Worker/WASM。

## 时间与输入确认

`NetworkClock` 使用 `performance.now()`，恢复 token 的有效期继续使用墙钟，两者互不混用。每秒发送一个有界 Ping；Pong 回显 nonce/客户端时间，同时返回宿主单调时间、当前 serverTick 和模拟时间。只接受当前 socket/session 的匹配探针，RTT 超过 2000ms、负时间、回退或明显异常偏移会丢弃。20 个样本的较低 RTT 一半估算 RTT/偏移；每个快照重新锚定模拟进度。服务端过载丢弃墙钟积压不会凭空增加模拟时间或 dt。

首个基线完成初始对时；之后的快照 / Pong 只修改目标偏移，显示时钟每毫秒最多校准 0.1ms，避免采样时突然前跳或暂停。自适应插值 delay 也按同一速率渐变，保持远端显示时间连续。连接中断仍有原有时间上限和重置路径。

Input 的 targetTick 由估计模拟时间得出，不等待下一份快照。它命名服务端将执行的玩家阶段：快照 tick T 表示阶段 T-1 已完成，重演阶段 T 得到状态 T+1。服务端仍检查未来 2 tick / 过去 5 tick 的接收窗口；迟到但有效的输入映射到下一未执行阶段。同一阶段只采用最新 seq。

快照分别返回 `lastReceivedInputSeq`、`lastAppliedInputSeq` 和 `inputAppliedTick`。前者表示入队；后两者表示一次实际采用及其阶段，持续复用该意图时不逐 tick 改写采用 tick。selfState 的有效意图和 `inputExpiresTick` 描述当前租期，TTL 到期可以中立而 ACK 保留原值。不能把每一个未确认 packet 积分为独立的 50ms。

selfState 另有 position、f64 velocity/acceleration、f32 motionScale、碰撞半径和地图宽高。运动参数由 `schema/multiplayer.yaml` 的 motion 区域生成独立 C++/TS 常量，领域 core 不依赖网络 codec。速度不通过 f32 压缩。协议仍为开发中的 v2，前后端须配套重新构建，不兼容先前 v2 的旧字段布局。

## 远端显示

`SnapshotBuffer` 按带代际 handle 保存最多 8 个 serverTick 样本。位置和最近角度绕向在相邻快照间插值；renderTime = estimatedServerTime - delay。初始 delay 100ms，依据接收抖动和 RTT 波动在 50—200ms 内调节。没有未来样本时最多外推 50ms，随后冻结。全量、连接/房间换代、出生/handle 换代、AOI 删除和传送清理相应历史。

离散权威字段按收到的快照/事件 tick 原子应用，不对血量、生命状态、装备和交互权限做插值。死亡/删除即时生效，插值历史不能复活实体。HUD 和死亡相机仍使用自己的 selfState；健康本地身体、移动指示与相机共用显示位置，不再叠加旧 120ms 插值。

## 本地重演与校正

`player_motion.*` 提取原有控制冲量和线性积分。原有 f32 narrowing、f64 速度、三角函数、摩擦表达式分组、地图夹取及中间坐标写入的 dirty 标记均保留。动态碰撞、未知效果、AI 和击退不在浏览器运行；下一份权威 position/velocity 覆盖预测基点。

预测环最多 256 条输入，按目标阶段合并并重演最多 4 tick。ACK 删除已采用输入；尚未采用的迟到输入合并到权威基点后的未执行阶段。有效意图复用、停止、中立、TTL 和已知慢速倍率均沿同一时间线执行。缓存溢出或持续一秒无法落入前瞻范围时停止预测、清环并请求一次有界全量 resync。

渲染使用估计模拟时间的小数 tick，在相邻两个固定 50ms 移动状态间线性插值；不再把整 tick 结果直接显示 50ms，也不额外提前一整步消耗前瞻范围。身体、相机和移动指示共享同一采样位置。插值只改变显示，整步位置 / 速度仍使用原来的纯移动计算，包含插值端点在内最多计算 4 步。

权威基点立即更新；小显示偏移在 100ms 内衰减。误差超过权威碰撞半径、传送或生命换代直接对齐。full、死亡、body 删除、重生、离开、断线、SessionEpoch/RoomEpoch 变化清空输入与旧历史。自己的附着花瓣与身体先在相同缓冲时间采样，再获得至多一个身体半径的视觉平移，避免减去最新原始身体坐标导致每次快照跳动；其权威轨迹/发射/伤害仍由服务端决定。

## 验证和测量

- `engine_player_motion_tests`：8 类轨迹共 640 步与提取前独立字面量参考计算精确一致，并验证真实原生玩家控制/积分轨迹；`tests/integration/player-motion.test.mjs` 逐步核对 TS，位置精确一致、f64 速度容差 1e-14。
- `network-timeline.test.mjs`、`network-session.test.mjs`：单调时钟/异常采样、目标 tick、合并/复用/迟到/ACK 缺口、TTL、缓冲/前瞻上限、校正、full/死亡/重生/换代与计时器释放。
- `latency-browser.test.mjs`：真实键盘事件到完成绘制的身体位移；0/80/150/250ms RTT × 0/±20ms RTT 抖动 × 预测开关，共 16 组。TCP 字节流代理保证有序交付，不任意丢 WebSocket message；另有 300ms 可靠流阻塞及 socket 中断/恢复。
- `movement-smoothness.test.mjs`：0/80/250ms RTT、80/250ms 含 ±20ms 抖动，预测开启 / 关闭共 6 组持续直线移动；在实际绘制后逐帧测量身体和相机的位置、停顿、回拉与速度波动。该回归进入 client-integration / delivery 清单，报告为 `reports/multiplayer/jitter-fix/smoothness.json`，绑定当前源码和构建身份。
- `network-browser.test.mjs`：250ms RTT、抖动下的双 BrowserContext PVP，每场两位观察者使用相反的预测设置，下一场互换；同一 serverTick 的权威血量和掉落逐项相同，胜者/死亡资料、重生及两房隔离均受检查。不同实时战斗的输入采用 tick 会改变 RNG 进度，因此不要求跨场随机掉落或逐帧轨迹完全重现。

矩阵报告记录真实输入显示响应、RTT、插值 delay、服务端 tick 处理最大耗时、预测误差/校正次数与累计距离、前瞻/缓冲深度、resync 和恢复。响应从真实 DOM 事件起算，在实际绘制后采样；不使用发送/接收 Promise 的耗时。预测自身耗时计入原有渲染路径，测量窗口中的最大耗时另行记录。全部入口加入既有测试清单、源码身份与 17 gate；完整证据与测量结果见 [阶段交接](../../multiplayer-goals/CHECKLIST.md)。

此测量使用同机原生服务与真实 TCP 延迟代理，覆盖可控延迟/抖动和有序流阻塞；不声称完成运营商网络、真实 TCP 丢包重传或 M08 容量/生产部署认证。画面中的碰撞接触与服务器伤害裁决仍可能相差网络时间，不提供历史命中回溯。

## 2026-11-02 持续移动抖动修复

原验收测量了首次响应和停止收敛，漏掉了持续运动中间的逐帧连续性。修复前，预测开启时约 66% 的稳定移动帧间隔位置不变，其余帧集中跳动。原因是显示直接使用整 tick 预测状态；额外提前一 tick 在高延迟下还会反复触及前瞻上限，时钟校准和花瓣平移又混入了不连续的时间 / 坐标基准。

修复后，6 组持续移动共 996 个稳定帧间隔，身体和相机的停顿 / 回拉均为 0；16 组延迟矩阵继续通过，预测响应 p95 为 31.5—42.6ms，停止收敛最大 571.8ms，实际 renderer CPU p95 最大 2.4ms。143 项客户端单元、88 项浏览器、41 项协议 / schema 单元、24 项工具及 9 项跨端回归全部通过，`dist-next` 已重新构建并验证。

本次定向修复记录为 `jitter-fix-2026-11-02`，汇总和源码 / 构建身份保存在 `reports/multiplayer/jitter-fix/summary.json`，逐帧数据为同目录 `smoothness.json`，另保留修复前探针及延迟 / PVP 报告。这里的回归结果独立于上述历史 M07 的 17 gate 验收；本次没有重跑整套发布 / 离线性能认证。
