# 多人表现差异核查（2026-11-01）

本次对照当前渲染代码、原有 snapshot publisher、`docs/m3-structure.md` 的首帧约定，以及 archive 中的 player/drop 渲染行为记录。核查范围是进入/重生、攻击/防御、花瓣接触、掉落出生、房间排行榜；没有据此宣称整个 UI 已与原版逐像素一致。

另查看了归档的[原版攻击截图](../../archive/tree/tests/parity/golden/attack/screenshot.png)和[原版静止截图](../../archive/tree/tests/parity/golden/garden-idle/screenshot.png)，并与当前多人浏览器截图检查脸部、排行榜和 HUD 布局。原版攻击截图中的花朵保持黄色。历史 [`next-ui-v2` 基线说明](../../archive/tree/tests/parity/next-ui-v2/provenance.json)明确将其定义为重建客户端的自一致性基线，不能把该基线通过视为与原版画面完全一致。

| 问题                   | 原因                                                                                | 修正与验证                                                                                                                           |
| ---------------------- | ----------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| attack/defend 改变脸色 | M06 将 field 31 的按钮位重新用作 field 14 的特效位；渲染器因此执行紫色/白色特效混色 | 保留原特效算法，恢复独立字段含义；检查各按钮组合连续多帧颜色，以及命中特效仍有效                                                     |
| 不同玩家花瓣互不伤害   | 碰撞入口无条件跳过所有花瓣对，旧 M03 测试也将此作为预期                             | 只跳过相同控制根；检查双方伤害、归属、同时破碎/充能和自身免伤                                                                        |
| 排行榜只有自己         | HUD 未收到多人名单，沿用单玩家 fallback；AOI 实体也不足以构成房间榜                 | 增加房间级公开名单，保留原排序/平滑/面板；检查远处玩家、自己的高亮、分数更新、Leave 和房间隔离                                       |
| 掉落无旋转入场         | v2 发布器没有传递 v1 已有的出生标志，而且公开块校验器只接受 flags=1                 | 发布与校验均支持出生位；跨 C++/TS 解码验证，检查实际绘制矩阵；旧物进入视野和 resync 不补播出生动画。原版稳定态是脉动，未新增持续自转 |
| 进入无动画             | 网络快照直接进入 playing，跳过 prepareFrame 约定的最后一帧菜单及捕获                | 将 joining 的确认留在 presentation；真实浏览器检查捕获菜单、首次进入/重生各一次、重连不重播                                          |

这些问题主要来自多人数据接入对既有字段含义、出生标记和首帧顺序的遗漏，也包含单玩家时期遗留的碰撞限制。此前测试更多验证协议、归属和流程完成；仅检查按钮字节、健康出生和可游玩，没有断言对应的实际画面，无法发现这些差异。新增回归覆盖数据发布、客户端状态和实际绘制/浏览器流程，历史 M06 全量验收记录不作为本次修改后的验证结果。
