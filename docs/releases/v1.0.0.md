# Florr.io v1.0.0

Florr.io 的首个正式版本，基于 2020–2022 年 Legacy Florr.io 的行为重建。
C++20 引擎编译为 WebAssembly，在浏览器 Web Worker 中运行；TypeScript + Canvas2D
客户端负责交互与绘制。游戏为本地单机模式，通过静态 HTTP 服务即可运行。

## 本次提供

- 固定 50 ms tick 的确定性模拟、怪物 AI、战斗、花瓣效果、掉落、拾取、升级和死亡重生。
- 首页与设置、游戏 HUD、背包、快捷栏、储备槽、Mob Gallery、更新日志和本地聊天界面。
- 鼠标、键盘与模拟触控操作；昵称和设置继续使用既有本地存储格式。
- 由 schema 统一生成协议、数据布局、花瓣/怪物目录及客户端和引擎视图。
- 可独立部署的静态交付包，包含客户端、Worker、WASM、字体与完整性清单。

## 优化与修复

- 空间查询、活跃实体遍历和快照发布减少重复扫描与临时构建。
- 文本、图形和布局缓存设置容量预算，并在生命周期结束时释放资源。
- 每个模拟步骤通过一个 Worker 请求完成有序输入、推进与输出。
- Mob Gallery 的掉落概率按从大到小排列。
- 修复 Dandelion 等长花瓣名称的缩放不一致：静态卡片与拾取、落位、退场动画
  统一采用目录定义的字号。
- 静态交付与发布包包含 Ubuntu 字体版权声明和许可证 `fonts/LICENCE.txt`。

## 下载与运行

下载同一 Release 的以下三个附件：

- `florrio-1.0.0-<source12>.tar.gz`
- `release-manifest.json`
- `SHA256SUMS`

在附件所在目录执行：

```sh
shasum -a 256 -c SHA256SUMS
tar -xzf florrio-1.0.0-*.tar.gz
```

将 `<source12>` 替换为实际文件名中的源码哈希前 12 位。使用静态 HTTP 服务提供解包后的
`florrio-1.0.0-<source12>/` 目录；也可在源码仓库中执行：

```sh
node serve.mjs --root /absolute/path/florrio-1.0.0-<source12> --no-open
```

默认地址为 `http://127.0.0.1:8477/`，端口被占用时自动顺延。需要通过 HTTP 访问，
直接用 `file://` 打开入口无法加载 Worker 和 WASM。

从源码构建需要 Node.js 24+、npm 11+、CMake、C++20 编译器、固定版本的 Emscripten；
执行 `npm ci && npm run build && npm start`。环境说明见 `docs/environment.md`。

## 基本操作

- 输入昵称后按 Enter 开始；鼠标指向或 WASD / 方向键控制移动。
- 左键 / 空格攻击，右键 / Shift 防御。
- I / Tab 打开背包，1–8 选择快捷栏，Q / E 选择储备槽，T 丢弃，Esc 关闭界面。
- 死亡后按 Enter 回首页，再按 Enter 开始新一局。

## 验证与兼容性

发布包必须通过 `npm run test:all` 的完整 15 项验收，并由 `npm run release:prepare`
绑定同一次验收的源码、交付、测试日志及报告哈希。实际通过状态以该包对应的
`reports/current-verification.json` 为准，历史 M4 性能报告不代替本次发布验收。

- 验收目标为固定 Chromium 156.0.8078.47 的桌面与模拟触控配置；Firefox、WebKit
  和真实移动设备未纳入支持范围。
- 本版本为单机游戏，没有在线匹配或多人服务器；聊天界面不提供在线通信。
- 音频边界目前为空实现，本版本没有游戏音效或背景音乐。
- DPR2 与触控配置的大量文本场景仍可能出现帧间隔波动，不承诺所有设备稳定 60 FPS。
- 保留现有 `?cheat` 产品诊断入口；分发包排除测试 API、fixtures、source map 与历史归档。
- 沿用 `florr-menu` 存储键及既有昵称/设置格式，无需迁移；重新载入页面后开始新局。
