# Florr.io v2.0.0

Florr.io 的首个联机版本。原生 C++20 服务端在同一房间内权威推进共享 World，
TypeScript + Canvas2D 客户端通过二进制 WebSocket 收发输入与快照；默认入口不再
加载 `server.wasm` 或 `server-worker.js`。显式 `?profile=offline` 仍保留上一版
Worker/WASM 单机路径，用于离线诊断和回归。

本版本完成 M01—M07 的多人目标：原生 core 边界、多玩家状态、PVP 与玩法归属、
v2 协议与每连接复制、原生网络服务、浏览器联机客户端，以及网络时钟、远端插值
和本地移动预测。M08 的 2×8 容量认证、Linux 生产发行包和 TLS 部署 smoke 尚未
完成，因此本版本仍按默认每房两人、最多两个房间发布。

## 本次提供

- 原生 `florr_server`：Boost.Asio/Beast 异步 WebSocket、固定 50 ms tick、
  共享 World、按连接的全量/增量快照、房间与连接上限、health/readiness/metrics、
  有界写队列、token/grace 重连和 SIGINT/SIGTERM 有界排空。
- 同一 World 的多个玩家：独立 PlayerId、身体、装备、输入、死亡与重生；
  花瓣、宠物、投射物、持续伤害和治疗按真实来源归属；唯一拾取、死亡掉落与重生。
- v2 协议：schema 生成的 C++/TS codec、公开/私有字段分离、AOI、每连接基线、
  full/delta/resync、输入接收与实际采用确认、LifeEpoch/SessionEpoch 拒绝旧命令。
- 默认浏览器网络客户端：50 ms 独立 InputPump、显式 PlayerId/controlledHandle、
  selfState、命令结果、断线重连与房间隔离；在线路径零 WASM/Worker 请求。
- M07 时间与预测：Pong 采样的网络时钟、按 serverTick 排序的远端插值、
  有限外推、本地移动预测/重演/有界校正；`?prediction=off` 可对照纯权威插值。
- 回归与测量：19 项 engine CTest、30 项根构建 CTest、真实双 WebSocket、
  双 BrowserContext PVP、16 组 RTT/抖动矩阵和持续移动平滑性回归。

## 下载与运行

源码标签 `v2.0.0` 是服务端与客户端的配套组合。Release 附件中的
`florrio-2.0.0-<source12>.tar.gz` 是静态 Web 客户端；服务端需从同一标签构建。
不要混用其他版本的服务端、客户端或 v2 开发中间构建。

### 构建服务端

要求 CMake 3.24+、C++20 编译器和 Boost 1.86.0 归档（可自动下载，或通过
`FLORR_BOOST_ARCHIVE` 预置）。服务运行环境不需要 Node 或 Emscripten。

```sh
npm ci
npm run build:server
```

服务默认监听 `127.0.0.1:8787`，并拒绝未显式允许的浏览器 Origin。开发时复制完整
配置并加入页面 Origin：

```sh
node -e "const fs=require('node:fs'); const c=JSON.parse(fs.readFileSync('server/config/default.json')); c.allowedOrigins=['http://127.0.0.1:8477']; fs.writeFileSync('build/server-local.json',JSON.stringify(c,null,2));"
./build/native/server/florr_server --config build/server-local.json
```

`GET /healthz` 返回进程存活，`GET /readyz` 在过载或排空时返回 503，
`GET /metrics` 返回固定标签计数。生产环境由同源 TLS 代理把 `/` 转发到静态客户端、
`/ws` 转发到本服务；代理必须保留 WebSocket Upgrade。

### 启动客户端

```sh
npm run build
npm start -- --port 8477 --server ws://127.0.0.1:8787/ws
```

打开 `http://127.0.0.1:8477/`，输入昵称即可加入 `garden` 房间。第二个浏览器
窗口使用同一地址即可进入同一房间。`--server` 只覆盖本次静态服务的公开
`connection.json`，不会把服务端地址写入产品文件。

离线诊断访问 `?profile=offline`；在线连接失败会明确报错，不会自动回退到离线。

## 操作

1. 首页输入昵称（可选），按 **Enter** 进入花园。
2. 鼠标指向决定移动方向；**左键 / 空格**攻击，**右键 / Shift** 防御。
3. **WASD / 方向键**也可移动。
4. **I / Tab** 打开背包；**1–8** 选择快捷栏；**Q / E** 选择储备槽；
   **T** 丢弃；**Esc** 关闭背包或菜单。
5. 触屏设备使用屏幕虚拟摇杆；其余操作通过界面按钮完成。
6. 死亡后按 **Enter** 回首页，再按 **Enter** 开始新一局。

## 已知限制

- 默认每房 2 人、最多 2 个房间。8 人目标容量、集中战斗和 30 分钟资源浸泡属于
  M08，尚未认证；不能用测试配置的 `certificationPlayersPerRoom` 宣称发布容量。
- 本版本未提供 Linux 生产发行包、配对 manifest、TLS 反向代理示例和升级/回退
  smoke；当前验证平台为 macOS arm64，部署前需在目标平台重新构建和验收。
- 房间、玩家和 token 只存在于内存；进程重启后旧 token/RoomEpoch 失效，客户端
  必须重新加入，不能恢复旧房间。
- 不做账号、排行榜、排位匹配、组队阵营或跨进程迁移；聊天只有发送者、限流和
  房间广播，没有持久历史或审核。
- 预测只影响本地身体显示。动态碰撞、击退、AI、伤害、拾取和掉落仍由服务端裁决；
  没有历史命中回溯，画面接触与伤害确认可能有网络时间差。
- 浏览器验收固定 Chromium 156.0.8078.47 的桌面与模拟触控配置；Firefox、WebKit
  和真实移动设备未纳入支持范围。
- 音频仍为空实现；本版本没有游戏音效或背景音乐。
- `?profile=offline` 继续随包分发 WASM/Worker；默认在线入口不请求它们。正式
  在线发布包的精简与容量认证留给 M08。

## 验证

完整 17 项验收由 `npm run test:all` 产生，`npm run release:prepare` 只为同一次
通过的账本生成静态客户端包。实际 runId、测试数量、延迟测量、包哈希与已知失败
见 [v2.0.0-verification.md](v2.0.0-verification.md)。
